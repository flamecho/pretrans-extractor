# 提取成行 · 名札边界与记录框语义（B10–B12）

> B1–B6、B14–B17 见 `04-lines.md`，B7–B13 见 `04-lines-cases.md`。

> 见 `04-lines-echo.md`。

**B10. 「名札/占位符」记录必须先当「框边界」消费，再谈丢弃 —— 别让噪声过滤把它静默吃掉**

SNOW BOUND LAND 实证：`#Name[n]` 是**说话人名/主角占位**记录，同时它也是**框边界**。
若把它归进「全局高频串」噪声过滤直接 `continue`，**同一个点击里同一行的两个互斥版本**会粘成一行：

```
#Name[0]  「それじゃ……行こう、ゲルダ」      ← 直写名版
#Name[0]  「それじゃ……行こう、#Name[0]」    ← 宏版
⇒ 错： 「それじゃ……行こう、ゲルダ」「それじゃ……行こう、ゲルダ」
⇒ 对： 「それじゃ……行こう、ゲルダ」          （互斥两版取一）
```

- **规则**：凡「说话人名 / 主角名占位 / 名札」类记录，**先按边界处理（flush 当前行），内容再丢弃**；
  顺序必须是「判名札 → 判噪声」，**不能**「判噪声 → continue」。
- **名札的「后果集合」要含心声/独白**：名札后面不一定跟 `「…」`，也可能是 `（…）`（心声·独白）。
  只认 `「` 会漏判（SNOW BOUND LAND `謎の青年（本当に単純な人だ…）`）⇒ 后果判据写 `「『（(`。
  含平假名的名札（`謎の青年`/`見知らぬ男１`）**不能**被「名札不含平假名」的启发式排除——那条只适用于按频次建表。
- **名札的「分隔符」与名札「内部」都可能是全角空格**（ヴァルプルガの詩实证）：
  `人狼一族の男　その一 「…」`（名札自带全角空格）、`少年　その二 「…」`、`蘇芳 （…）`、`蘇芳 『…』`（手机邮件）。
  故判据**不能**写成 `^[^\s…]{1,N}[空格]`——会被名札内部的全角空格截断、只吃到前半。
  正解＝「行首片段 `[^「『（]{1,26}?` ＋ 半角 0x20 或全角 U+3000 ＋ **lookahead 起始括号** `(?=[「『（])`」，
  非贪婪取**最早**的「空格＋起始括号」。全身检得名札 37 种 / 269 行，全剥、残留 0；
  反向扫描确认无「叙述＋空格＋引号」形态（0 例）⇒ 不误伤。
- **禁止盲删「相邻重复行」**：去重前必须证明是**同一次点击被重复发出**。
  判据＝给每行记录**来源 token 偏移**：同偏移（SAME_OFF）= 伪影、可去；
  **不同偏移（DIFF_OFF）= 两次点击 / 两个说话人 = 真实文本，去重即删原文**。
  反面例（ヴァルプルガの詩）：`金の犬 「……」` 与 `銀の犬 「……」` 是**两个说话人**的两个框，
  被「相邻重复去重」并成 1 行 ⇒ 删了真文本；实测 76 处相邻同文**全部** DIFF_OFF。
  ⇒ 引擎管线里没有「同框被重复发出」的证据时，**宁可不做去重**；
  `check_text.py` 的 `[W] 相邻重复行` 本就是「允许存在」的告警（多作皆 PASS）。
- 自查：跑一遍「整行对半重复」扫描（`l[:n//2] == l[n//2:]`）＋「行内重复子串 ≥10 字」扫描，
  排除掉真实反复修辞后应剩 0；再对修改前后产物 `difflib` 全量比对，逐条目视变化行。

**B11. 记录「框」有语义 —— 连续同类文本记录 = 同一文本框，别按记录逐条断行**
一个文本框的正文常被拆成**若干条同型记录**（框内软换行），由**一条「换箱记录」**表示换箱。
⇒ **相邻同类记录必须合并**；按记录逐条成行会得到成片碎片行（两个方向都会错）。
- 实证（STCM2L 子文件 0x1800 前缀区 / PANDORA）：记录框 = `[u32 cmd][u32 arg][u32 size][payload]`，
  `0xd2`＝正文/台词、**`0xd3`＝换箱分隔**（size=0x10 空 payload）、`0xd4`＝说话人名(丢)、其余＝资源控制。

  ```
  d4 '#Name[1]'  d2 '（どんどんマクシミリアンが壊れていく……'
  d2 '私には、どうにもできないの？'  d2 '受け入れてあげることしかできないのかな？）'  d3
  ⇒ 对：1 行「（どんどん…私には、…？受け入れて…？）」   （3 条 d2 同框）
  ⇒ 错：3 行（旧版；`（`/`）` 被拆到不同行 → 引号不配对假象 → 再「修引号」会造出 `）（`）
  ```
  一次修正合并 ≈270 行。**判据**＝先确认「换箱记录是哪一种」（例 `d3` 空 payload），**别把所有记录当边界**。
- ⚠ **同一子文件里可能混两种框架**：代码段 `[size][payload]`、数据/场景区 `[cmd][arg][size]` —— **逐区分别确认**，
  且**两区之间要补边界**，否则交界处两行粘连。
- ⚠ 引号修复方向：**缺开括号要「行首」补**、缺闭括号行尾补；若误把缺开括号在行尾追加会产出 `）（` 怪串。
  更根本地：**先按 B11 合并跨框心声**，多数「引号不配对」会自然消失，不必造字。
- ⚠ 同 opcode 含「人名＋正文」时，人名别当菜单项吐出（`opt/mopt` 也要过人名过滤）。

**B12. 别尽信脚本里的「长度/边界」字段 —— 用「结构自洽」自停，并容忍跨界记录**
脚本头里的 `code_size` / `exports_offset` / `data_offset` 之类**常不是真终点**，照它截会静默丢正文。
- 实证（STCM2L / PANDORA）：`exports_offset`（头 +0x20）被当初代码链终点，但 **118 个子文件在它之后仍连续是合法 opcode**（含真台词），共 **244 条文本记录被截**。
  ⇒ 遍历到**子文件末尾**（`startCluster×0x800 + sizeBytes`），按「`[size]` 合法 + 链不断」自停。
- 同理 **区块首条记录的头可能落在「起点之前」**（实测 -0x10，payload 在区块内）⇒ 链起点要**向前留 margin**
  并认「覆盖起点的记录」，否则丢首条（PANDORA 丢 `「だが忘れるな。`）。
- **说话人名/名札的判定别用「频次」**：集合名+番号（`救急隊員１`/`軍人４`/`通行人１`/`オペレーター５`）常只出现在单一文件，
  `freq≥2` 会漏判 ⇒ 名札与台词并成 `救急隊員１「…」`。改判据＝「紧邻下一段以 `「『（(` 起头」＋「无平假名／短」（B10）。
- ⚠ **名札字符集要含「形近破折号」**：原作会误用 **U+2015 `―`** 代替长音符 **`ー` U+30FC**（PANDORA `ロニ―`），
  字符集只收 `\u30a0-\u30ff` 就判不出 ⇒ 与台词并成 `ロニ―「乾杯！」`。把 `\u2010-\u2015`/`\u2500` 纳入。
- 自查：扫 `^[名札形]{1,8}[「『]` 应为 0；**更稳**＝「行内含 `「` 但行首不是 `「『（(`」者逐一目视。
- ★ **名札字符集必须含「全角数字」`０-９`**：带编号／数字起头的集合名（D.C.G.S. `女子生徒１/２/３`・`男子生徒１-４`・`３年女子`・`３年男子`＝8 种）
  字符集只收假名/汉字就判不出 ⇒ 名札被当正文**拼进台词**（`女子生徒１「…」`）。⇒ 与「频次别设 ≥2」并列，**第二道口子＝字符集**（`０-９`＋`\u2010-\u2015`）。
- ★★**「行内『名＋「台词」』剥离」须加「整行以闭合引号收尾」这一条件**，否则毁句（2026-10-16，D.C.G.S.）：
  `稜平くん（本当はくんなんて付けて呼びたくないけど）だって、黙って立ってれば普通に格好いいのに。` 的 `稜平くん` 是**句子主语**，
  按「名＋括号」剥掉即残句。正解＝`^([名札形]{1,8})(「|『)(.*)(」|』)$`（**要求行尾闭合引号**）。
  ⚠ 故上面那条自查须改成「**行尾非闭合引号** 且 行首像名札者」才报警（本照旧扫会误报 129 处，逐一目视后**全为合法句中引用**）。
- ★ **注音（ルビ）宏亦有 `#Kana[n,よみ]基底语` 写法（宏在**前**、基底紧随）** ⇒ **只删宏留基底**
  （`「あ、#Kana[1,ゆう]悠くん？」`→`「あ、悠くん？」`）；与 KiriKiri 的 `[字'よみ]`（基底在前）**方向相反**
  ⇒ 见宏先问「基底语在宏前还是宏后」，别无脑套同一正则。
  （`「あ、#Kana[1,ゆう]悠くん？」`→`「あ、悠くん？」`；`#Kana[2,こじょう]古城先生`→`古城先生`）。
  与 KiriKiri 的 `[字'よみ]`（基底在前）**方向相反** ⇒ 见宏先问「基底语在宏前还是宏后」，别无脑套同一正则。

**B31. ★「名札」没有独立记录类型时，用「**后随同类串**」定名札位（无标签序列化；2026-10-16 千銃士R）**

字节码脚本里名札常有专属 opcode（B10/B11）。但**无标签的序列化**（如 Unity 自研 `*MasterVO.bin`）里
名札与正文**同为字符串、同一编码**，只能靠**位置**分：

- **名札 = 含假名/汉字的串 且 其「下一个字段」也是日文串**；
  **正文 = 含假名/汉字的串 且 其「下一个字段」不是日文串 且 不在名札词表内**。
- 实测效力（千銃士R）：一次性分出 **1,337 条名札** vs **87,562 条正文**，误判仅 **32 条**（全是 `A＆B` 复合名札）。
- **反着核一遍**：把「后随日文且长度 ≥15」的串全导出 ⇒ 32 条**全为复合名札**（`ケンタッキー＆ペンシルヴァニア`、
  `ボフォンキオ・ファミリー幹部１`），**无一条是正文被误判** ⇒ 判据成立。
  这一步是**必做的证伪**（否则「长串被当名札丢掉」是静默缺陷）。
- 附带：`〔名（？）〕` 形态（`在坂（？）`）与「同一角色的别表记」会进名札表 ⇒ **外部核对时按角色归并**，别当新人。
