# 名字宏 / 名字表 / 交付改名（原 `03-selffont.md` §4–§5 拆出）

> 适用：脚本用**内联宏/占位槽**注入人名（主角可改名）或名字以**游戏码 u16** 存储时。
> 字形/自建字体部分见 `03-selffont.md`。实例：STORM LOVER V（PSV）/ OZMAFIA!! -vivace-（Switch）。

## 1. 名字相关：宏 与 名字表

**名字类文本以「游戏码 u16」存储，搜 cp932 会 0 命中**——别据此判「没写名字」。

| 载体 | 含义 | 处理 |
|---|---|---|
| `FF08` | 主角**一人称**宏（默认「私」） | 填默认值；**不要**当名字 |
| `FFE6` | 主角**姓**占位 | 填默认姓 |
| `FFE7` | 主角**名**占位 | 填默认名 |
| `3458` 之类高码槽 | **可能是「配角的名」槽，≠主角** | **必须用名札/称呼上下文判定，切勿想当然当主角槽** |

⚠ **一人称宏的码位「逐作可变」**（V=`FF08`；2ndV=`FF0F` 且无 `FF08`）。定值靠**锚句**
`[FF0F]は２年に編入予定の[FFE6][FFE7]です`＝「**私**は…嵐山**真理**です」。`FFE6/FFE7`＝姓/名 跨作稳定，**一人称别照搬前作**。
- ★ **「字面名→宏名」的切换点＝默认值的证据**（OZMAFIA 実証）：角色在剧情里被改名后，脚本**从字面名切到宏**
  （`W_018A_ORG`：24 处字面「ドリアン・グレイ」全在改名事件前、5 处宏 `＊Ｂ` 全在其后）⇒ 宏值＝**改名输入框默认**（eboot 名字表槽 2）；
  **别**拿「宏旁更长的字面名」或 write-only 的 `_WKST(Fxxxx,长名)` 去推。

- **该 run 是「其后正文」**：正确做法＝**先插宏值、再续 run**（漏 run 会丢字）。
- **名札区 `FFF0 … FFFF` 内的内容一律丢弃**（§0 不加说话人前缀）；区内同样含 `FFE6/FFE7`，
  必须靠「进入名札区则整段跳过」的状态量排除，否则会漏成「纯姓名行」进正文。
- ⚠ **名札区有「两形态」，别只按 `FFF0 → 首个 FFFF` 跳过**（プリンス・オブ・ストライド 実証）：
  ① `<FFF0><样式><NAME>`；② `<FFF0><样式> ＋ **空** `<FFFF>` ＋ `<FF4D><NAME>`。
  形态② 中间夹一个**空** `FFFF` ⇒ 若实现成「见 FFF0 后遇首个 FFFF 即退出名札态」，`FF4D<NAME>` 会**漏进正文**（成「纯姓名行」）。
  正解＝名札态须**容忍一个空 run**（空 run 不计入「已收名札内容」），或直接扫 `FFF0` 后紧邻的 `FFFF`/`FF4D` 直到出现**有内容的正文 run**。

### ★★ 高码槽 ≠ 主角：实例（V 的 `3458`）
`3458` 真值 = **配角「猪狩 澪」的名**（非主角）。判据（一条即够）：
- 前接「狩」3791 处（→ 全名「猪狩**澪**」）；后接「く」1496 处（→「**澪**くん」）。
- 锚句：`僕は三年の猪狩[3458]と言います`、`やっぱり[3458]くんは[3458]くんだなっ`。
- ⇒ 先看「该槽在名札跟谁连用、被谁怎么称呼」再定性；**别因它出现在主角自我介绍附近就当主角**，更别「改名成主角名」（真实事故）。

**默认名/姓名来源**：`eboot` 里有一张**「名字输入初始值表」**（铁律 13 的具体落点）：
逐条 `[≤3~6 字 u16][填充 0][0xFFFF]`，另有 u32 指针表指向各条；**名字是游戏码**（搜 cp932 会 0 命中）。
★ **表往往有多张，务必分清「主角候选表」与「配角表」**：
- 实例（V）：**主角表** = 姓段（`…村崎/ジョン/**五十嵐**`）＋名段（`…スミス/**由奈**`）⇒ 默认名 **五十嵐 由奈**（0x166176 / 0x1662a2）；
  **配角表** = 另一张（`…辰原/**猪狩**/酉水…`）。⚠「字面出现的姓」多来自配角表（本作字面 `猪狩`＝配角，主角 `五十嵐` 字面 0 次）⇒ 见 §2。

## 2. 交付口径 ≠ 原始字面（★**严禁对姓名做批量替换**）

游戏原始字面可能与外部资料（攻略/维基）不同（实例：游戏主角默认姓写「五十嵐」）。
**忠实提取按游戏数据走。**

### ⛔ 反面教材：`RENAME={'猪狩':'五十嵐'}` 批量替换（真实事故）
曾把字面 `猪狩` 当主角姓做全体替换。**错**：
1. **误伤同姓配角**：字面 `猪狩` = 配角 **猪狩 澪**（いかり，男）→ 被改成「五十嵐 澪」。
2. **主角姓不在字面里**：主角（五十嵐 由奈）**只经宏**，字面 `五十嵐` **0 次** ⇒ 改名只改**宏填充值**（`NAME_SUB`）。

**判据（做替换前必须过）**：把该姓氏**所有字面出现**按「名札 / 他人称呼 / 自我介绍」分类，若它属于**名札里某个具体配角**
（且有独立 vndb 条目 / 独立名字槽）⇒ **该姓氏是配角的，禁止批量替换**。

### ✅ 正确做法
- **只改宏**：`NAME_SUB = {0xFF08:'私', 0xFFE6:'五十嵐', 0xFFE7:'由奈'}`（主角的姓/名/一人称 → 默认值）。
- 字面姓名**原样保留**（各配角的真名）。
- 确需「统一写法」的**非姓名**术语，才用输出层 `RENAME={...}`（解码层不动、可置空还原），并写进报告。
- 替换脚本一律**可逆 + 有依据 + 记入报告**；替换后**必做**「旧串残留 = 0 且未误伤同名角色」检查。

## ★ 名字宏的「基准值」不必靠外部查——游戏自带**变量定义表**就是权威（2026-10-12）

**做法**：在 DATA 里找**变量定义表叶子**（表头魔数 + 节点树），它常直接写着**字段名 + 默认值**。
锚点＝**默认值字符串本身**（如主角默认名），一眼即得字段 ID。

实证（Koei CDAR v4 / ネオアンジェリークSpecial, PSP）：`DATA.BIN` 有一叶 `+Pn\x93` 头 → 节点树
`{ char name[16]; …, u32 childOff[]; …, u32 ID; …, u32 default_ptr }`，其中

```
主人公 → 名前  默认「アンジェリーク」  ID = 0x06010233
         愛称  默认「アンジェ」        ID = 0x05fa0288
```

- **旁证要用「游戏内说明文本」**：同一份 DATA 里找到
  `主人公名を「アンジェリーク」と入力すると、音声でも…` / `愛称を「アンジェ」と入力すると…`
  ⇒ 与变量表 100% 对上，**双证据**才落地。
- **同名字段亦有多通道**：同一字段可经 `02 <表ID>` 与 `1e <哈希>` 两种操作数访问（本作 名前 = `0x06010233` / `0x0d8503f6`）。
  两通道都要映射到同一宏值。
- ⚠ **`07 <u16>` 索引 + 名字变量并存 ≠ 主角名**：这是「**按索引指定的人物名**」（同伴/被称呼者）⇒ 只能出语义占位
  （实证：`（[ins]さんに微笑みましょう）` 的字面互斥版写作 `（レインに…）`，而主角名另有宏）。
- ⚠ **别把「表参照」当名字**：`02 <表ID> 02 <索引>` 或 `07 ff ff 02 <idx>` = **用語/地名/依頼名 テーブル参照**
  （运行期查表），静态不可求 ⇒ 语义占位。

## ★ 用語辞典：見出し語 常在**独立表**，用「索引指令」取（2026-10-12）

- 辞典条目本体 = `（読み）解説`（読み＝假名/`・`/`ー`）；但**見出し語不在同一条记录里**，
  而在同 DATA 的**見出し語表**（本作 `root#1292`，魔数 `9b474074`）。
- 脚本侧以 `07 ff ff 02 <u32 idx>` 给出索引 → 表项 `T[idx]`（本作实测基准 `T[idx+1]`，因表头多出 1 项 ⇒ **必须用已知条目校验偏移**）。
- 定表：**看前几项是否为「已知专有名词」**（本作 `天使の庭リース / 聖都セレスティザム / 首都ウォードン …`），
  勿用「含某个字符串」当唯一判据（正文里也会提到同一名词，会选错叶子）。
- 输出：**去 `（読み）`，改 `【見出し語】解説`**，一行一条，**并入 `_全文本.txt` 末尾**。
- ⚠ 辞典常与 **依覧/人物情報/話題 データ** 同处一个模块 ⇒ 先用指纹（本作：`この話題は最初から知っています` /
  `依頼主に会えば` / `（主人公のプロフィールは削除予定`）把这些**菜单载体整体排除**，只留辞典。

## ★ 「字面名 vs 宏注入名」：宏的钥匙在**引擎字符串表**（2026-10-16，HuneX IKA SEQ 幽霊船）

- 症状：正文里某词（主角名/昵称/宠物名）**100% 带同一个前置全角符号**（本作 `＄` U+FF04），他人名 0%。
- 正解：**别在正文里猜**。解开 EBOOT（`~PSP` → MIPS ELF）后搜该符号的**默认值表**：
  本作 `0x1c79dc` = `＄フェリチータ\0\0＄フェル\0\0\0\0＄フクロータ\0\0\0\0` ⇒ `＄<默认名>` ＝ **姓名槽插入宏**（主角＋宠物各自一槽）。
- 处置＝**删宏、保留其后的默认名**（主角名 inline）；⚠ 与名札里作「显示名＠内部名」分隔符的 `＠` **不是一回事**（两符号可同作并存）。
- ⚠ 若同族前作报告曾判「无名字插入宏」（Festa Regalo 曾如此，已于 2026-10-16 修正：成品内 32 处 `＄` 全去、按默认名 inline），新作遇同一符号**必须用引擎表复核**。
