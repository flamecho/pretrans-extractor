# 互斥备选 / 整段折叠 / 选项数据区（B22·B24·B25·B26）

> B7–B13 见 `04-lines-cases.md`。

**B22. 守卫块 `_IF__(变量,op,值,标签) … _ZY<id>(标签)` ＝ 互斥备选 ⇒ 只留第一支**（赤い砂堕ちる月 実証）
HuneX「Ogre」系部分作用**扁平守卫块**表达分歧：`_IF__` 后跟 body，`_ZY<id>(标签)` 回收（标签＝该 `_IF__` 的末段）。
- **判据**：**相邻**（中间无普通指令）且**同变量**、**条件互斥**的守卫块 ＝ **同一点击的备选 ⇒ 只保留第一支**。
  互斥＝`eq k` vs `eq j`(k≠j) 或 `eq v` vs `ne v`。赤い砂 `F038 eq0..4`＝5 性格（同场景写 5 份，多仅立绘异）；OZMAFIA `G241 eq0/eq1`＝相遇标记（文本全同、仅语音异）。
- ⚠ **条件相同**的相邻守卫（`ne 0`＋`ne 0`）是**两个独立跳块**（两体**都**执行）—— **不可丢**。**闸门＝「是否互斥」，别只看「变量相同」。**
- ⚠ **整串 vs 成对**（OZMAFIA 実証）：序列常为 `[eq0,eq1,eq0,eq1,…]`（`_IF__` 条件**成立即跳过其 body**）⇒ **须两两配对**，不可整串只留第一。
  且 **仅当两支 body 正文逐条完全相同才折**（宁多勿失），配对判定须**容忍两支之间夹「无正文语句」**（如 `_STCH(...)`）。
- 实现：栈式扫描（记「最近闭合的守卫条件」＋「此后是否出现普通指令」）；`_ZY` 标签匹配即弹栈。`_IF__`/`_ZY` 数应配平——先核对再动手。
- 量级：赤い砂 `_ZM` 54,534 → **30,162 行**；OZMAFIA 40,348 → **39,222**（相邻重复 869→9）。
- ★★ **反例：同族续作的守卫块可能「完全不承载正文」⇒ 先量化块内文本数，为 0 就整个跳过折叠**（罪喰い for V PCSG01019 実証，2026-10-14）：
  本作 `_IF__`×429 / `_ZY`×437，逐块统计 `_IF__…_ZY` 区间内 `_ZM` 计数 **全为 0**（块内只有立绘/语音/演出/`_GOTO`）
  ⇒ 文本严格线性、**无需任何折叠**。⚠ 与赤い砂（`F038 eq0..4` 5 性格同场景写 5 份、**必须折**）**同族却相反** ⇒
  **不得因「同族同结构」照搬折叠**；动手前必跑「块内正文计数」，0 就跳过折叠分支。
  （同源：**`_MSAD`「续接同框」语义逐作可变** —— マジきゅん／罪喰い＝合并、カレイドイヴ `@n`＝拆行；一律以**引号配对**当验收探针。）

**B24. 互斥分支可能把「整段场景」重复发射 ⇒ 按「整段全同」折叠；判框优先用「指令签名统计」（MARGINAL#4 実証，2026-10-11）**
- 编译器会把**同一段场景**分别发射到两条互斥分支下：`101_ATOM01.DAT` 中 idx207–270 与 idx307–370
  有 **62 行完全相同**（仅前 2 行 lead-in 异）⇒ 成品凭空多 20% 行（36,032 → 28,836）。
- **折叠规则**＝只删「与前面**完全相同的整段**」，任何只出现一次的行都不动；保留 `--keep-dup` 开关出全貌版。
  **阈值先由数据定**：统计重复块长度分布（本作 6/18/20/24…78 各 1），阈取 5 安全。
  ⚠ 阈值必须 >「N 名角色各说同一句」的**自然重复长度**（本作 4 行，`speaker_id` 各异 ⇒ 真文本，**不可删**；同 B10 纪律）。
- **★ 顺带的通用判框法**：判「两条文本记录是否同框」别靠引号启发式（本作全篇引号仅 196 对，几乎无分辨力），
  改**统计相邻两条文本记录之间的指令集合**：`()`（**中间无任何指令**）35,683 例 ⇒ 同框必合并；
  含「换框 op」者 ⇒ 断行。一眼定案，且天然回避「引号配对」的假象。
- ★ **另一触发形态：两份的码流不同、展开后文本相同**（プリンス・オブ・ストライド 実証）——
  同一场景发射两次时，一份人名用**字面**、另一份经 **`FFE6/FFE7` 宏** ⇒ 原始码**不同**，但**宏展开后文本全同**。
  ⇒ **折叠必须在「宏展开后的文本层」比较**；在码流层比会判成不同、一条都折不掉（本作若不折，相邻重复约 **750 组**）。
  落地：`fold_repeats()` 放在「码流→文本」之后（同 OPCODE 双写与宏双写共用同一折叠函数）。
- ★★ **先量化，再决定折不折**（Vamwolf Cross† 実証，2026-10-12）：「同族引擎」**不等于**「有双写」。
  动手前先跑一次**双写块计数**（`i..i+k == i+k..i+2k` 的块数）：**为 0 ⇒ 必须禁用折叠**。
  ⚠ 无脑折叠的代价：本作实测块数 0、却折掉 1 行，**并让全篇引号计数失衡（`「` vs `」` 差 1）**——
  即「折叠」把一处**真·相邻重复**（`「え？」`）当双写删了。**判据：产物自检的引号配对就是折叠误删的探针。**

**B25. 选项文本可能在「指令之外的数据区」＋ 断框须含「名札 / 变量 op」（MARGINAL#4 RTG，2026-10-11）**
- ★★ **选项 op 的参数可指向「指令之后的数据区」记录**（指令 @`0x737d4` → 文本在 `0x73818`，**不在** `[p,p+len)`）。
  ⇒ 只做「**内联范围判定**」的解析器**选项 100% 漏**。正解＝**双路**：内联失败再按**绝对偏移**取记录（仍用签名校验）。
  ⚠ 同文件**库函数区**另有同 op 若干条、参数是常量（`0xFFFFFF0x`）⇒ 须按「**能否解出有效记录**」过滤。
  ⚠ p2 常是**跳转标签**（`sure2/3/4`）⇒ 可作分组自校验。
- ★ **断框不能只认换框符**：少数短句框尾无换框符，引擎把「切变量/显示状态」当隐式断框
  （`304.DAT`『え、何？』后紧跟变量 op `0x4F80 'switch'`）⇒ 会并句。
  断框集合四类：① 换框 op ② **名札 op** ③ **按名访问变量/标签的 op** ④ 章题/选项 op（同变体 B 判据；加 ③ 全库仅 +10 行）。
  ⚠ 框粒度自校验：统计**每框记录数分布**，峰值 ≤3 ⇒ 「预排版显示行」，框内连续记录合并为一行。

**B26. 选项 ＝ 「连续 `FFFF` 链」（D3P 系 CPK＋自建字体；プリンス・オブ・ストライド 実証，2026-10-12）**
选项**不在独立 op 里**，而是**一串连续的 `FFFF`（框）记录**紧挨在一起；每条 run 形如 `<样式符><选项文本>`。
- **组内首条无样式符、其余恒有 1 个**；**单符号 run**（`　〃` / `　；` / `　ー`，即 1 个全角空格＋1 符号）
  ＝**组分隔符**（一链可含多组＝时限制选择的多个分支）⇒ 用它把链切成组。
- **链尾填充 run**（≥6 个全角空格）不是选项，剔除；空 run 直接跳过。
- **落地：就地输出**（忠于剧情顺序），**不要**附到全文末尾（与「选项＝一行一条、按序」的总口径一致，且保住顺序信息）。
- ⚠ **链内若含系统/UI 菜单项**（`最初から開始する` / `シーンNから開始する` / 带 `はい`/`いいえ` 的场景选择链）
  ⇒ **整链丢弃**。⚠ 只按「单条黑名单」剔会漏（同链里 `はい` 是通用词、单看无法判）⇒ 必须**先整链判、再决定整链留或弃**。
- 与 B18「选项 op 可独立、双写取组 1」的区别：B26 是**无 op、纯框链**形态（同族引擎的另一种选项表达）。
- ★ **同族他作实测（Vamwolf Cross† PCSG00467，2026-10-12）：前缀形态逐作可变，别照搬**——
  プリンス＝组内非首条恒剥 **1** 码；Vamwolf＝恒为「`　`＋样式符」**2** 码。
  ⇒ 判据写成「**组内首条无前缀、其余恒定 N 个**」，落地＝`if run.startswith('\u3000'): strip 2`（比「按不可见字符剥到正文首字」稳）。
- ★ **同族他作的两处结构性差异（同报告）**：① 正文 op 可能是 **`FF95 <固定 3 码前缀><TEXT>`**（不是 `FFFF <TEXT>`）；
  ② **宏链**——`FFE6`(姓) 紧跟 `FFE7`(名) 时第二个宏会被「只看前一 token」的判据丢掉，须允许**宏链续接**。

**B31. 选项行可能带「显示条件」⇒ 同组同文案＝互斥备选，须「组内取一」（Aromarie ATL 実証，2026-10-15）**
有些引擎把**显示条件写在选项记录上**（不是写在脚本分支里）：Aromarie「ATL」的 `choice` 表有 `eval` 字段
＝一段 Lua 条件（`return gameScene[N];` / `return not gameScene[N];`），**空＝恒显示**，只有求值为真者才上屏。
- **症状**：同一 choice 组里出现**多行完全相同文案**（本作 6 组：`誰かに相談？`×5 / `出る`×2 / `帰宅する`×2 …），
  若不查条件就会**原样输出多条重复选项**（并把 `check_text.py` 的「相邻重复行」警告点成一片）。
- **判据**：同组内**同文案多行** ＋ 每行绑**不同的 `eval`/条件**（常为互补：`return gameScene[1420]` ↔ `return not gameScene[1420]`）
  ⇒ 是**互斥备选**（作者为「同一句选项、不同后续」写的多条记录）。旁证：脚本内注释「…を通過した場合強制的に…を選択」。
- **修法**：**同组内按首现顺序去重取一**（`if ct not in seen`，**只在组内**，勿全局去重）。本作 141→132。
- ⚠ 反向风险：真·同时显示的重复选项（玩笑/陷阱选项）会误删 ⇒ 落地前先列全集人工过目（本作 6 组全部符合互斥特征）。
- 与 B7/B22/B18 同族（「互斥分支同段取一」），只是**互斥粒度是「组内选项行」**而非「正文段」。

## 变体分支的对白**不是重复**，不能删

- 现象：同一剧情点存在「含主角名 / 不含主角名」或「A 分支 / B 分支」两套近似行。
- **判据：两套在游戏里都会实际播放**（条件不同：称呼分叉、性别/性格分歧、路线 flag），属**有效文本**。
  → 一并删除会**丢内容**；只能按「同一条件下互斥」折叠，不能按「文本相似」折叠。
- 反例来源：遥か6DX 変体分岐（含/不含主人公名的两版）；STORM LOVER 系性格分歧；赤い砂堕ちる月 `_IF__(F038)`。
- 做法：先找出**分歧条件**（`_IF__`/switch/称呼表），再按条件分组；只对「同组内重复」去重。
