# 坑 · 提取层 B（行粒度 / 一次点击=一行）

> **一次性总览看 `pitfalls/A1-decode-core.md`**（那条索引已覆盖全部坑）；本文件只在**对应阶段**才读。

## B. 提取层（行粒度）

**B1. 续写形态必须做全集**（否则碎片行 / 长行粘连，两个方向都被退过）
コルダ 实证的 **5 种**：
1. `INS` 追加码（同框续写）
2. **名字插入块横跨一条文本记录**（记录本身就是插入块的字面量，其后间隔只剩收尾操作数；
   需跟踪「插入块是否仍开启」）
3. **间隔恰好只有 `CLOSE`**（无 msgid / 无边界码）→ 纯续写
4. **只有标点/空的记录 = 框内文本更新帧**（不另起一框）
5. **纯停顿帧**（整框都是标点/空）→ **丢弃**

★ 安全写法：**「默认新框，只在看到追加码 / INS 才合并」**。
反过来「要求必须有 INS 才算续写」会**漏合折行**（我犯过的错）；「默认合并」则会粘连标题/菜单。

**B2. 纯标点记录不要无脑断链**
否则会把 `「香穂子…` 拆成 `「`。但**整框都是标点/空** ⇒ 停顿帧，丢弃。
与 `4` 的区分：**仅当当前框尚未收句**（不以 `。！？」』）` 结尾）时才并入；已收句者单独成框并作停顿帧丢弃。

**B3. 标签/调试串要断链**（`is_label()`），否则菜单/标题会粘到正文上。

**B4. 互斥随机台词会并成一行**
无收尾标记就 `goto … textclear` 的随机台词串会被线性扫描并成一行（最长 589 字）。
→ **进入新 `*label` 且当前页未结页时 → 结页**（分支/随机台词互斥，标签即显示上下文边界）。
主剧情几乎不受影响（+54 行）。

**B5. 大字号演出把话者名写进正文流**
`setwindow3 …,0,0,…`（字号 0 = 不可见/全屏）后把 `【　椿　】` 之类的说话人名当普通文本行写进正文，
紧跟台词行且中间无点击标记 → 被并成一行 → 看起来像「说话人前缀残留」。
→ 裸名札文本行（`^【[^】]*】$`）视为说话人标签**剔除**。常规对白（99.9%）走 `name` 命令，人名不进正文流。

**B6. 页 / 点击粒度不要跟随引擎的宽窗模式**
脚本的 `*text_all*`=28×16 / `*text_all_angeltxt`=38×20 只是**显示模式**，
物理宽窗会把整段对话并成一行。**除非用户对本作另有明示**，一律「一次点击 = 一行」。

**B14. 先测「记录长度硬上限」→ 判定「记录是否＝显示行」（RE:VICE[D] 实证）**
对全库文本记录做**长度直方图**：若存在**硬上限**（本作 28 字，峰值 14-17、**0 条 ≥30**），
则该上限＝编辑器**预排版的一行宽度** ⇒ **记录 ≠ 框，框 = 连续记录**（支持「相邻记录合并」），
也解释了「一条记录会在句中断开（`まで` / `のだろう` 处断）」。**本作框记录数 97.2% ≤3 行**。
> 反向亦可用：若记录长度**无上限**，则记录可能本就是整框，合并前要多验一层。

**B15. 「长行是否该拆」→ 用官方截图核对显示模式，别靠字符猜**
1. 拉官方站 / vndb 截图（`POST api.vndb.org/kana/vn`，`fields:"screenshots{id,url,dims}"`）**看图**：
   窗口满载几行？有没有**无窗全屏地文**模式？（RE:VICE[D]：窗口模式满载 3 行 ＋ 全屏地文无框）
2. 长段若**记录之间没有任何断框 op**、且文本是单一语义单元 ⇒ **脚本层的单条 message，不拆**；
   引擎若内部翻页，脚本里并无对应 op，不能凭「长」推断。
3. **句中 `」`/`「`/`（`/`）` 只作筛查探针**（=扫出可疑行再去回查源码），**不可当断框判据**。
   同作实测：字符启发式比 op 判据**少拆 100 处**（旁白→旁白段）。

> **B7–B13（各引擎实证案例：互斥分支/双写归并/框内换行/共通导入块/框标记多形态/名札边界/记录框语义/边界字段不可信）见 `04-lines-cases.md`。**

**B16. 行内断行符（`\` 等）究竟是「框内换行」还是「翻页」—— 两条硬判据，别靠感觉**
行式脚本常用一个符号（反斜杠 / `@` / `\n` 文本内标记）表示「此处断行」。它到底是**同一文本框内换行**（须合并＝一行）
还是**翻页**（须拆成两行），直接决定成品行数。用下面两条独立判据互证，**不要凭语感**：

1. **框几何统计（一步出结论）**：在全部脚本上统计
   ① 每个「步」（= 脚本的一行）内该符号的**段数上限**；② 去掉内联标记（如 `<dicNNN>`）后**每段字符数上限**。
   二者应分别等于**文本框的行数**与**行宽**；`段数上限 × 段长上限` ≈ 单框容量 ⇒ **1 步 = 1 框**，该符号就是**框内换行（合并）**。
   实测（爽海バッカニアーズ!）：段数上限 **3**、段长上限 **28 字** ⇒ 文本框 3 行×28 字，1 步 1 框 ⇒ `\` 为框内换行。
   - 反证用法：若某步的段数能超过「单框行数」（例如出现 5、8 段），则该符号必是**翻页**而非换行。
2. **截图/说明书回源比对（最硬）**：游戏同捆的 **`sce_sys/manual/*.png` 是原生分辨率实拍**（PSV 为 960×544）。
   取截图里的一句台词 → 回脚本检索同句 → **看脚本里 `\` 的落点是否正好等于截图中的视觉断行处**。
   若 `\` 正是视觉换行点、且该框内同时出现前后两段 ⇒ **框内换行（合并）**；
   （若 `\` 是翻页，截图只会出现半句。）另外：**文字靠上、下方留空**的框 = 固定多行框，可据此估框高。
   > 技巧：Pillow 裁剪 + 4〜6× LANCZOS 放大即可辨读小字（`~/.workbuddy/binaries/python/envs/default` 装 Pillow）。
3. 旁证：**同一断行符的两种用法会同时存在**且数量悬殊时，说明作者刻意区分「同框换行（`\（`）」与「独立成框（行首 `（`）」——
   例：`\（` 仅 1 例，行首 `（` 1547 例 ⇒ 前者是刻意把括注放进同框末行。

**B17. 换页符 / 暂停符的语义**同引擎跨作会反转** ⇒ 用「**引号配对**」当判据，别照搬旧作的拆行口径**
同为 HuneX「**Ogre**」系：カレイドイヴ 的 `@n` 判为「框内换页 → **拆新行**」；**マジきゅんっ！ルネッサンス 实测相反** ——
该作 `@n`(41) 与 `_MSAD`(41) **严格 1:1 配对**（`_ZM(…@n)` 与 `_MSAD` 之间只隔 `_WTVT`/`_STCN`/`_FADS` 等演出指令），
且 `_MSAD`＝续接**同框**（引擎文档口径）⇒ `@n` 是**框内暂停**，须**合并成一行**。
- **判据（一步定案）**：先按「拆行」跑一遍 → 若出现**成片的 `行首「未闭合`**（本作 **35 行**：`「………………` ＋次行 `…ます！」`），
  改按「合并」后**归零** ⇒ **拆行是错解**。因为整部作品的引号总量是配平的，某框以「起句而不收尾 ⇒ 该句必续在下一显示单元」。
- 合并口径下**真正跨框**者只会剩极少数（本作 1 处：MINISCENARIO 电话场景被切断的台词 `「…しな。`＋`…見て――」` 分属两条 `_PSSM`）
  ⇒ 再用「**未闭合引号 ⇒ 与次行归并**」兜底即可（勿正则泛修，只按此判据）。
- ★ 换作同族引擎：**先统计 `换页符 ⟷ 续写指令` 是否 1:1 配对**，再决定拆 / 合并；**引号配对永远是验收探针**。

**B18. 「选项」未必依附正文 op —— 按「引用短句的 op」独立找；双写变体取「组 1」**
- **别假设选项＝正文 op ＋ 标志位。** STCM2L PSV 变体 D（ROOT∞REXX）实测：选项是**独立 op `56856`**（np=4，
  `p0`=选项文本记录、`p1`=空、`p2`=序号/filler、`p3`=跳转 label）；**连续多条 `56856` 紧接选择结果变量 `switch`** ＝ 一组选择肢。
  找法：枚举 `ic==1` 的 opcode → 取「`p0` 指向**短句**记录、且成簇出现」者（正文 op 的串是整句、选项 op 的串短、同簇同结构）。
  ⚠ 同名 op 在**每文件开头的共通 init 块**里可能以 `p0>=0x80000000`（栈/哑参）出现 ⇒ **只在 `p0` 是真记录时才收**。
- **双写变体**（同一文本框 2 个变体，非 `goto` 分段）：ROOT∞REXX 的 `121804`(np=8)＝`[id][t1][t2][t3][id2][t1'][t2'][t3']`
  —— 对应游戏的「呼び方/敬称」设定。取法＝**统一取组 1**：两变体**都含 `#Name` 时「不含宏者优先」失效**，
  差异通常是「称呼 / 助词 / 标点」。
  自检：两种取法各跑一遍，看输出里是否出现**成对的近重复行**（差一两个字）——成对 ⇒ 取错或未归并。

**B27. 文本框不止以 `0A 00` 结束 —— 换页命令 `FB FF` / `FE FF`**（2026-10-14，マスケティア）
- **症状**：出现**超长行**（一个「文本框」里塞几百字）＋**多条选项被并进同一条**。
- **成因**：长旁白 / 选项列表在引擎里是**多个「页」**，页与页之间的命令是：
  - `FB FF <u16 A> <u32 B> <u32 × B>`（B＝其后 u32 的个数）
  - `FE FF <u16 A> <u32> <u32> <u8>`（随后 `FE 00` 才带正文）
- **判据**：**终止符集合＝`{0A 00, FB FF, FE FF}`**（不是单一 `0A 00`）。页间参数字节由「非字符字节直接跳过 ＋ 起点前字节∈{00,02,1F}」自然跳过，无需专门解析。
- **实例**：マスケティア 学园说明 321 宽 → 正确拆成 9 条（最长 61）；`辞書のように分厚い専門書。` / `恋愛小説にします。` 本是两条选项。
- **自检**：**任何一行宽 > 约 120 全角 ⇒ 先怀疑有换页命令未被当作终止符**。
