# 行完整性审计（引号 / 括号结构）

> **一句话**：交付前必须做「**结构穷举**」——把每行的 `「」` `（）` `『』` 按配对嵌套拆成顶层段，数「一行塞了几个框」。
> 只靠单一正则（例如只查 `」「`）必然漏，见 §0 的返工记录。

## 0. 为什么单独立册（2026-10-26 返工记录）

27 部批量交付后，用户指出「句中 `「`/`（`/`」`/`）` 是错误指示器」。一查：

| 探针 | 命中行 |
|---|---:|
| `(?!^)「`（行中开引号） | 1,818 |
| `(?!^)（`（行中开括号） | 2,739 |
| `(?<!^)(」)(?!$)`（`」` 两侧都有内容） | 2,137 |
| `(?<!^)(）)(?!$)`（`）` 两侧都有内容） | 1,571 |

**根因不是「没查」，是「每次只查一种外观」**：先只查 `」「`（相邻两框），漏了
`「A。「B」`（前段缺闭合）、`「A」B」`（后段缺开引号）、`（A）（B）`、
`地の文…台词」`（台词尾巴粘在叙述后）、以及**完全没有引号的 `A。B。`**（地の文双版）。
⇒ 本册把验收改成 **三维穷举**（结构 / 字符 / 版式），任一项不通过不得交付。

## 1. 四探针（只用于「找」，修必须靠代码）

```python
(?!^)「             # 行中出现开引号
(?!^)（             # 行中出现开括号
(?<!^)(」)(?!$)     # 」既不在行首也不在行尾
(?<!^)(）)(?!$)     # ）既不在行首也不在行尾
```

⚠ **探针只报警，不判性质**：`「はい」とも「いいえ」とも言えず`、辞典条目 `「ポーン」の役職…「キング」に挑み`
都命中，但都是**合法内联引用**。必须加 §2 的结构判定。

## 2. 结构判定（A / B / C / D 四类）

```python
def scan(s, op, cl):
    stack, pairs, depth_top = [], [], 0
    for i, ch in enumerate(s):
        if ch == op:
            if not stack: depth_top += 1
            stack.append(i)
        elif ch == cl and stack:
            pairs.append((stack.pop(), i))
    return pairs, len(stack), depth_top     # 配对表 / 未配对数 / 顶层段数
```

| 类 | 判据 | 含义 | 处置 |
|---|---|---|---|
| **A 失衡** | `「`数 ≠ `」`数 | 必有截断（跨行 / 缺符号） | §3 ①②③ |
| **B 失衡** | `（`数 ≠ `）`数 | 同上（独白） | §3 ①②③ |
| **C 多段** | 平衡但顶层 `「…」` ≥2 | 可能一行两框，也可能内联引用 | §4 判据 |
| **D 多段** | 平衡但顶层 `（…）` ≥2 | 可能两个独白框，也可能「人名+状态注」 | §4 判据 |

工具：`scripts/struct_probe.py 提取结果/*.txt [-v --kind C]`（逐部计数 + 样例）。

## 3. 六类缺陷与对应代码

| # | 缺陷 | 外观 | 处置 | 工具 |
|---|---|---|---|---|
| ① | 框内软换行被切成两行 | `「…` ／ `…」` 分处相邻两行 | 下行**不以 `「` 开头**且余额为闭 ⇒ 并成一行（可多行） | `fix_wrap_pairs.py`（join / joinup） |
| ② | 台词尾巴粘在地の文后 | `地の文……台词」` | 在**最后一个句读**处拆两行，后半补 `「`（闭合补回后半） | `fix_wrap_pairs.py --repair`（split） |
| ③ | 缺 / 多一个引号 | 行余 `「` 或 `」`，差恰 1 | 补 `」`／删多余；**行首是开符号才删**（否则走 ②） | 同上（close / trim） |
| ④ | 一行两框 | `（A）（B）`、`「A」「B」`，**段间只有空白** | 拆成每段一行 | `fix_multi_brackets.py` |
| ⑤ | 说话人名+状态注 | `リュウ・クロア（子供時代）（…）` | 剥 `人名（注）`，只留独白（本批不显示说话人） | 同上（strip） |
| ⑥ | 名字宏双版交错 | `「義経様は…。「遮那王様は…」` | §5 合并算法 | `merge_name_variants.py` |

**① 的判据必须双向**：`「…` 行若**下一行以 `「` 开头**，就不是续行，而是「前框缺闭合」⇒ 走 ③ 补 `」`，**不许合并**（否则两框被缝成一句）。

## 4. C/D 类：拆不拆，只看段间是什么

| 段间内容 | 判定 | 例 |
|---|---|---|
| **只有空白** | 并列两框 ⇒ **拆** | `（進め方はどうしようかな……）（ザフォラは本気でやってるだろうし…）` |
| `と` / `って` / `や` / `、` / `など` / `という` | 内联引用 ⇒ **不拆** | `「はい」とも「いいえ」とも言えず…` |
| 行尾残留 `と`（引号后无内容） | 源侧截断 ⇒ 报告，不改 | `「２人にはバレてないよな…」「うまくいくといいけど…」と` |
| 首段短（≤10 字、无句读）+ 前面是纯人名 | 人名+状态注 ⇒ **剥前缀** | `リュウ・クロア（子供時代）（叔父さん、遅いな……）` |

**误判成本**：把内联引用拆开 ⇒ 语义断裂；把两框留着 ⇒ 一行两次点击、译文串味。所以「段间是否有连接成分」是硬判据，**不看长度、不看语气**。

## 5. 变体三义（术语必须先分清，否则一直返工）

| 名称 | 是什么 | 是缺陷吗 | 处置 |
|---|---|---|---|
| **双版对照** | 一页内 ≥2 次点击（换行 ≠ 换页） | **不是**，是交付格式 | 段行 + 合并行都出；`--dual --expect-dual`；报告写 `- **版式**：…` |
| **名字宏双版** | 同一句存「字面名版」+「宏回填版」，提取时两版被拼进一行 | **是** | 合并，**保留宏回填版** |
| **点名版 / 泛称版双写** | 同一句存「点名版（セシリー）」+「泛称版（キミ／あなた）」 | **是** | 去重，**保留点名版** |

判据：两段**去名字后逐字相同或相似度 ≥0.9** ⇒ 同一句的两版；否则是两句话。

## 6. 名字宏双版合并算法（⑥）

```python
# 1) 切点 = 行内层引号的位置（两版一定被一个多余的开/闭引号隔开）
cuts = [k for k, ch in enumerate(body) if ch in '「」']
# 2) 每个切点：A = 前半，B = 后半，各自剥掉并排时多出的首/尾括号
# 3) 取「更完整的一版」
eq = cover(A, B)                       # A 中有多少字被 B 覆盖
if eq/len(A) >= 0.8 and len(B) >= len(A):  m = B      # A 是残段
elif eq/len(B) >= 0.8 and len(A) >= len(B): m = A      # B 是残段
else: m = merge(A, B)                                 # 各有一半 ⇒ 逐字对齐
# 4) 名字统一为宏名：遮那(?!王) → 遮那王
# 5) 校验：引号/括号平衡、长度 ≥ 原 60%、无残留重复子串
```

**merge 的安全阀**：若 A 有独有实词段（≥8 字，非空白），说明两版内容不同 ⇒ **拒绝合并**。
这条防止把 `（胸の高まりを抑えられなくなってしまう。継信のことしか考えられなくなってしまう。…）`
（自然重复）误当双版合并掉。

**迭代**：三版交错（`「A」　A'」`）需重复执行 2–3 轮；每轮后仍要过校验。

## 7. 无引号的双版：`dup_probe.py`

地の文双版**不产生任何引号异常**，四个探针全部抓不到：

```
義経の酌を思い出し、重衡の顔は自然と綻んだ。遮那王の酌を思い出し、重衡の顔は自然と綻んだ。
```

判据：名字替换成占位符 `@`、去空白后，找**长度 ≥10 的重复子串**。
⚠ 演出性重复（`ァァァァ`、`ごめんなさい、ごめんなさい`、`許さない許さない`）会命中 ⇒
**合并结果若仍含重复 ⇒ 拒绝**（回到原样），这条把「连呼」与「双版」分开。
