# 解密 / 解码套路（细节）

对应 SKILL.md §2 的 S3〜S5。按顺序做，成本从低到高。

## 1. 先试已知魔数（最便宜）
图片、音频、压缩流的头部是**确定的** → 直接 `key = cipher[0] ^ magic[0]`。
- PNG `89 50 4E 47` / OGG `4F 67 67 53` / ZIP `50 4B 03 04` / zlib `78 9C|78 DA` / BMS…
- 若整文件键恒定 → 一步搞定。**先做这一步**。

## 2. 压缩之后还有一层
`zlib` 解开后**未必是明文**。典型：解开后再做 **1 字节 XOR**（如 KiriKiri 系）。
用**字符似然模型**定键：以已知明文段（或已解出的其它文件）训练 cp932 字符/字节频率，
对每个候选键打分取最大；窗口要有重叠以防噪声（16〜96 字节窗口，取总长固定以免长度偏差）。
注意：模型评分必须**固定总长**，否则短窗口天然占优。

## 3. 键「基本恒定 + 个别字节例外」
- 同一文件内**主键恒定**，但**极少数孤立字节用了另一个键** → 1〜3 字的化け。
- 也见过**真·多区间**（`first.ks` = `[0,574)` 键 0x93 + `[574,700)` 键 0x18，边界落在词中间）。
- 定位孤立坏字节：**严格 cp932 遍历**找非法位置；再对邻域枚举「使窗口完全干净」的改法。
- 判别「哪个键才对」用**语言模型得分 + 上下文**，不要只看「解码不报错」。
- 根因往往**不能硬啃**（KiriKiri 的 `poisonchain.tpm` = RSA 公钥 + 加密 `.decc` 节）→ 放弃逆算法，
  改用**定值复元表**（每条注依据）。

### 复元表的落地顺序（`scripts/chou_fix.py` 是范例）
```
REKEY       区间改键（多区间）
 ↓
OVERRIDES   按字节位置替换（等长，最精确）
 ↓
TEXT_PATCH  按字符串替换（可增字/变形，如补落字、整行修正）
```
`apply_fix()` / `apply_text_patch()` 接进解码管线，保证可复现。

## 4. 化け的两大类（**两类都要扫**）

| 类 | 表现 | 发现手段 |
|---|---|---|
| ① `〓` / `U+FFFD` | 坏字节造成**非法 cp932** | 严格 cp932 遍历，容易发现 |
| ② **半角假名化** | 坏字节恰好落在**半角片假名区间**（0xA1-0xDF / U+FF61-FF9F），躲过「非法字节」扫描 | **必须专门扫半角假名** |

机构（类②）＝「**双字节字的首字节被破坏**」→ 后续被重新配成「半角假名 + 别的字」。
- `金を作ﾕ驍ｵかない` → `金を作るしかない`（只差首字节 `0xd5`→`0x82`）
- `あの薔薇の花ﾍ思いがけず` → `…花は思いがけず`
- `頭が細かｻｭ震え` → `細かく震え`

复元依据（都不是猜）：
- **ルビ（注音）**：`[迎�'げいごう]`→`迎合`、`[花街'かが�]`→`かがい`
- **同型脚本平行**：9 本 `endroll_*.ks` 的 `[wait time=�00]` 数列完全一致 → 第 10 项必为 `500`
- **本文频度**：`右50?`→`右500`（同作 158 例）、`;?---`→`;■---`（798 例）
- **字节数硬约束**：`舌をﾙ?れる` 只 6 字节 → 必是 3 字 `噛れる`（噛=0x8A9A）
- **年代自洽**：`明治二十六年…今から二十dﾜ年前` → 「二十五年」（1893 ← 大正7=1918）

## 5. 官方修正补丁先解（★常被忽略）

- 同捆的 `Patch.rar` / `update.exe` / `patch.xp3` **先解开**。官方补丁常写「**一部の誤字脱字の修正**」。
- 内多为**与本体同方式的脚本文件** → 同一套解密即可解出 → 与本体 **diff 就拿到「作者认定的正确文本」**。
- 蝶の毒 v1.01 实证修正 6 处显示文：
  `斯波さま→斯波さん` / `噛察→観察` / 助詞脱落 / `*G用→雑用` / `済んだ→澄んだ` / `非常→非情`。
- **关键旁证**：`*G用→雑用` 说明**配布数据自身就带着化け文字** —— 不是解密方的错，官方只能靠补丁修。
  ⇒ 见到孤立化け时**两边都查**（自己的解码 + 原始数据缺陷）。
- 补丁**只覆盖部分文件**；未覆盖文件里的同类缺陷要自己判。
  （蝶の毒 `05_shiba_1.ks` 的闭引号 `」` 脱落就是官方漏修：原文 `…くださいね` + CRLF，
  XOR 保长度 ⇒ 物理上不存在该字节 ⇒ 数据缺陷，据「开 `「` 必合 `」`」补回。）

## 6. 判不出来时的旁证手段
- **同型脚本的平行结构**（最强）：抄写/复制出来的脚本，同一位置的值应一致。
- **字数/字节数约束**：目标字数 × 编码宽度反推。
- **语境/年代自洽**：日期、称谓、称呼矩阵。
- **已知明文攻击**：两枚归档里有同名文件 → diff 出密钥差异。

## 7. 「孤立化け」は総当りせず、逐位置定值复元表で（2026-10-07 定案）

**规律（蝶の毒 ～幻想夜話～ で確定）**：区间 XOR 系で起きる孤立化けは、ほぼ常に
**「2 バイト字の首バイト 1 個が別値に置換された」**もの。置換後の姿は 2 通り：

- (a) **ASCII になる**（`B` `7` `p` `b` `y` `C` `\r`→`p` 等）→ 半角/制御文字の走査で検出できる。
- (b) **別の合法な前導バイトになる** → 誤った漢字が出る。**文字種走査では検出できない**。

**修復手順（枚举しない）**：
1. 検出：(a) は「行内 ASCII・`【`/`[` 混入」走査、加えて **bigram 意外度**（`gensou_scan.py`）で候補を絞る。
   (b) は bigram 意外度の下位＋**稀な JIS 第 2 水準漢字**を目視（多くは正当な文学語なので誤報注意）。
2. 確定：**尾バイトは既に正しい**ことが多い ⇒ 「尾バイト＋前後文＋**同作内の平行語**」から正しい首バイトを一意に決める。
   （例：`ﾏﾘ財`→`借財`：借=8ED8、尾 D8 は既に正。同作に「借財の証書」あり。）
3. 記録：**逐位置定值复元表**（`{バイト位置: 正値}`）に固定 → 再現可能・高速。
4. **全探索・総当りは禁止**（用户鉄律 18）。数分走る総当りは無効な作業量。

**★ 制御行の化けは必ず直す**：`@endif` が `ﾋendif` 等に化けていると、パーサが制御行と認識できず
`@if/@else` の分岐整合が崩れ、**出力行数が大きく狂う**（実測 408→560 行）。表示文だけ見ていると気づけない。

**無圧縮 XP3 の罠**：XP3 で zlib 無しの変体がある（幻想夜話）。その場合、索引 `segm` の
`original` フィールドは当てにならず、**`stored`（第 3 フィールド）が磁盘長**。判定は「off+stored == 次の off」の連続性で行う。
