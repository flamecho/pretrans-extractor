# 坑 · 解码层 A9–A13（容器·归档·定长表 案例）

> 由原 `03-pitfalls.md`（23 KB）按阶段拆分（2026-10-10）。
> **一次性总览看 `SKILL.md` §3 的坑索引**（那条索引已覆盖全部坑）；本文件只在**对应阶段**才读。

**A9. 内联插入可能是「定长表引用」，别当成「文本内联」**
插入块解出来是空 / 断句时，先怀疑真值在一张**定长记录表**里（不是变量表缺失）。
- 表基址＝**用「空槽字面」反推**：空槽（`仮` / `用語予約NNN`）会把 **slot 索引 ≠ 逻辑 ID** 的错位暴露出来；
  由某空槽的字面编号 N 推 `base = 该槽地址 − N × 记录长`（遥か5：`0x1a5e0 − 368×64 = 0x149e0`）。
  直接 `base=0` 会整体错位、查到邻居值（表现为「差一个字」的假象）。
- 定位表本身：找**长度固定、首字段是可见语/读音**的密集区，用「首条已知语」（遥か5 首条 `御使い`）锚定。
- 表可能**一 leaf 内多张**（同 leaf 同时含 用语表 / 字表 / 章題表 / 年表），别只找一张就收工。

**A10. 同一作系的「本体」与「FD/续作」可能换插入机制 —— 每作必须重新求证**
遥か5 本体：正文插入走**两张定长表**（52B/64B）＋ `1e 05290204`/`1e 05b2027e`；
同作的 FD《風花記》则**完全没有表插值**（两指令计数 = 0），改为把用語/续写**直接写成内联 `04` 文本记录**
（前导 `02<id> + 1e 4e 04 3a 14` / `1e a6 04 a8 14`）⇒ 记录扫描+合并即得，**无需查表**。
→ 照搬本体代码会「找不到表」而断言失败；反之把内联当表则断句。**开工先数一次 TERMOP/GLOSSOP 计数**即可判定走哪条路。

**A11. 選択肢 op 与 调试菜单 op 可能是同一个 —— 结构分离不了，只能内容过滤**
風花記：選択肢 = `1e c6 02 87 06` / `1e 72 03 91 0b` 前导的 `04` 记录（正文流内、1 记录 1 条）。
但**デバッグ分岐メニュー也走同样的 op**（`〜の量は？` / `〜の場合` / `〜をセット` / `〜周目` / `見ますか？`）。
→ 别指望靠 opcode 区分；用内容剔除调试项，剩下的真选项按序收（这也符合「选项一行一条」）。

**A12. 見出し語/角色表锚定要「双重」—— 首条已知语可能在同一 leaf 出现多次**
風花記母表：`桐生 瞬` 在同一 leaf 内出现 **2** 次（0x65f1 的另一张表区 + 0x167cc 的真見出し語表）。
只按「首条已知语」取第一处会**锚到错的表**（stride、字段全乱）。
→ 追加第二个锚：要求「+stride 处正好是第 2 条已知语」（如 `+64B == 坂本龍馬`）才认。

**A13. 同一场景可能同时存在「旧稿 leaf」与「冒頭修正版小 leaf」—— 两个都当独立场景就会重复＋显示旧稿**
風花記の序章冒頭が 2 leaf に存在：
`leaf 18`（本編 126 記録。冒頭 `今度は…誰？`）と `leaf 4999`（9 記録。冒頭 `…誰か私を呼んでる。これは…？`）。
修正版 `4999` は**末尾で入口ラベル `イベント・共通序章頭` を宣言**しており、ゲームが表示するのはこちら。
→ 見分け方（自動判定可・本作で誤検出 0）：
  ① 同タイトル（先頭記録が一致） ② 冒頭が**逐条対応**（小 leaf の末尾ラベル連続を除いた n 条が、
     大 leaf の先頭 n 条と**位置対応**し、n−2 条以上一致かつ 1 条以上相違）
  ③ 小 leaf の末尾にラベル宣言がある ⇒ **overlay**。大 leaf の対応冒頭を差し替え、小 leaf 単体は出力しない。
- ⚠ 同タイトルの leaf 対は本作に 100 対以上あるが、**別内容（別分岐／別場面）が大半**。位置対応＋高一致率で絞れば誤検出しない。
- ⚠ 見落とすと「同じ冒頭が 2 回出て、初出が旧稿」になり、ユーザーが実機と突き合わせて必ず気づく。
- なお修正版 leaf は**冒頭だけ**を持つことが多い ⇒ 大 leaf の**本文は捨てない**（叙述接続＝別 leaf へ続くかで確認）。
