## 2. 外部资料核对（强制步骤）

**「解出来读得通」≠「字对」。** 替换槽 + 自定义码表决定了：语义通顺的句子里仍可能藏 1〜3 个错字。
（例：`完仆`(正:完璧)、`武居拓仭`(正:拓眞)、`赤星英佗奈`(正:英莉奈)。）

| 目标 | 首选来源 |
|---|---|
| **角色人名**（主角/攻略对象/配角） | **vndb** API `POST api.vndb.org/kana/character`（`filters=[["vn","=",["id","=","v<id>"]]]`，**2026-10-16 实测可用**，见下「修正」）；HTML `https://vndb.org/v<id>/chars` 作 role 分组/兜底 |
| 作品信息（发售日/开发商/平台） | vndb 作品页、官方站 |
| **歌名 / 乐队 / 品牌 / 店名 / 术语** | 官方站、攻略 wiki、まとめブログ |
| 台词原文（疑难字） | 攻略本、实况/プレイ日記、台词集 |

★ **抓 `/v<id>/chars` 必须带 `Cookie: vndb_view=2-/v<id>/chars`** —— 不带则**默认隐藏剧透角色**（ときメモGS3 实证：
不带只出 18 名，带上才补出 `藍沢 秋吾／春日 太陽／平 健太／若王子 貴文` 4 名）。命令：

```bash
curl -s -A "Mozilla/5.0" -H "Cookie: vndb_view=2-/v2956/chars" https://vndb.org/v2956/chars -o chars.html
```
解析：`<a href="/c\d+" … lang="ja-Latn">Romaji</a><small … lang="ja">原名</small>` **成对**取（正则
`lang="ja-Latn">([^<]+)</a><small[^>]*lang="ja">([^<]*)</small>`）；按 `<h1>` 分组读
（`Protagonist` / `Main characters` / `Make an appearance`）。**cast 首选 API**（`vn` 过滤可用，见下「修正」）；
仅需 role 分组或 API 异常时才走 HTML 页（`/vn` 的 `characters{}` 字段已废）。

★ **修正（2026-10-16，新宿羅生門 v34021 实测）**：`POST api.vndb.org/kana/character` 的 **`vn` 过滤其实可用** ——
`{"filters":["vn","=",["id","=","v34021"]],"fields":"id,name,original,aliases,sex,description","results":100}`
**一次拿全 cast**（13/13 命中，且带 `original` 日文原名／`aliases`）。先前误记「`vn` 过滤常报 Invalid query」的
真实原因＝ **`fields` 里塞了非角色字段**（`role`／`va` 会 `400 Invalid 'fields' member`；role/VA 属「(VN,角色) 关系」，
不在 character 端点）⇒ **优先走 API（快、字段全），只取 role 分组时再退回 HTML `/v<id>/chars`**。

★ **主角名取 vndb 的 `name`（罗马字）/ `original`（日文）** —— 游戏内**常无默认姓名**（只有
`ExtraProfilePlayerName`／`EntryProfile` 之类的 UI 回退值「主人公」），**别把回退值当主角名**。
四作实测（ときメモGS）：`｛主人公苗字｝`＋`｛主人公名前｝` 是**两个独立槽位**，都填回退值会输出
「主人公主人公」（用户实测发现）；正确做法＝**统一填 vndb 主角名**，且**相邻两槽合并为一个名字**。
主角无专名时（GS1）才保留 `主人公`。
★★ **vndb 也只写 `Nameable`、连 `name` 都没有**时（恋プリンス PCSG00590 実証，2026-10-17）：
游戏内两处输入（「あなたの苗字／下の名前を入力してください」）**输入框为空、无默认串**（`graph/name_entry/*.png` 只是标签图，
eboot 里也没有默认名表）⇒ **不存在「正解」**。做法＝**自取一个占位名**（姓/名各一个，**先查名札表确认不与任何既有角色撞名**），
成品 inline 填好，并在报告里写明「占位名＋可全局查找替换＋改脚本常量重跑」；不可留下 `{firstname}` 宏。

做法：
1. 先产两份清单再核对：① 全部说话人姓名（去重）→ 逐个比 vndb；② 全部命中「非日文字符/罕见字」的行 → 逐条上下文比对。
2. **以外部资料为准**：vndb 写 `拓眞` 而本地解出 `拓仭` ⇒ 该码位也是替换槽 → 补进 EXC 表重跑。
3. **查不到就不猜**：保留原码，报告里单列（码 / 次数 / 原句 / 可能读法）。
4. **反向校验**：外部资料给出的字若**从未**出现在自己输出里 ⇒ 还有未发现的槽位，回去复查。
5. **教训**：「该字在别处也出现过」**不能**用来排除槽位（同一字形可同时存在于槽位与普通码；
   莉 = `0x166c` 与 `0x0da8`，眞 = `0x143e` 与 `0x0da0`）。
6. ★★ **「名札表整表导出」＝零成本 cast 核对（首选手段）**：说话人名札（`FFF0`）**一定写全名**，
   正文里却往往只出现姓或名 —— 所以**别在正文里翻名字，直接导名札**：
   扫 `FFF0` 记录 → 去掉名字前的样式符（`？゛´｀゜￣ヽ＾¨ゝ〃ゞヾ仝〆ー〇‐々―／～＼｜…‘∥“（〔）` 等
   配色/字体样式参数）→ 去重 → **与 vndb 角色表逐字比对**。
   名札不入正文（§0），但它是最完整的 cast 表；**导出脚本 10 行，几分钟搞定**。
   （STORM LOVER 夏恋!! 实证：13 名名札 100% 命中 vndb v4597/v8030，主角无札＝玩家视角。）
7. ★★ **「字面姓名」与「宏注入姓名」必须分开判（本条最容易翻车）**：
   主角**可改名**时，正文里字面出现的姓氏**极可能是别的角色**。
   判据三条：① 名札里有没有该姓名；② 外部资料里该角色是否与主角**同时存在**；
   ③ 该姓名是否另由宏（`FFE6/FFE7` 之类别）出现。
   **反例（实际踩过）**：STORM LOVER 夏恋!! 字面 `猪狩` 74 框**全部是 猪狩 澪**（vndb c6095，男性配角），
   主角 **五十嵐 由奈**（c14782，`Name can be changed`）**只经宏**出现（字面 0 次）——
   当时误把字面 `猪狩` 当主角姓并 `RENAME` 成「五十嵐」，等于**把别人改成了主角**。
   ⇒ 交付口径若需改名，改的应是**宏的填充值**，**不是**字面姓名。
   ★ **报告须写明主角是否 `Nameable`（vndb tag / `Name can be changed`）＋名字出现性（经宏 or 字面）**；
   同系列各作主角**可不同**（STORM LOVER：V/夏恋!!=五十嵐由奈；2nd V=嵐山真理；**三作皆只经宏**）。
8. **看 vndb 角色表要看 role / 性别 / 所属作品，别只看主角那一条**：
   同一作品常有**同姓或近形**角色（猪狩/五十嵐、卯都木/丑木）；
   vndb 对部分 VN 只挂部分角色（副角色可能只挂在本篇 v 号下）⇒ 用 `filters=["search","=","<名>"]` 反查其 `vns`。
9. **正反双向核对**：① 外部名单的每个名字都能在成品里找到（**姓与名分开查**）；
   ② 成品里出现的专有名词都能在外部名单里找到。
   找不到时先分清「提取缺陷」与「数据本就如此」：
   例 `ミミ`(130 行) 与 `高未三咲`(名札) 同行 0 次 ⇒ 昵称/全名关系（两份名单同位可证），
   且字面「三咲」189 次**全在名札区** ⇒ 非缺陷。
10. **核对结果写进报告**（来源 URL + 「外部名单 × 成品」对照表 + 缺项说明），便于复核。

## 4. 报告与交付

报告（`提取结果/解析报告/XX_解析报告.md`）建议结构：

1. **源与容器结构**（大小、文件类型统计）
2. **保护 / 压缩方案**（逆向结论；**未解明部分要写明**，别装作全解了）
3. **脚本结构**与「一次点击 = 一行」的落地规则
4. **产物清单**（文件名 / 行数 / 校验值）
5. **外部核对**（来源 URL + 结论）
6. **化け复元表**（**每条注依据**：ルビ / 同型脚本平行 / 字节数吻合 / 年代自洽…）
7. **重跑步骤**（逐条命令）
8. **未决项 / 已知非显示项**

交付走 `present_files`（成品 txt + 报告）；**不要**把中间产物当交付物。
派生/合并版本（如 `@n`）保留原文、另存新文件，不改动原版。

### 4.1 报告头部要有**机器可读块**（新作强制；`archive_work.py` 直接读它）

报告**第一段**放这个（`---` 围起来，键值一行一条）。有它 ⇒ 索引字段零歧义；
没有 ⇒ 只能靠正则猜（会标「正则抽取，请核对」，实测主角只有 ~53% 能猜对）。

```yaml
---
作品: 西の善き魔女 ～Exalto～          # 不带 [平台-JP] 前缀、不带「解析报告」后缀
平台: PSP                              # PSP / PSV / PS2 / Switch / PC
引擎: STCM2L                           # 尽量写引擎名；未知写「自研」
主角: 西村 あかり                       # 带空格「姓 名」；可改名也写**默认名**
行数: 31,838                           # 成品 txt 的行数（与实物一致，会做一致性校验）
日期: 2026-10-18
---
```

- 键可用中文或英文（`title/platform/engine/main/rows/date` 都认）。
- **`行数` 必须与成品实际行数一致**：`wrapup.py` 会比对，差 >1% 就报 `[W]`（防用错文件 / 成品过期）。
- 本块只服务索引；正文仍按原有结构写（链路 / 容器 / 判据 / 重跑步骤）。
