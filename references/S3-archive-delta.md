# 归档块单位 / opcode Δ 平移 / 链式自校验

> WSC rotl / 前缀区见 `S3-wsc-ops.md`。

**归档的「块单位」不是常量 —— 用文件大小反推，取错会整体错位花屏**
「表内 `u32 offset` × 固定 UNIT + base = 文件真实偏移」的归档里，**UNIT 会随平台/版本变**，不可当普适常量：
- Malie `LIBP` 实证：`base + entry2[i] * UNIT`。**PC 版多为 1024，PSV 版 MalieVita = 2048**
  。
- **症状极具误导性**：取错 UNIT ⇒ 全部文件**整体错位**，表现为「**隔一个块是明文、隔一个块是化け**」的
  规律性花屏 —— 极易误判成「**部分文件被单独加密**」而白费力气去找密钥（英国探偵ミステリア The Crown 实证：
  一度据此认为 `.svg`/`exec.dat` 被加密，实则只是 unit 取 1024）。
- **判据（秒级、非枚举）**：`max(entry2) × UNIT ≈ 文件大小`（base 与文件同数量级，可忽略）。
  在候选 {1024, 2048, 4096} 里选最贴近文件尾的那个；`scripts/malie_extract.py::read_libp` 已内置该自适应。
- 通用化：**任何「表内 offset × 块大小」的归档，开工第一步先做这个校验**；别把某作的 unit 抄给下一作。
- 附 **MalieVita 指纹**（可与 PC 版 Malie 区分）：LIBP **明文**（无 Camellia）；`exec.dat` 里
  函数名/标签名 = **窄字节 ASCII**（非 UTF-16）、字符串表 = **CP932**（非 UTF-16LE）；
  **`_ms_message`(vCall `0x2D`) 调用数 = 字符串表条目数**（走全与否的硬判据）；
  主人公名宏 `07 0C <n> 00` 的 `n` ↔ `malie.ini` 的 `NAME<nn>`（`InputName=true` 才可改名）；
  `voice.csv` = 角色语音码 ↔ 角色名（可直接当人名核对表）。

**「同一引擎」的 opcode 可能**逐文件**平移 —— 别把 opcode 号写死**
STCM2L 的 **PSV 版**（Norn9 Act Tune）实证：**每个文件的导入函数 ID 整块平移常量 Δ**（Δ = 0x10 的整数倍；
实测 0 / ±0x10 / 0x30 / 0x40 / 0xe0 / 0x120 / 0x150），**只有 builtin 不动**（`0x1f4` 等待换框 / `0x6` goto /
`0x3` Mif / `0x0` / `0x11` / `0x12`）。
- 症状：同一功能的 opcode 在不同文件里数值不同（本作「文本 push」在 0101 是 `0xcfac`、0152 是 `0xcf9c`、
  1003 是 `0xd0ec`、5001 是 `0xcf8c`…）⇒ 若把 opcode 写死成某一文件的值，**其余文件整批丢正文**。
- **Δ 检测（秒级、非枚举）**：把「含日文串的 opcode」按**平均字符串长度**排序，取最大者为 `text_op`，
  `Δ = text_op − 0xcf9c`；随后所有 opcode 用 `op − Δ` 归一化。
  **切勿用「字符串出现次数」**——正文极少的文件（Norn9 的 5001–5010，除共通头外无正文）里
  flag 串（`色変化判定`×89）出现次数反而更多，会把 Δ 选错。
- 通用化：任何「opcode = 导入函数 ID」的 VM（STCM2L/自研 VM），**开工先验证 opcode 是否逐文件平移**：
  取两个文件比同一功能的编号差是否恒为常量。归一化后再定义 opcode 表。
- **另一形态：Δ 极小、且三个显示语义的相对偏移恒定**（STCM2L PSV 变体 C，PsychicEmotion6）：
  TEXT 目标只 ∈ {`0xCD7C`, `0xCD6C`}（Δ∈{0,−0x10}），且 **`NAME = TEXT+0x6FC`、`OPT = TEXT+0x10F4`**。
  ⇒ 先用「引用含日文串最多的 call 目标」定 TEXT，另两者**直接按常量推**，不必逐语义扫。
  判据：`OPT` 是 `np=2` 的 call（`p0`=选项文本记录、`p1`=跳转目标）；`NAME` 的串短、`OPT/正文`的串是整句。
- **第三种形态：opcode 完全恒定、Δ=0**（STCM2L PSV 变体 B/D：RE:VICE[D] / ROOT∞REXX）——
  同一语义的 opcode **全库一致**，此时**不能用 Δ 检测**：直接「按『引用含日文串的记录数』排序枚举 ic==1 的 opcode」定 TEXT/NAME/OPT。
  ★ 别只看 p0：**选项 op 可能把文本放在非 p0 位置**（ROOT∞REXX 的 `OPT` 是 `np=4`、文本仍在 `p0`，但 p1/p2/p3 非文本 ⇒ 逐参数试读）。
  ⇒ **开工先判「本作到底有没有 Δ」**：跨 2 个文件比对同一功能 opcode 是否相同——相同就是变体 B/D 型。

**同族指令「名字在前的字段」会随平台变 —— 别套用上一作的 payload 布局**
STCM2L 三平台实测（详见 `S4-structure.md` §6）：
PS2/Switch = `[u32 size][payload]`；**PSV = `[is_call][opcode][nparams][length]` + nparams×`[p0,p1,p2]` + data**。
字符串位置的表达也不同：PS2/Switch 在 payload 内偏移 12；PSV 是「p0 局部指针 → 指向指令内数据区`[0][L/4][1][L][text]`」。
→ **判据**：先用导出表头 `export_addr`（`EXPORT_DATA\0` 在 `export_addr−12`）把代码段走通；
若「第一条指令的 size 字段」不能整除/走不到 `export_addr`，就是指令头布局不同。

## ★ 节点流格式用「链式自校验」确立
面对 `[头][节点]…` 的记录流（节点自带总长），**枚举起始偏移**，只接受「沿 `pos += size` 一路走、**恰好落在 EOF**」的那个起始
⇒ 一次定死「节点头长 = `size − align4(len)`」＋「下节点 = `pos + size`」，胜过逐个字段猜。
实例：Koei 自研「pasc」（アンジェリーク ルトゥール，PSV）从 `0x20` 起，**1161/1161 文件全通过**。

## ★ 子文件「遍历终点」不能只信 FAT / 导出表 —— 记录流会跨文件边界（2026-10-16，STCM2L / CRI「UNI2」`L2 Love×Loop`）
同引擎同容器的第 2 样本（PANDORA 之外的 `L2 Love×Loop`，PS2 `SLPM-55191`）实测：
- **容器/子文件参数逐作变**：UNI2 子文件＝`[前缀区][STCM2L]`，**前缀区 PANDORA=`0x1800` → 本作=`0x2000`**
  （且本作前缀区只是符号/资源表，无正文）⇒ **一律先从子文件头 `find(b'STCM2L')` 实测前缀区大小**。
- ★★**FAT 的 `sizeBytes` 会截掉子文件末尾记录**（实测 id=109 末条 `です。喜ぶのはまだ早いんですか？」` 被切）。
  改用**簇对齐大小** `startCluster*0x800 + sizeClusters*0x800` 可补回一部分。
- ★★**但末条还会跨进「下一个子文件的前缀区」** ⇒ 正确终点 = **`下一个子文件起点 + 前缀区大小`**
  （按 `sizeBytes` 或簇对齐都会丢；本作差异 **约 5,000 行 / 16%**，267 个可解析文件里 **266 个**都跨界）。
  实证：id=136 末条 `#Name[1]に危害を加えるなら` 的 `」`＋续文就落在 id=137 的前缀区起始处。
- 判据（零成本）：对每个子文件算「`pos += size` 的自停位置」与「下一子文件起点」的差 —— **若普遍越界 ⇒ 记录流是连续的，
  终点必须放宽；若普遍不越界 ⇒ 可用自身边界**。**别默认「子文件＝自包含」**。
- 副作用防范：放宽终点后**每段区间只会被读一次**（f 的遍历覆盖「f 的代码 + f+1 的前缀区」，而 f+1 的遍历从 f+1 的代码起）
  ⇒ 不会重复；但仍要用「整行重复率」复核一次（本作长行重复均来自原作多副本，非提取产物）。
  ★ **第 3 样本（PSP，`D.C. Girl's Symphony Pocket`）补注 —— 前置区到底是什么**（2026-10-16）：
  同容器 `UNION/SCRIPT.UNI`＝UNI2、`[前置区][STCM2]`，**前置区＝`0x1800`**（同 PANDORA，≠ L2LL 的 `0x2000`）。
  ★★**前置区里放的不是「本文件的表」，而是「上一个子文件 opcode 链的溢出」**：实测 fid=100 的链终点比自身末尾多
  `0x161C` 字节，正好落进 fid=101 的前置区 `0x0000–0x10F0`；链撞上 `EXPORT_DATA` 导出表时因 `size` 非法**自然自停**。
  ⇒ L2LL 那句「本作前缀区只是符号/资源表，无正文」**只对该作成立，不是通则**。前置区同时可能是：
  **(a) 上一文件的正文续写**、**(b) 本文件的 `EXPORT_DATA`／导出表／符号表**（他作遗留串常在此，见 `pitfalls/C-deliver.md` ⑨·㉑）。
  终点规则仍为 **`下一个子文件起点 + 前置区大小`**；漏此，本作**每个子文件开头丢一段**（fid=101 丢 32 条整场）。
