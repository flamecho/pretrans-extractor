**A19. CRI CPK 抽取的两处「静默错」：TOC 偏移基址 ＋ CRILAYLA 实现变体**
同一个 CPK（PsychicEmotion6，`CPK ` @0 ＋ `@UTF` @0x10 的标准形态）也会踩：
- ① **`@UTF` TOC 里的 `FileOffset` 基址不可靠**：现成解析器（`cpk_v1.py`）算出的文件偏移可能整体
  偏 **+0x1000**（本作 STORY 104/104 皆然）⇒ 抽出来全是花屏/解压崩。
  **正解＝不信该字段，改用「ContentOffset 起 ＋ Align 对齐 ＋ TOC 条目序」顺序排布**（本作 104/104 首字节即 `CRILAYLA`）。
  自检：抽出的每件应恰好 `FileSize == 16 + csize + 0x100`（CRILAYLA 头 16B ＋ 压缩流 ＋ 0x100 字面尾）。
- ② **CRILAYLA 有实现变体，别只留一份实现**：长度编码有两档 ——
  **`scripts/cpk.py`（PyCriCodecs 系）含变量 2/3/5/8-bit 长度扩展**（可解本作）；`scripts/cpk_v1.py` 只做**定长 8-bit**，本作直接 `index out of range`。
  另外「0x100 字面块」在**输出的头部**、解码自尾向前、引用向前（`out[dp]=out[dp+off]`）。
  ⇒ 手上两套实现都要在；解不动先换实现，别急着重写/穷举。
- 通用：**CPK 头/ITOC 能解 ≠ 内容能解**；`CPK `/`@UTF` 都在也可能整体抽错。

**A20. PSARC 块表 `size==0` 的语义不唯一 → 用「条目自带 offset」自动判定（爽海バッカニアーズ! 実証）**
- 背景：Kuriimu2 系把块表 `u16 == 0` 当**未压缩整块（= 块大小，如 65536）**；另有把它当**真空块（0 字节）**的变体。
  取错 ⇒ 累计偏移漂移（本例 **393216 = 6×65536**），表现为「部分条目 zlib 报 truncated、部分乱码」，易误判成「损坏/加密」。
- 判据（一步定位，无需试错）：**每个目录条目自带 offset 字段**（`TocEntry[25:30]`）。
  候选解释各算一遍 `blockOffset[firstBlockIndex]`，取 **与条目 offset 命中最多的那种**。
  本作实测：`0→blockSize` 命中 1029/4500，`0→0` 命中 **4500/4500**（且 `dataEnd == fileSize` 精确相等）→ 后者正确。
- 另：`cmp.psarc` 的 offset 字段本身可信（与正确解释一致）；**别的 PSARC 里它可能不可信**，故只做「择优」不当唯一依据。
- 落地：`scripts/psarc_extract.py` 已内置该自动判定 ＋ 异常块容错跳过（原先遇到 truncated 会整包中断）。

**A22. 同名「同族引擎」的记录头与码位各作不同 —— ROM2/SNR 两作对照（换作必回查）**

| | 鳥籠のマリアージュ（PCSG90230） | 参千世界遊戯（PCSG01194） |
|---|---|---|
| 消息记录头 | `87 <A2><F1> **01** <C2><LEN2>` | `87 <A2><F1> **<T ∈{0x00,0x01}>** <C2><LEN2>` |
| 单字节 kana | cp932 半角假名可直接读 | **引擎自定义码表**（见 A21） |
| `@v` 语音名 | 纯 ASCII（`kan_00001.`） | **含 SJIS 假名/汉字**（`A_トモエ_014.` / `B_フェリクス_09.`） |
| 记录数 | 14,450 | 22,672 |

- **`T=0x00` 的 47 条是正文** ⇒ 只认 `T=0x01` 会**静默漏 47 行**；换作必须回查这一个字节。
- `@p`(40 70)/`@v`(40 76) 的参数统一是「**到 `.` 为止的名字**」—— 旧写法「按 ASCII 连续段截断」在 SJIS 名上会把
  语音名漏进正文（本作 798 条语音名以假名/汉字开头）。另有 `@y`(40 79)/`@|`(40 7c) 无参控制。
- 自洽判据：`A` 严格递增且 **1..N 完全连续**（本作 1..22672，0 缺失）⇒ 可当解析正确性的一票否决项。

### 串联单文件 zip 容器 ＋ UTF-8 长度前缀串（Otomate/Idea Factory 自研，PSV 学園K）

- **归档可能是「多个独立单文件 zip 顺序拼接」**：`DATA.PAK`＝1720 个各自带 central dir + EOCD 的 zip，
  每块按 **0x200 对齐**（EOCD 后补 0）。⇒ **`7z l` 只列出第 1 个成员**（会误判成「只有 1 个文件」）。
  判定法：数 `PK\x03\x04` / `PK\x01\x02` / `PK\x05\x06` 出现次数（本例 1719/1720/1720，差 1 因首块 `PK\x03\x04` 落在偏移 0）；
  或从 0 顺序解析：`local`→取 `csz` →`central`(46+nl+el+cl)→`EOCD`(22+clen)→**上取整到 0x200** 继续。
- 内层 `DAT ` 归档：`[u32 count]` ＋ count×`(name[0x20] + u32 size + u32 offset)` ＋ 数据区。
  **字段序＝size 在前、offset 在后**（用「末条 size+off==文件长」或「offset 处魔数正确」验；搞反也能自洽，必须验内容）。
- 剧本 `.SCD`（UTF-8）：字符串统一 `<u16 len> <bytes>`，**记录自带长度⇒天然自定界**（不必宽度感知）。
  旁白 `fe ff 00 XX 02 00 2d 31 02 00 25 26`；会话 `0f 00 00 00 <len> char_id(ASCII "ddd_ddd_ddd") <len> 名札 <len> 正文`
  ⇒ **`char_id` 之后紧跟的短串＝名札**（名札自举挖掘的确定形态）。`len` **可能含尾 NUL** ⇒ 一律 `rstrip('\0')`。
- **选项不需猜**：`61 00 14 00 <u32 scene_id> <u32 idx>` → 独立表 `CHOICE.BIN`
  （`[u32 n]`＋n×`[u32 size][u32 scene_id][u32 idx][u32 n_opts][s32 -1][pad]`＋选项串 4B 对齐）。
  **`scene_id` ＝棋盘文件名去前导零**（100980 ↔ `0100980.SCD`）⇒ 可与 SCD 精确对齐、按位内联，不必按顺序猜。
- 行内记号：`\`=框内软换行（合并）、`$…$`=用語辞典词条标记（去 `$`）、`%`=主角姓 / `&`=名 / `%&`=全名。
- 用語辞典 `DICT.BIN`：`[u32 n]`＋n×`[u32 size][u32 idx][u32 ?][u32 title_len][title][u32 n_lines][n_lines×(u32 len+utf8)]`；
  **正文按固定行槽（36/40 B）切分**，拼接前逐槽 rstrip NUL ⇒ `【見出し語】解説文`。

**A23. 同目录「定长表」字节序可能不同 —— 用「引用集合双向零差」自校验（MARGINAL#4 実証，2026-10-11）**
- 同目录三个选项表：`dbXlsSelect`＝**小端** u32×8/行；`dbXlsIPSelect`/`dbXlsSkitterSelect`＝**大端**
  ⇒ **别按扩展名/目录推字节序**，逐文件验（把候选偏移解成 cp932 看是否成串）。
- 字符串偏移硬判据＝**「NUL 起点」**（`d[base+v-1]==0`）：仅靠「能解出可读串」会收进**指到串中间**的值（本作哨兵 199/200）。
- 自校验＝**「脚本引用键集合 ⇔ 表内键集合 双向零差」**（本作 `0x599`→108、`0x7e9`→108 均零差）；
  ⚠ 表的**首组键可能藏在文件头**（偏移 0）⇒ 按脚本首键补回。

**A24. 自研 `.lzs`（大小前缀 ＋ Okumura LZSS 字节互换变种）—— 明治活劇 ハイカラ流星組（NS, 2026-10-15）**
- 形式：`[u32 解凍後サイズ]` ＋ LZSS 流。フラグ 1B／8 トークン、**LSB-first**、**bit=1 → リテラル**；
  マッチ 2B `[b0][b1]`：`len = (b1 & 0x0F) + 3`、`off = b0 | ((b1 & 0xF0) << 4)`；
  環 4096、**`r0 = N − F = 0xFEE`**、ソース＝`ring[(off + k) & 0xFFF]`（**絶対位置**）、初期値 0。
- ★ **同定手順（枚举しない）**：① 120 本の小ファイルで「長さぴったり＋全消費」⇒ 6 組が生存（＝**判別力なし**）

  ④ 通読確認。**小ファイルだけで決めない。**
- ⚠ 「距離 = off − 1」に見えたら **r0 を取り違えている**サイン（絶対索引 ↔ 距離の読み替え）。
  `dist`（`src = r − off`）実装は本変種では**誤り**。
- ★ **同作は NX32 ＝ 32-bit ARM（AArch32）ビルド**（開発パス `<開発機>/...
  **Switch を ARM64 と決め打たない**：判据＝`stp x29,x30`(`fd 7b bf a9`) が 0 件・A32 `stmdb sp!`(`…2d e9`) が存在。
  `hactool --exefsdir` の `main` は**そのまま解凍済み**（NSO 段 LZ4 は hactool 側で処理）。
- ⚠ **`hactool -t nsp` が `Invalid NCA header! Are keys correct?` で落ちる場合** ⇒ `-t pfs0` で NCA を

★ **CRILAYLA 的 Python 实现不等价，换作须自证**（2026-10-17 ガーネット・クレイドル PSP）：
  本仓库两份实现在同一 CPK 上**一份直接越界**——`cpk_v1.py` 假设长度恒为「13 bit 偏移 + 8 bit 计数」，
  而 CRI 真实格式有 **2/3/8/13 bit 多级长度**（`plen==3 → +3 bit → ==10 → +5 bit → ==41 → 逐字节 255` 扩展），
  `cpk.py` 版（来自 tpu / PyCriCodecs）才正确。**不要因为「上次能解」就默认换作也能解**；
  自证判据＝**解出内容必须命中已知魔数/已知明文**（本作＝`STCM2 File Make By Minku 07.0`），
  否则先换实现再怀疑数据。
