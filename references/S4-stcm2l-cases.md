# STCM2L / CPK-UNI2 · 实战案例

> 本册专收**个案**：两套指令体系、变体并入、名札 8 种 kind、第二个断框点。
> 形态与判型方法在 `S4-stcm2l.md`。

## ★★★ 同 romfs 混有**两套指令体系**：只收 `dbEntryScript.gbin` 登记的那套（2026-10-27 SympathyKiss）

**症状**：同一场景在成品里出现两遍（一份带 `「」`+全角空格排版、一份无引号）；某行「台词 + 地の文」被合成一句；
`＃＃＃` 名字掩码残留。

**根因**：移植/改版时把**两套完整脚本**都打进了 romfs，只有一套被游戏加载。

| | **A 组（在用）** | **B 组（旧稿）** |
|---|---|---|
| 正文 op | `0x54B4C` | `0x16FF0`（**单一正文 op，无地の文 op**） |
| 地の文 op | `0x17160` | 无 |
| 收框 | `0x54E5C` / `0x1F4` | `0x52E30` |
| 名札 | `0x54568`（`吉岡 緑郎` 带空格） | `0x527F0`（`吉岡緑郎` 无空格） |
| `dbEntryScript.gbin` | ✅ 登记 | ❌ 未登记 |
| 与同组 `X01` 重复 | 0–2% | 35–49% |
| `＃＃＃` 掩码 | 0 | 145（全部） |

**判据（两条，互相独立，都要写进报告）**
1. **外部表**：`SYSTEM.cpk → DATABASE/dbEntryScript.gbin` = 游戏自己的脚本入口表（本作 86 条，含 `SCRIPT/init/*`）；**未登记 ⇒ 不加载**。
   读法：`grep -o '/SCRIPT/[A-Za-z0-9_]*\.DAT'` 即得清单。
2. **自证（op 体系）**：文件里出现「另一套正文 op」且**缺本套独有的地の文 op** ⇒ 旧稿。不依赖外部表，可离线判。

**收尾纪律**：
- 剔除前必须做**覆盖性检查**（B 组每行去掉掩码/空白后与本套全集比对）：本例 87% 逐字相同、93% 前 8 字命中 ⇒ 不丢剧情。
- 剔除后在报告里写明「B 组行数 / 命中率 / 剩余独有行性质」，否则下次会被当成漏提。
- 备份命名 `*.preDropBset`。

**别踩的坑**：
- ❌ 把 B 组的 op 编号当「A 组的同义变体」并列收（原报告就写成「A 组 `0x54E5C` + B 组 `0x52E30`」⇒ 两套都进了成品）。
- ❌ 用「行内引号数/字数」判 B 组那行该不该拆——B 组本来就**没有独立地の文 op**，拆与不拆都是治标，正解是整份不收。
- ⚠ `＃＃＃`（全角井号）是名字掩码，本作**只在未使用的 B 组**出现；若在 A 组出现，按 `S7-charset-ledger.md` 入台账。

#### ★ 同规则补踩一次：2015 变体（`0x146b0`/`0x14dac`）也适用 —— 别只靠 `」「` 形态探针（2026-10-27 ラディアンテイル）

**症状**：`「へえ、そんなやつがいるのか！　都会ってすげえんだな！」（ウールー便もないような田舎って　一体どこなんだろう……？）`
—— 台词与心声被并成一行。**这是上面 KLAP!! 那条规则的漏用**，不是新问题。

源结构（`100.DAT` op@7301）：

```
0x14dac NAME  ヴィリオ
0x146b0 BODY  「へえ、そんなやつがいるのか！
0x146b0 BODY  　都会ってすげえんだな！」
0x8d1c        switch（分支，不断句）
0x14dac NAME  #Name[1]              ← 第二个名札 = 新消息 = 新点击
0x146b0 BODY  （ウールー便もないような田舎って
0x146b0 BODY  　一体どこなんだろう……？）
0x1f4  WAIT                        ← 整段只这一个
```

**统计**（95 个 DAT）：`0x1f4` 周期 89,430；其中 **632 个含 ≥2 组「名札+正文」，632/632 组内容互不相同**（不是双版）。
组内排版行数 1/2/3 行占 99.8%（4–6 行 104、12 行 93＝6×2 双版）⇒ **窗口一次 ≤3 行**，两组不可能同屏。

**为什么当时没修**：2026-10-26 那一轮用的是**形态探针**「句中 `」「`」⇒ 只拆到 472 个（台词接台词），
**台词接心声 `」（`、旁白接台词 全漏**（本次补拆 159：`地の文+台词` 102／`地の文+心声` 24／`台词+心声` 21／`心声+台词` 11／三组 1）。

★ 教训两条：
1. **同一引擎族的判据要回灌到每个提取器**（KLAP!! 的规则写在册里，2015 变体的脚本却没实现）；
2. **形态探针只能补漏、不能当判据** —— 结构判据（`NAME` 之间 / `0x1f4`）一次就能全中，探针永远漏一类。

**第二轮（同日，用户又指一处）**：`「う、うん！　ザフォラの説得でばっちりだったよ……？」顔の火照りを…`
—— 这一处**没有第二个 NAME**，台词与地の文之间夹的是 `0x8d1c switch` + `0x0 end`（正是上面 KLAP!! 记过的「夹 switch ⇒ 分行」）。
于是最终判据收敛成一句：

> **一行 ＝ 一段「连续 BODY 记录」**：两条正文记录之间夹了任何非 BODY 的 op（`0x14dac` 名札／`0x8d1c` switch／`0x14bd4` 清名／`0x1f4` 收框）就是新消息；只有**紧邻**的 BODY 记录才是同句折行。

实测把资源类 op（`0x41554` 立绘 / `0x1f624`）也并进 SEPS **行数不变**（它们从不夹在两条正文之间）。

| 轮次 | 判据 | 补拆 | 行数 |
|---|---|---:|---|
| 1 | NAME | 159 | 33,139 → 33,299 |
| 2 | ＋ switch/清名 | 182 | 33,299 → **33,482** |

**落地**：`scripts/radian_extract.py`（`SEPS = {0x14dac, 0x8d1c, 0x14bd4, 0x1f4}` 断行；双版折半改按 `clean` 后比较）
＋ `scripts/radian_split.py`（对旧成品按 `SEPS` 重建段落、唯一匹配才拆；跑拆前备份 ⇒ 与交付版 0 差异）。

0x17260 BODY  'そういう仕事だったし、'
0x17260 BODY  'そうすることが当たり前の立場だったから。'

★ **同一个坑在 STCM2L 三个变体上各踩一遍**（本体 2015 / FD 2018 / KLAP!! 2026-10-26）。
根源是「每个变体都新写一份 flush()，只抄了 `0x1f4`」。**新变体一律照抄这句话**：

> 一行 ＝ 一段「连续 BODY 记录」；两条正文之间夹任何非 BODY 的 op（名札 / switch / 清名 / 收框）就断行。

### ★★★ 文本组 op 会把「多变体」并排塞进一个槽 ⇒ 一句重复 2–4 遍（2026-10-27 終遠のヴィルシュ -ErroRsalvation-）

**现象**：成品里同一句台词/旁白整条重复两遍甚至四遍（本作 50 处），
`私たち一般人が住む【庶民区】の治安を守る、自警団のリーダーを務めてくれている。` × 2，
换一处是 × 4（最长行一度 78→156 宽）。

**源形（`101.DAT` 5169，op `0x4738C`，argc=14）**：

```
slot 0,1 = None            ← 资源 ID
slot 2..13 = 4 个变体 × 3 段（12 段全连续，**段间没有 None 分隔**）
  '私たち一般人が住む' / '#Color[8]【#Ruby[庶民区,クーネ]】#Color[0]の治安を守る、' / '#Color[8]自警団のリーダー#Color[0]を務めてくれている。'
  '私たち一般人が住む' / '#Color[8]【#Ruby[庶民区,クーネ]】#Color[0]の治安を守る、' / '自警団のリーダーを務めてくれている。'
  '私たち一般人が住む' / '【#Ruby[庶民区,クーネ]】の治安を守る、' / '#Color[8]自警団のリーダー#Color[0]を務めてくれている。'
  '私たち一般人が住む' / '【#Ruby[庶民区,クーネ]】の治安を守る、' / '自警団のリーダーを務めてくれている。'
```

四个变体**只差 `#Color[8]` 的包裹位置**（术语高亮 on/off 的组合），clean 后完全等价。

**为什么旧逻辑会拼全**：常见的取法是「按 `None`/非文本切 run，取第一段连续正文」（＝ `#NAME` 版 vs 明文版那种形状是对的）。
但这条 op **变体之间没有分隔符** ⇒ 12 段落在同一个 run 里，全被拼进一个框。

**正解（周期判据，别靠固定长度切）**：

```python
def _min_period(t):          # t = 该 run 的串列表
    n, cl = len(t), [clean(x) for x in t]
    for P in range(1, n // 2 + 1):
        if n % P or n // P < 2:
            continue
        if all(cl[i] == cl[i % P] for i in range(n)) and any(t[i] != t[i % P] for i in range(n)):
            return P          # ← 原串层面必须「有差异」（确有 #Color 差），才算变体
    return 0                  # 0 ＝ 不截断
```

两个条件缺一不可：

| 条件 | 作用 |
|---|---|
| `clean` 后整串 = 周期 P 重复 | 找出「同一段文字被排了几遍」 |
| **原串层面存在差异**（`t[i] != t[i % P]`） | 区分「多变体」（有 `#Color` 差）与「真·正文重复」（完全相同的原串） |

⚠ 少了第二条就会把**作者故意重复**的正文吃掉：本作 `501.DAT` 4157 原串就是 `かわいそう。かわいそう。`（同一 slot 内两遍），
`■■■。■■■。…` 也是同串重复 8 次（剧情遮蔽）——这两类必须照源保留。

**判据来源（怎么发现）**：成品行内「前半 == 后半」自检（`len%2==0 and s[:n//2]==s[n//2:]`）→ 50 命中；
再回源看那个 op 的完整 slot 列表（含 `None` 位置），才看出是 4 变体并排而不是 4 次独立正文。

**同一家族还有别的排法**（都别写死）：`#NAME` 版／明文版是「`None` 分隔两 run」⇒ 取 `runs[0]` 就对；
而多变体是「无分隔、周期重复」⇒ 要周期判据。**先 dump 一次完整 slot 再看形状，不要凭上一作的记忆取段。**

### ★★★ 名札 kind 在同一作里就有 8 种，且每种都与别的用途混用（2026-10-27 終遠のヴィルシュ -EpiClycoris-）

**症状**：`「それじゃあ、ここに向かうのはどうでしょう……？」（それじゃあ次は、どこへ向かおう？）「――ああ。その二人なら、今でもよく覚えていますよ」`
三句（台词／心声／台词）并成一行 69 字 —— 而三句之间**明明各有一条名札记录**。

**根因**：`extract_file` 只用固定的 kind 集合认名札（`{0x123,0x125,0x12b}`），而本作名札 kind 有 **8 种**，
且同一 kind 里混着完全不同的东西：

| kind | 名札样本 | 同 kind 的非名札串 |
|---|---|---|
| `0x120` | `アドルフ` `#NAME[1]` | `\x04`（控制码） |
| `0x121` | `？？？` `国民Ａ` `シアン・ブロフィワーズ` | — |
| `0x123` | `イヴ` `#NAME[1]` | — |
| `0x124` | `笏木環` `？？？` | — |
| `0x125` | `？？？` `近所の女` | — |
| `0x126` | `イヴ・シアン` | `sure2`…`sure9`（跳转标签） |
| `0x12b` | `サロメ` `#NAME[1]` | — |
| `0x12d` | `教会の管理者` `#NAME[1]` | `05u_nml_a`（**语音资源名**）、`another`、`end06_02`、`sure2`、`P` |

**正确判据＝kind 白名单 × 形态过滤**（缺一不可）：

```python
NAMEK = {0x120, 0x121, 0x123, 0x124, 0x125, 0x126, 0x12b, 0x12d}
NOT_NAME_KIND = {0x122}                      # 'ＣＥＲＯ用' 分级审查标记（全角，形态过滤挡不住）
RE_LABEL = re.compile(r'^(?:sure\d+|IF_\w*)$')
RE_ASCII = re.compile(r'^[0-9A-Za-z_]+$')     # 语音资源名 05u_nml_a / another / end06_02 / P

def is_name(kind, s):
    if kind in NOT_NAME_KIND or kind not in NAMEK or not s or len(s) <= 1:
        return False
    if RE_LABEL.match(s) or RE_ASCII.match(s):
        return False
    return not any(ord(c) < 0x20 for c in s)
```

注意 `#NAME[1]` 含 `[`/`]` ⇒ 不算纯 ASCII，能通过过滤 ✔。
`0x122 ＣＥＲＯ用` 是**全角**字母，ASCII 规则挡不住 ⇒ 必须列 `NOT_NAME_KIND`（本作 3,862 条，误断会切碎大量正文）。

**发现方式（可复用）**：先按 `kind → 前 4 个串样本` 打一张全库直方图（本作 20 种 kind 就够看出哪些像人名），
再用「名札前一条正文是否以 `0x1F4` 收框」统计漏断处；两者交叉即得「漏了哪些 kind」。
本作从 39 处补到 **45 处**名札断框（+6 行），三句那处由 69 字一行拆成 3 行。

🔥 **通用结论**：STCM2L 的名札 kind **逐作不同、逐平台不同，且会与标签/语音名/资源名共用同一 kind**。
认名札永远要「kind 白名单 ＋ 串形态」双条件；只写 kind 集合必漏，只写形态（像人名）必误。

### ★★★ 除了 `0x1F4` 还有第二个断框点：`0x0A118`（消息结束＝清屏）（2026-10-27 同上作）

**症状**：`（でも普通にお願いしたところで、聞いてくれるとは思えないし……）ベッドに寝転んでから、じっとシアンさんの背中を見つめる。`
—— `（心声）` 与 `旁白` 并成一行。三处同型，且**中间既没有名札、也没有 `」`+`「`**，前三条判据全打不中。

**源形（`402.DAT` 1318）**：

```
0xF5 '（でも普通にお願いしたところで、'      flag=0x14010
0xF5 '　聞いてくれるとは思えないし……）'     flag=0x0A118   ← ★ 心声段末
0xF5 'ベッドに寝転んでから、'                flag=0x14010
0xF5 '　じっとシアンさんの背中を見つめる。'    flag=0x001F4
```

**怎么确认 `0x0A118` 是清屏而不是普通续行**：它在别处也出现在**名札之前**——
`1205.DAT` 406（旁白末，flag=0x0A118）→ 407（`0x123 '#NAME[1]'` 名札）。
既然它后面既可能跟正文、也可能跟名札，那它就是「**一条消息结束**」的标记（清屏），等价于换页。

**判据**：`flag ∈ {0x1F4, 0x0A118}` 都 flush。本作 63 处 `0x0A118`，
其中 15 处后面直接接正文（其余跟名札、已由名札判据拆），新增 15 处拆分**全部合理**：

| 前 | 后 |
|---|---|
| `どちらを進むべきだろう？` | `娼婦の女性が通う、富裕区に続く道を進む。` |
| `……昔。煙草を吸っていたかどうかの記憶は残っていない。` | `だが嗜好品だというのなら、少なくとも不味くはないだろう。` |
| `変死体が出た以上。詳細を知りたがっていたシアンさんにも、当然報告は行くはずだが……。` | `……情報なんて、ろくにないけど。` |

**★ 最终形态：写成「续行白名单」，不要写成「断框值黑名单」**

先补 `0x0A118` 之后仍剩 12 处并框（`0x1A9E4` 5／`0x2C7` 2／`0x15A0C` 1／`0x3B630` 2／`0x6` 2），
逐条看后继**全是另一段正文**（例：`「――……アアァッ！！！」獣にも似た咆哮。`、`……意識のない彼に、シアンさんの宣言は届かない。けれど――偶然か否か。`），
拆分都合理 ⇒ 说明这些小值同样是「消息结束」。

```python
CONT = {0x14010, 0x14030}      # 只有这两个值算「同框续行」
if flag not in CONT:           # 其余一律断框（0x1F4 / 0x0A118 / 0x1A9E4 / 0x2C7 / 0x15A0C / 0x3B630 / 0x6 …）
    flush()
```

本作最终：40,588 基线 → **40,668 行**（+80）。

**判据发现顺序（可复用）**：一条并框行 → ①先看**前一条记录的尾标记**是不是续行值 → ②再看中间有没有名札
→ ③都没有就看两边首尾字符（`」`+`「`）。
本作一路是 39 → 45 → 53 → 68 → 80 处，**四轮都是"用户再贴一句、才发现还漏一个断点"**——
这就是为什么判据要写成**白名单**：先把 `kind×flag` 直方图打出来（本作 `kind=0xF5` 的 13 个取值一眼看全），
认定「哪几个是续行」，剩下的**全部**当断点，而不是等用户逐个帮我们试出来。
