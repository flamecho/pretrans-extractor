SKILL.md §4 有精简索引；本文件是**全量与案例**。

## A. 解码层

**A1. 字符宽度**
见 `02-script-reverse.md` §1。丢 20% 文本且抽出来仍然通顺，肉眼看不出来。

**A2. 替换槽 / gaiji 不能信 cp932**
- 开发者会把未使用的 JIS 槽改画成别的字形：`＄ ￠ ￡ с` 实际是 `？ ！ 。`。
- `0x82 0x40..0x91` 可能不是全角符号，而是**假名**（与假名频次高度一致）。
- **全角符号槽（U+FFE0-U+FFE5）必须列入允许集**，否则 `！` `？` 会凭空消失。
- 判据：**凡出现非日文字符，必须按上下文复核**（疑问句尾→`？`，感叹句尾→`！`）；
  并用 §外部核对确证。

**A3. 变量表要提前锁定**
数据流解析必须先固定「已知人物名映射」，否则条件分支里的 `mov $x,$y` 会把它冲掉
（ときたま 实证：先锁定人名映射才解析字符串变量默认值）。

**A4. eboot（SELF→ELF）串表含「同发行商他作遗留串」**
已见 2 例 → 按角色/场景名核对后**整体排除**，勿混入。
另需剔：名字输入用标点/单字汉字字库、`error :` 内部日志。

**A5. PSV PFS 解密**
`zRIF` 与 dump 自带 `work.bin` 一致 **≠** 可用。以 `psvpfsparser` 的 `header signature is valid` 为准；
失败时改 `-k <work.bin[0x50:0x60] hex>`。NPS 的 zRIF 可能与 dump 不一致。

**A6. 扩展名/文件名不可信**
`.dat` 可能是图片集；一律看**魔数**判内容。

## B. 提取层（行粒度）

**B1. 续写形态必须做全集**（否则碎片行 / 长行粘连，两个方向都被退过）
コルダ 实证的 **5 种**：
1. `INS` 追加码（同框续写）
2. **名字插入块横跨一条文本记录**（记录本身就是插入块的字面量，其后间隔只剩收尾操作数；
   需跟踪「插入块是否仍开启」）
3. **间隔恰好只有 `CLOSE`**（无 msgid / 无边界码）→ 纯续写
4. **只有标点/空的记录 = 框内文本更新帧**（不另起一框）
5. **纯停顿帧**（整框都是标点/空）→ **丢弃**

★ 安全写法：**「默认新框，只在看到追加码 / INS 才合并」**。
反过来「要求必须有 INS 才算续写」会**漏合折行**（我犯过的错）；「默认合并」则会粘连标题/菜单。

**B2. 纯标点记录不要无脑断链**
否则会把 `「香穂子…` 拆成 `「`。但**整框都是标点/空** ⇒ 停顿帧，丢弃。
与 `4` 的区分：**仅当当前框尚未收句**（不以 `。！？」』）` 结尾）时才并入；已收句者单独成框并作停顿帧丢弃。

**B3. 标签/调试串要断链**（`is_label()`），否则菜单/标题会粘到正文上。

**B4. 互斥随机台词会并成一行**
无收尾标记就 `goto … textclear` 的随机台词串会被线性扫描并成一行（最长 589 字）。
→ **进入新 `*label` 且当前页未结页时 → 结页**（分支/随机台词互斥，标签即显示上下文边界）。
主剧情几乎不受影响（+54 行）。

**B5. 大字号演出把话者名写进正文流**
`setwindow3 …,0,0,…`（字号 0 = 不可见/全屏）后把 `【　椿　】` 之类的说话人名当普通文本行写进正文，
紧跟台词行且中间无点击标记 → 被并成一行 → 看起来像「说话人前缀残留」。
→ 裸名札文本行（`^【[^】]*】$`）视为说话人标签**剔除**。常规对白（99.9%）走 `name` 命令，人名不进正文流。

**B6. 页 / 点击粒度不要跟随引擎的宽窗模式**
脚本的 `*text_all*`=28×16 / `*text_all_angeltxt`=38×20 只是**显示模式**，
物理宽窗会把整段对话并成一行。**除非用户对本作另有明示**，一律「一次点击 = 一行」。

## C. 交付层（每次必查）

**C1. 主角名 / 称呼宏被当空控制码丢掉**
主角可改名 ⇒ 脚本里**必然存在**插入宏。已见：遥か3（`5d 17 00` 静默前缀 + `5b XX 00` 称呼表；
`0x16`=将臣くん…）、はかれなはーと（`f.name`/`f.family`）、ひめひび（`0x0c02`/`0x1802`）、
花宵（`FFE6`/`FFE7`）、カレイドイヴ。
→ 交付前**主角名出现性自检**（`check_text.py --name X`）。默认名从 eboot 名字输入初始值表 / Config 取。
→ 出现次数还要与被称呼的台词量**量级相符**。**若脚本内无任何改名机制 ⇒ 主角为固定名**，直接用其出现次数核对。

**C2. 选项文本整块漏掉**
被当 `[...]` 标签丢弃。→ 专门提取 `[seladd/_link/_click/_extmenu/_homepage … text="…"]`，一行一条。
⚠️ **注音正则必须限定基底语**（`[漢字'よみ]` 的基底不含 `= " '` 与空白），
否则 `[seladd text="X" target="*sel_1" cond='f.shiba==false']` 会被误当注音，
**把命令残骸当正文**输出（蝶の毒实证）。

**C3. 说话人前缀残留的 4 种形态**
1. 独立名字札行 `【秀雄】`（含原作笔误 `!【警官２】`）→ 丢弃该行
2. 行首 `【名】` + 正文 → 去掉前缀
3. 行首 `名前：` / `名前「` → 去掉前缀
4. 大字号演出写进正文流的裸名行（见 B5）

**C4. 系统 / UI 文本混进正文**
`sysscn/`・`main/`・config/help/save 类 → 不收、也不产出「系统・UI テキスト」附属文件。

**C5. 行数 / 长度异常时先查合并逻辑**
不要急着怀疑源。（コルダ 最长行 152 字 / ときたま 589 字都是合并 bug。）

## D. 流程 / 环境

**D1. 清理产物只在用户明示「清理产物」时做**；任务收尾**不要**主动清理。
**并且：用户说「清理产物」时，顺手检查 skill 是否需要修订/补充**（新踩的坑要沉淀）。

**D2. 成品「不见了」= 用户主动删/移**
→ **不复原、不报警、不当异常**。（多次误判为丢失并重建，属多余动作。）

**D3. 本工作区有并行 agent**
→ 覆盖 `scripts/` 或重跑前先看产物 mtime 与内容。

**D4. 源母本迟早会被清**
→ 报告里必须写**重跑步骤**（逐条命令 + 依赖）。

**D5. 环境**
pip 走 `-i https://pypi.org/simple`；GitHub raw 被墙走 `api.github.com`；
7-Zip `C:/Program Files/7-Zip/7z.exe`；managed python
`python`。

**D6. 派生 / 合并版本（如 `@n` 合并版）保留原文不删改**，原版另存。

**D7. 外部核对不得省略**（见 `04-verify-and-report.md`）——
「解出来读得通」≠「字对」。

**D8. 压缩包头部加密**
`.rar/.zip` 可能**带头部加密**（7z 列不出文件名）→ 密码常在同目录小 txt 里；
`otoame.com` 统一密码 `otoame`。
