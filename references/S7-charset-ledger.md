# 字符台账与改名槽（whitelist 验收）

> **一句话**：交付前把「假名/汉字/CJK 标点/全角符号」以外的**每一个字符**列成台账，逐个人工认领；
> 台账里没有的字符 ⇒ 直接判 `[E]`。**禁止用「像不像变量」的黑名单去猜**。

## 0. 为什么单独立册（`%&` 漏检事件，2026-10-26）

品检原实现有两处盲区，`%&` 同时落在两处：

```python
MACRO = re.compile(r'%[-0-9.$*]*[A-Za-z]')      # ① 要求 % 后跟拉丁字母 ⇒ %& 不匹配
if o < 0x80 or ch in ALLOWED_SYM or is_jp(ch): continue   # ② 所有 ASCII 直接跳过
```

结果：`%&`（Honey Vibes 主角全名槽）**既没被模式抓到，也没被字符检查看到**，而那条检查还只是 `[W]`。
根因：**用黑名单去猜「哪些像变量」，猜不到的就会漏，而且漏了不报警。**

## 1. whitelist 机制（`scripts/check_text.py`）

- 把 kana / 汉字 / CJK 标点 / 全角符号**以外**的每个字符记入 `inv{字符 → [行号]}`；
- 与该作基线 `解析报告/allow/<作名>.charset` 比对：**基线里没有的字符 ⇒ `[E] 未备案的非日文字符`**（带次数 + 首现行）；
- **基线缺失本身也判 `[E]`** ⇒ 不给「静默通过」的机会；
- `--init-charset` 生成基线（**必须人工核对后才允许生成**，否则等于白名单自己签自己）。

```bash
python scripts/charset_audit.py 提取结果/*.txt --sus      # 字符 → 次数 / 首现行 / 原文
python scripts/check_text.py <txt> --init-charset          # 核对后生成基线
```

## 3. 名字回填：四步取证（**不许猜**）

1. **数据层**：改名界面的输入框初值（Unity：`Data/level3` 的 `InputFamilyName` / `InputName` 的 `m_Text`；
   il2cpp：`TextData` 的 `NAMEINPUT_NAME_02`「初期名『…』に戻します」内嵌默认值；PSV/PS3：`strNameEntry.gstr`）。
2. **正文槽形态**：`%様` 219 处 vs `&様` **0** 处 ⇒ `&` 是呼び捨て的名前，`&&` 才是愛称；
   `&ちゃん` 39 次 ⇒ `&` 是名（不是姓）。
3. **同场双写对照**：同一场景「点名版 ↔ 泛称版」并排（`セシリー、クラウディアを王に…` / `セシリアちゃんを借りるぜ`）
   ⇒ 逐对确认槽位语义；同时给出「去重」依据。
4. **用户实机核对**（最终裁定）：`%`＝姓、`&`＝名、`%&`＝全名紧排 —— 这一步推翻过我的推测。

★ **名札掩码字符数 ≠ 名字长度**（Honey Vibes 教训）：`＆＆＆＆＆` 是 5 个字符，我曾据此推「天野 凪咲」（2+空格+2=5），
实际是 **`天野凪咲` 紧排 4 字**。掩码只是占位，不代表长度，也不代表有无空格。

★ **字面名 ≠ 宏注入名**：主角可改名时，正文里的字面姓氏多半是**别人的**（STORM LOVER 实例）。
改名要改**宏的填充值**，不是字面姓名。

## 4. 空槽 vs 合法符号（排除法，必须有闭合证明）

| 现象 | 判定 | 证明方式 |
|---|---|---|
| `L&L` 565 处 / `L＆L` 1 处 | 店名，**不回填** | 逐行剔除 `L&L` 后剩余 `&` = **0** |
| `「マイナス60%」` | 数值百分号 | 除该处外全文 `%` = 0 |
| `80\|000人` | 原文千位分隔笔误 | 逐行看上下文，仅 1 处 |
| `ＣМ`（西里尔 `М` U+041C） | 同形字误入 ⇒ 改全角 `Ｍ` | 3 处全为 `ＣМ`＝广告，`Ｃ` 是全角 |
| `【KANE DE BOO】` / `o(･ﾛ･)o` | 原文（厂牌/颜文字） | 保留，登记台账 |

**闭合证明的写法**：「剔除已知合法形态后，该类字符余 0」——一句话就能被复核。

## 5. ruby / 富文本剥离（成行前完成，`[E] 内联标记残留` 会抓）

| 形态 | 例 | 处置 |
|---|---|---|
| `#R(基底,よみ)` | `#R(こう,こ)後顧` | 只留**基底**（`後顧`）；若标记后紧跟汉字，直接删标记 |
| `#C(TR,0xff0000ff)` / `#C(TR,prev)` | 颜色 | **整段删除** |
| `#漢字#[よみ]` | `#舗道#[ほどう]` | 只留基底 |
| `<基底,よみ>` | `<たお,・ ・>れる` | 只留基底（基**在括号内**）；注意读音段可能是强调点 |
| `<fs 75>…</fs>` / `<color …>` | 字号/颜色 | 剥净后应拼成一句 |
| `#KW` | `「…」#KW｛名札｝「…」` | **等待点击 ⇒ 切成两行**（一次点击一行的优先级高于「行数不变」） |
| `｛名前｝` / `*/` | 名札残留 / 块注释尾 | 剥前缀；纯注释行删 |

## 6. 说话人前缀（本批口径：不显示）

- **默认不加前缀**；独立名札行 `【秀雄】` 丢弃；`名前：` 去前缀；行首 `名「…」` 去名保引号。
- **例外**：名札若印在**正文文本框内**（无 `name` 命令、无独立窗口）⇒ 按技术判定保留并接在同行；
  三层证据＝脚本参数恒 `WIN` ＋ IL 调用链不调 `SetNamePlate` ＋ 控件坐标落在框内矩形。
- 本批（27 部）用户明确「都不显示说话人」⇒ 连框内名札也剥（**只留台词**）。
- 剥离判据：行首为「纯名形态」（假名/汉字/`・`/数字，不以 助词 はがをにでとものへや 结尾、不含句读）紧跟 `「…」`；
  叙述句（`〜は「…」`、`〜。「…」`）**不动**。

## 7. 验收

```
- **字符台账**：N 种，全部认领（`解析报告/allow/<作>.charset`）
- **改名槽**：<槽> → <值>（依据：数据层 / 双写对照 / 实机核对）
- **残槽**：0（或逐条说明「原文如此」）
```
