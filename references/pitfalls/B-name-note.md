# B · 名札与备注的边界（哪些文本不该进正文流）

> 本册回答一类问题：**这段是正文、是作者备注、还是名札残留？**
> 判据是**标记**与**位置**，不是形态、不是长短。成行与断框见 `B-lines.md`；
> 名札在成品里剥还是留见 `S6-lines-names.md`，台账与回填见 `S7-charset-ledger.md`。

## 1. ★★ 「长得像备注」≠ 备注：判据是**标记**，不是形态

（2026-10-27 レッドベル「その本の挿絵で…」）

用户存疑的原话：「这后半部分有没有可能是备注」。成品一行 `「` ×1 ／ `」` ×2：

```
「うん……間違いないよ。書庫にある本にも書かれていたはず」その本の挿絵で解毒薬の瓶と似たものを見た気がするんだ」
```

回源：`Comment(A)` 与 `Comment(B)` **相邻、中间无 `Empty`、无 `@` 指令**，同属一个 `CMsg`
⇒ 它是**同一文本框的第二行**，多出来的 `」` 是作者笔误。一框一行合并后，那个 `」` 落在行中间，才显得像「备注被并进来」。

**四条判据，逐条都指向「正文」**

| 判据 | 做法 | 本例 |
|---|---|---|
| ① 框内结构 | 框里有几个「框尾」标记（`CMsg` 对象 / `@cMsg …` 内联指令）？ | 1 个 ⇒ 同框两行 |
| ② 备注必带标记 | 统计全部注记行的**开头形态**，看「非标记行」有没有先例 | 注记 7,436 条：`◇SE：`2,826／短头冒号 3,381／`@ //`1,229；以 `」` 收尾的 36 条**全是** `//選択肢…` ⇒ 零标记的行**没有**备注先例 |
| ③ 语义连锁 | 上下文有没有回指它 | `その本` 回指上一行的「書庫にある**本**」；下一框「どの本に書かれていたか思い出すから…待って」接着它 |
| ④ 平行版本 | 同一句在库里是否另有版本（草稿 v.s. 正式） | `その本の挿絵で` 全库仅 1 处 ⇒ 排除「草稿重复」 |

**★ 反向自查（很便宜，务必做）**：把「框内**非末行**就已用 `」` 收尾」的框全列出来。
本作 23,657 框里只有 **1 处**（就是它；另一处 `2人「え？/なんだって？」` 是同框双人对话，合法）
⇒ 孤立个案＝笔误；若成百上千 ⇒ 才是作者习惯，需要另立判据。

**处置**：不拆、不删标点，行中孤立 `」` 登记 [W]。要「好看」属于改原文，须用户明示。

**落地**：`scripts/redbell_dialog.py` 跑完打印候选（只报不改）：

```
框内「非末行已用 」 收尾」2 处（作者笔误；一框一行合并后行中会出现孤立 」）：
   <blob> #759 'オレアンダー・レンウィック「うん……間違いないよ。…
   <blob> #656 'ギャレット・ウェルキン「なんだって？」2人「え？/なんだって？」'
```

⚠ 这是**候选列表**，不是错误列表：同框双人/双角色台词会出现同样形态，人工扫一眼排除即可。

## 2. ★★ 长句注记：没有标记、也不是短句的作者备忘

（2026-10-27 レッドベル 第 2 例）

`is_note()` 的四条（`@ // ◆ ◇ ※ ↓` 开头／短头冒号／首 12 字含演出词／≤14 字无句末标点）
漏掉这种：

```
Comment '人型のミドルクラスヴァンパイア（アイラ）はミドル（獣）でも代用できないので立ち絵なしで進行します'
EmptyScriptLine
Comment '######・ローズ'            ← 名札
Comment '（男性を襲っているのはハイクラスね……！…）'
CMsg
```

41 字、以 `人型` 开头、`立ち絵` 出现在第 30 字 ⇒ 四条全不中，被当正文收进框，成品变成
`（アイラ）は…進行します・ローズ（…）`。

**补两条（都要求「行尾不是 」』）」——台词/心声被引号包着，天然不中）**

```python
PROD_ANY = ('立ち絵','スチル','立ち位置','カットイン','名前呼び変え','モーション','アイコン','代用')
POLITE_END = re.compile(r'(?<!ま)(します|ください|ません|ます)$')   # 敬体且无句点
```

- `PROD_ANY`：**制作用语出现在行内任意位置** ⇒ 注记。正文台词/地の文不会用到这些词（本作成品里 5 处含
  `演出/立ち位置/代用` 的行全是台词，都以 `」`/`。` 收尾，被闸门挡住）。
- `POLITE_END`：`〜にしています` `〜しておきます` `〜してください` 这类**敬体且没写句点**＝作者对着同事写备忘。
  本作台词是常体、地の文是过去常体、系统提示虽有敬体但**带 `。`** ⇒ 安全。
- `(?<!ま)` 排掉叠词 `ますます`（正文实例：`…ますます決意が固くなった`、`…ますますその想いを強めた`）。

**验证方式（必做）**：把「符合新判据的全部源行」列出来，逐条看是不是注记；再 diff 重跑前后的成品，
差异必须**只包含注记行**。本作 68 条全中注记，成品只动 1 行。

⚠ **不可跨作照搬**：这里的闸门是「台词一律 `「」`、心声一律 `（）`」。像 新テニス（正文不带引号）
那样「行尾没有 `」`」是常态，套用会把正文台词整片剔掉。移作前先在该作成品里抽样验证 10 条。

## 3. ★ 名札**永远不会进文本流**：单框出现两个名札 = 作者改稿残留

（2026-10-27 レッドベル）

成品里冒出 `「なんだって？」2人「え？/なんだって？」` —— 中间那个 `2人` 是**名札**，不该在正文里。

```
Comment 'ギャレット・ウェルキン'      ← 名札①
Comment '「なんだって？」'
EmptyScriptLine
Comment '2人'                       ← 名札②（半角）
Comment '「え？/なんだって？」'
CMsg
```

**三条硬数据（判据）**

| 检查 | 本作结果 |
|---|---|
| 单框名札数 | 23,663 框里**只有 1 框 ≥2**（其余恰好 1 个）⇒ 属改稿残留，不是常规结构 |
| 该名札是否真实存在 | `２人`（全角）作名札 38 次、`※２人` 12、`全員` 16 ⇒ 是作者惯用标签，只是这里打成半角 ⇒ **比较时要做全角/半角归一** |
| 正文里有没有名札先例 | 22,776 行里 0 行 ⇒ 名札一旦出现在行中必是漏剥 |

**做法**：`build_names(files)` 先扫全库建名札集合（短、无平假名、无标点、**下一行是引号开头**、出现 ≥2 次），
收行时若「短名 + 下一行以 `「（『` 开头 + 归一化后 ∈ 名札集合」⇒ 跳过该行（**只丢名字、不丢正文**）。
`norm_name()` 负责去 `#`/`・` 前缀与全角数字→半角。

**反向自查**：跑完打印「单框出现 ≥2 个名札 N 处」。本作 = 1（与人工一致）。
若某作几十处 ⇒ 该作「多名札框」是常态（如 NVL 同框多角色），不能照搬本条。

**处置边界**：发现这种框时，**先只剔名札、保留全部正文**（原文不删）；究竟是「改稿残留整块该删」还是
「两次点击该拆两行」，源数据（唯一案例、无第 2 例可比）判不出来，必须实机或用户确认后再动。

★★ **同引擎续作：块骨架相同但「块分类判据」可失效 ⇒ 必须按 `ops` 个数 + `ops[0]` 语义重判**（2026-10-15，ときメモGS3）
- 实例：GS1/GS2 的「块后 `0317 0402` 再跟 `0104` ⇒ 选项块」在 GS3 **只覆盖 3 选项块的 1,094/1,189**；
  2 选项块大量落在 `0007`/`0200`/`0102`/`0404`/`0108`… ⇒ 照搬会**把选项当名札+正文**，只收 ops[1]（丢选项）。
- **正解（按 `0503` 个数分类）**：

  | `0503` 个数 | 处置 |
  |---|---|
  | 0 | 丢（语音/资源骨架） |
  | **1** | 清洗后非资源 ID/数字标签/纯装饰 ⇒ **收（无说话人的旁白·结局叙述）**——GS1/GS2 式「只收 len==2」会**丢 1,346 行** |
  | ≥3 | 选项块（全收） |
  | 2 | `ops[0]` **是名札** ⇒ 名札+正文（只收 `ops[1]`）；否则 ⇒ 选项（两项全收） |
- **句子型选项必须以「名札白名单」判**：名札 = 剥样式前缀后**无 `。！？…、\n`、不以 `（`/`｛` 开头、len ≤ 9**。
  另需两条补丁（全量扫描 2-op 块得出，勿漏）：
  ① **选项对**：`ops[0]`、`ops[1]` 都像名札且 `ops[1]` **不含对话标记**（`「」（）()。！？…―～♪∋∈▼、`）
     ⇒ 选项（`鐘を鳴らす／鐘を鳴らさない`、`一緒に帰ろうと誘う／ひとりで帰る`）；
  ② **单列项**：`ops[1]` 含「、」致 ① 不触发者（`大学を受験する／やめて、就職試験を受ける`）⇒ 用 `OPTION_ONLY` 显式排除。
- ★ **采话人是占位符时其「台词」实为脚本注释**：GS3 有采话人 `ダミー`/`デバッグ`/`テスト` 的块，`ops[1]` 是
  `Q31_01_000修学旅行…`（脚本 ID ＋ 备注）⇒ **整块丢**（另可按「含 `[A-Za-z]{1,2}\d{2}_\d{2}_\d{3}`」逐行兜底）。
- ★ **同名既是采话人又是选项**：GS3 `鐘を鳴らす` 同时是注册 label 与选项文案 ⇒ 靠 `ops` 结构判，别靠名字。

★★★ **「名札 vs 选项」的最终判据：用游戏自带名表 + 词尾判断，别信控制码**（2026-10-15，ときメモ GS1〜GS4 四作同源实测）
- **`0104`（块后 `0402` 再跟 `01 04`）不是可靠的 2 选项标记**：同一批 `(1,4)` 块里既有**名札+正文**
  （GS3 25 块，全部 `ops[0]==主人公`），也有 **2 选项**（`話を聞いてもらう／やっぱり今日は帰ろう`）。
  只信它 ⇒ 名札泄漏成独立行；完全不信 ⇒ 丢选项。**结论：2-op 块一律按 `ops[0]` 判名札，不参考 `0104`。**
- **名札判据（三条件并集，任一条成立即判「名札+正文」）**：
  1. **`p0 ∈ 游戏自带名表`**（首选，非启发式）：`lang/ja/initialize.assetbundle` 的 `string_table` 里
     `AdvNameCh*`（ADV 名札表；GS4 = 8 攻略対象全列，GS3 只有 9 项）＋ `ExtraProfileCh_*` /
     `AddressBookAddress_*` **按全角空格拆出的姓与名** ＋ 固定 `主人公`。
  2. **名札形 ∧ 不以假名收尾**：`p0 = 去样式前缀(？＊！∈∋♪…)的 ops[0]`，须 无 `。！？…、\n`、非 `（`/`｛` 开头、
     `len ≤ 9`，**且末字不是假名** —— 台词/选项多以「です／ます／う／か」收尾，角色名多以汉字收尾
     （`嬉しいです`／`暇です`／`話を聞いてもらう` ⇒ 选项 ✓；`男生徒`／`大成先生` ⇒ 名札 ✓）。
  3. **非 `(1,4)` 块 ∧ 非选项对 ∧ 名札形**（沿用旧口径，GS1/GS2 已验证 5 万+ 块）。
- **选项对判据**（在条件 1 之前拦一层）：`ops[0]`、`ops[1]` **都**名札形且 `ops[1]` **不含**对话标记
  （`「」（）()。！？…―～♪∋∈▼、`＋**半角 `!?`**）⇒ 判 2 选项。⚠ 半角 `!?` 必须入标记集，否则
  `('主人公','わっ!!')` 这类台词会被误判成选项对（GS1 实测 681 个假阳性）。
- **占位采话人**：`{ダミー, デバッグ, テスト, セリフ, サンプル}` 的块，其 `ops[1]` 实为**脚本注释**
  （`Q31_01_000修学旅行…`）⇒ 整块丢；另按「含 `[A-Za-z]{1,2}\d{2}_\d{2}_\d{3}`」逐行兜底。

★★ **「选项组被『调试旗』守卫 ⇒ 整组剔除」的判据与踩坑**（2026-10-16，Takuyo gss ソラ*ユメ）
- 症状：某 `0x5c` 选项组的文案是**开发口吻**（`好感度が高い`／`ルートか？`／`〜した・してない`），
  但同一批脚本里也有正常选项 ⇒ 要能**只剔前者**、不伤后者。
- 判据（第 0 步＝先证「该旗只被读、从不被写」）：
  ① `Grep` 该旗的**写点**（赋值 op）。本例 `c808` 只在 `INIT` 里 `0x25(c808)←0`，
     **全 407 脚本无处置 1**，却出现 396 次比较 ⇒ `c808==1` 块**全是不可达死码**（开发菜单）。
  ② 条件块语义：`0x30`＋`0x36(a,flag,v)`／`0x3a` 建条件 → **`0x22(T)`＝条件为假则跳到标号 T** →
     **`0x23(T)`＝标号** ⇒ **`0x22`…`0x23` 之间＝条件为真时执行**。
     `0x5c` 落在该区间**内** ⇒ 只在「旗==1」时出现 ⇒ **剔**。
- ⚠**判据要严，踩过两轮**：
  ① 「`0x5c` 前 N 条里出现过该旗的比较」⇒ **窗口不稳**，误剔 2 个正常选项；
  ② 「找任意同标号的 `0x23`」⇒ 同标号重复时块被拉到很后面，**误剔更多**。
  **正解＝「`0x36(flag==1)` *紧邻* `0x22`」＋「`0x23` 取其后*最近*的同标号」**，再判开区间包含。
- ⚠**反例必须留**：`0x36(c808==1) → 0x18 goto *_end`（＝调试时**跳过**正常选项）⇒ 选项在块**外**，**保留**
  （实例 `AMAKYO007@0x21aa` `そんな事ない！／ちょっとびっくりしただけで……`）。

★ **选项的第二种形态：文案先写进「槽」**（同上，别只认行内串）
- 行内形：`(count,"文本,FLAG",…)` ⇒ 文本＝**最后一个 ASCII 逗号**之前。
- **槽形**：`(count,2006,4806,7006,9806,c006)` —— 文案先由 `0xfd(slot) ← "文本:FLAG"` 逐条写入
  （写前把各槽置 `''` 清空）⇒ 取 **`:` 之前**。
  ⚠**只管 `0x5c` 引用到的那些槽**（本例恒为上述 5 个）；`0xfd` 给别的槽（立绘 `d004`／名札 `2402`）写的是文件名/人名，别混。
  ⚠ 另有经 `0x10c`(sprintf) 写进槽的**调试**选项（`%sが自分で焼いた`）⇒ 被上一条剔掉。
