- 主角名分「名牌/内联宏」

## 1. 排除：这些不该进正文

### 1.1 术语表/辞典载体可能是他作遗留串 ⇒ 抽 3–5 条验证后排除。

### 1.2 ★判「该不该排除」用重复度量化，别凭文件名：菜单/extra 载体先与主线语料比「整行重复率」——
   高重复（≈100%）=「显示稿副本」⇒ 剔；**低重复（如 9/229）=独立内容**⇒ 按 SKILL.md §0「是否上屏」自判，勿一律当回想剔；
   排除项一律**留在源内可复现**（驱动脚本里一张 `EXCLUDE` 表），并留一行「想收就删表项」的提示。

### 1.3 ★引擎常按「行首标记」跳过注释行（本作 `0x5a` 文本以 `☆` 开头＝SE 制作备忘，仍占一个消息框却不上屏）
   ⇒ 见到 `☆/＊/＃/;//` 等行首符号先当「注释候选」，**别当正文收**（判据：紧邻有同类制作注记如 SE 文件名）。

### 1.4 ★★「无说话人文本框」opcode 常与系统消息共用 ⇒ 整体当系统文本排除会丢正文（2026-10-14，裏語 薄桜鬼）：
   实例 —— 序章年表行 `文久三年――京。`/`――安政五年。`/`――同年、冬。` 与系统消息
   `技「…」を覚えました！`/`〜を受領しますか？` **同为 `0x2e`**（前置一条**空名 `0x2d`(len=4 全 0)**）。
   **排查法（零成本，优于猜关键词）**：把该 opcode 的**全部唯一值一次列全**（本作 244 个）逐个过目
   ⇒ 一眼分出「叙事句」与「系统模板」。判据＝**不含系统关键词 且 以 `。` 收尾** ⇒ 收；其余按系统/UI 不收（本作命中 4 句/26 块）。
   ⚠ 反向风险同样要防：把「无说话人」一概当旁白收 ⇒ 任务/商店/技能消息会混进正文。**两个方向都要查**。

### 1.5 ★★条目型文本（用語辞典・図鑑・事典）常不在主脚本里 —— 交付前必查 CPK 全部非媒体文件（2026-10-15，裏語 薄桜鬼）：
   只出 `event.enc` 会漏掉**用語辞典**（本作＝CPK 根的 `termItem.dat`，**108 条**）。
   查法＝把 CPK 内**非媒体扩展名**（`.enc/.dat/.bin/.h/.l/.txt`）逐个统计「**≥12 连续日文串**」的条数；
   ⚠ **绝不能用单字计数** —— 图像（`town_pic_*.enc` 等）的字节巧合会解出大量**假日文**（`涛涛血血東血桁`），必然假阳性；
   判据用「**长串**」才干净（实测：单字扫出 569 个"含日文文件"，长串法只剩 51 个）。

### 1.6 ★同一 CPK 里可能混着「他作遗留数据」—— 按词频判归属，别按文件名（同上）：
   `npc_album.dat`／`book.dat`／`text/TextDataEx.bin` 的内容是「ドラッケン学園・ダンジョン・呪文・パーティー」＝**另一作品**，
   本作固有词 0 ／ 他作词 52・32・154 ⇒ **整文件排除**（与铁律 12 的 eboot 遗留串同类）。
   反面：`termItem.dat` 幕末詞 63 ／ 他作詞 0 ⇒ 本作固有，**须收**。**逐文件列出两组词频再判，不猜。**

**流程**：① 清理只在明示时做（顺带查 skill 是否需修订） ② 成品「不见了」= 用户删，
**不复原不报警** ③ 并行 agent → 覆盖前看 mtime ④ 源迟早被清 ⇒ 报告写重跑步骤。

★ **`check_text.py` 的「行首 `名前：`」判据要排除记号线族**（2026-10-14，CRAZY CHA!N）：
记录体正文 `――被験者：クラリス。１２歳。` 被误判为名札残留。修法＝前缀字符类再排除 `—―‐−─～〜`

⚠ 同时 `scripts/check_text.py` 与 skill `scripts/check_text.py` **两副本须同步**。

### 1.7 ★ 开发调试章要整章剔：判据是 `scene-set` 章节号，不是「文本像不像台词」

（2026-10-27 白と黒のアリス）

`白と黒のアリス`（NS・自研 `.qui`）原先只剔了 `ev1614/1615/1616`，成品尾部**漏进来 101 行**：

```
値はです / １足す / 最大数テスト / No.1〜No.8        ← sysvalue 数值试验
fadetype first-in表示してから消す表情切り替えとか     ← 演出试验
パーティクルテスト / ボイステスト / 好感度テスト …     ← 各种试验
```

这些**长得像正文**（有假名、有汉字、有句读），靠文本形态判不出来。唯一判据：

```
脚本头部 (scene-set 16 nn)  ⇒ scene 16 = テスト章
```

该作 `ev1616`（テストモード／章選択）是章选择菜单，`ev1602〜ev1613` 由它链下去、正常游玩不可达
⇒ **`ev1601〜ev1616` 全章剔**（空脚本 ev1601/1604/1606 一并进 SKIP）。

**做法**：`SKIP = {'ev16%02d.qui' % i for i in range(1,17)}`；报数按剔后重算「入库脚本数」（本作 101 → 86）。

**同时剔「开发注释冒充正文」**：`sub story.たぶん◯◯用パラメータ` ×12、`Album Replay.たぶん◯◯用パラメータ` ×7
是脚本里以 message 写的备忘，正则 `^(?:sub story|Album Replay)\.たぶん.+用パラメータ$` 过滤（19 行）。

**自查**：成品尾部有没有「テスト」字样的短行堆叠；有没有 `sub story.` / `Album Replay.` 开头的行。
本作 37,670 → **37,569**，重跑与成品 0 差异。

## 2. 版式与标点

### 2.1 ★★「行首孤立标点」＝ 「前文被切」的指示器（用户 2026-10-14 定，已写入 `check_text.py` [E] 行首孤立标点）：
   正常输出「一次点击＝一行」，一行**不可能**以 `、` `。` `，` `）` `」` 等**收束标点**开头。出现即说明该行**前面还有内容被吞**。
   最常见原因＝**内联插入宏落在打印命令的参数区末尾**，读取器把「宏+参数」整段当非字符字节跳过：
   实例（マスケティア）`<print-op> <params> 1D 00 <正文>` ⇒ 输出 `、私だ。` `。いいか。`，实际应为 `ダルタニアン、私だ。`
   ⇒ **修法：起点字符若紧跟名字宏（本作 `1D 00`），把该宏并入本框**（修后此类行 49→0、含名行 724→1024）。
   排查顺序：先数「行首 `、`/`。`」的条数 → 取其一 dump 前置字节 → 看是否为 `<print-op> … <name宏> <正文>` 结构。

### 2.2 名字宏：一人称宏码位逐作可变，`FFE6/FFE7` ＝姓/名
V=`FF08` / 2ndV=`FF0F`。**先插宏值再续其 run**；名札区 `FFF0…FFFF` 整段跳过；默认名取 eboot 名字表。

**改名 ⇒ 输出层 `RENAME={}`**（解码层留原字面，`S5-names-macro.md`）；⚠ **字面姓名常是他人** ⇒ 名札表比 vndb 证身份后只改**宏填充值**（`S6-lines-names.md`）；
⚠ **名札区两形态**（`FFF0<样式><NAME>`｜`FFF0<样式>＋空` `FFFF`＋`FF4D<NAME>` —— 后者漏判会把名字漏进正文）；**`FF4D`/`FF4C`＝行内关键词插入**（run 首字**恒为样式符、无条件剥 1**，即使该字是 `（`/`「`）

### 2.3 标点健全性：`。`=0 ⇒ E（或写在 `0x8140` 槽；`S7-selfcheck.md`）

## 3. 多版本 / 定长表

### 3.1 ★★「同一句并排存多版」＝引擎的台詞バリアント機構，先别当提取重复删（2026-10-14，裏語 薄桜鬼/Zerodiv；详见 `S3-archive.md` A15）：判据三条 ——
   ① 两版是**各自独立的文本指令块**（各有自己的 pos，非同一块重复扫出）；
   ② 中间夹**零长度 marker**（本作 `0x1e`，外层 `0x1c`…`0x1f`，偶夹 `0x2a`）；
   ③ 两版**各带自己的台詞ID/参数**（本作 `0x31` 连番 ID ＋人名后 `0xb6` 值也连番）⇒ 引擎登记为**两条独立台詞**。
   差异几乎都在**称呼＋表记**：A＝字面默认名（`梢`/`霧島梢`）＋漢字表記 ↔ B＝`&pcl` 宏/代名詞（彼女・あいつ・妹・あなた・君・お前）＋ひらがな表記（`来ます`↔`きます`），也有整段删名（`落ち着け、梢`↔`落ち着け`）。
   ⇒ **处置口径**：只对「主角名归一后**逐字全同**」的去重（本作 427 对/854 行）；**内容真不同的分岐必留**（本作 221 对）。
   ⚠ 别用「相邻重复行」一刀切 —— 会把真分岐和"同一句的两种写法"一起删掉。去重与否**先问用户**（SKILL.md §0 不改写原文）。

### 3.2 ★定长记录的记录长用 `len(dat) % N` 发现（同上）：`termItem.dat` = 34,776 B ÷ 322 = 108 ⇒ 记录 = 322 B
   ＝ `見出し語 32 B`（NUL 填充）＋ `読み 32 B` ＋ `解説`（以 `01 <索引1 B>` 起头、条内 `\n`）。
   索引值 ≤0x6c ⇒ 前缀恒 **2 字节**，可无条件切。**输出按规范**：`【見出し語】解説文` 一行一条、**不带读音**、
   条内换行合并、**并入成品末尾**（工具 `scripts/termdict_extract.py`，**幂等**：先删既有「【…】」区块再追加）。

## 4. 交付前的自检动作

### 4.1 ★原文缺陷（漏收尾 `」` 等）必须 `LINE_FIX` 定值补，不要「为了不改写」硬留着
（2026-10-18，あさき、ゆめみし PSP 回修）  某框正文以 `…けど。` 收尾即 NUL（源字节确证、**全库唯一、无平行副本**）⇒ 判为原作用漏收尾 `」`。
  第一次交付时按「不改写」留着 ⇒ `check_text.py` 挂 **2 项 [E]**（引号配对差 1 ＋ 行首 `「` 未闭合），
  用户拿到的就是一份「看起来有毛病」的稿子。
  **正确口径**（既有先例：アーメン・ノワール 3 处／Little Aid 3 处／月ノ光 FD 2 处）：
  * 建 `LINE_FIX = {原文: 修正后}` **定值表**（不写正则、不做批量猜），只修**已逐条证实**的原文缺陷；
  * 报告里**单列「原文缺陷 N 处」**并给行号／源偏移／判据（唯一性 + 无平行副本）；
  * 修正后重跑 `check_text.py` 至 **exit 0**。
  ⇒ 口径统一：**「不改写」约束的是「不许改写语义」，不是「不许补明显缺失的配对符号」**；
    凡补必留痕（`LINE_FIX` + 报告），不可静默修改。

### 4.2 ★交付前「名札复扫」是硬动作，`check_text.py` 抓不到泛用身份札（同上）
  `check_text.py` 的「说话人残留」只认 `【名】` 独立行／行首 `【名】`+正文／`名前：` 三种形态；
  `<名>\r\n<正文>` 型引擎里，**未登记的平面名札**（`青年「…」`）它会**全部放行**。
  ⇒ 每作交付前必跑：`^([^\s「」（）]{1,14})「` 词频复扫（见 SKILL §1 人工必做③）。
  判读：残留项里**叙述句内引用**（`彼がわたしを「姫さん」と呼ぶ…`）是正常的；
  其余（纯名字／身份＋`「`）一律是名札表漏项 ⇒ 修 `mine_plates()` 或补表后重跑。细则见 `pitfalls/B-encoding-lines.md` ⓩ5。

★ **「同一句并存两种标点变体」＝源数据侧的历史遗留映射，先证再归一**（2026-10-15，ときメモGS2 NS）：
  日文台词里出现 `∋`(U+220B)／`∈`(U+2208)（各 619/547 处），上下文全是疑问/感叹句（`えっ∋`＝「えっ？」、
  `じゃあな∈`＝「じゃあな！」）。**判据＝「归一化后同文」**：把 `∋→？`、`∈→！` 后，
  **44 组文本出现两种写法**（`（えっ∋）`／`（えっ？）`、`そうなんですか∋`／`そうなんですか？`）⇒ 实证等价。
  ⇒ 交付归一为 `？`/`！`（脚本里的**同文变体**＝零成本判据，比引外部资料可靠）。
  ⚠ 别把这类 `∋/∈` 当「未解码字符」丢弃；也别忘了 **`？`/`！` 本身在同一文本里正常存在**（＝不是整体替换）。

★ **`check_text.py`「半角假名」判据已拆分**（2026-10-16 ソラ*ユメ）：原 `[\uFF61-\uFF9F]` 连**半角标点** `｡｢｣､･`(FF61–65)
  也算 ⇒ **原文自带**的 `･`/`､` 被误判 [E]；现 **FF66–9F 才 [E]**、FF61–65 降 [W] 待人工核。★「行首 `名前：`」
  亦会误报**书信/告示**（`注意：`/`追伸：`）⇒ 人工判，别盲改。

### 4.3 ★★数据表（邮件/评论式表）成行粒度＝「字段行分离 ＋ 同件正文软换行合并」，交付前用「最长行宽」自检
（2026-10-18，アルコバレーノ! ポータブル PSP，被用户连打回两次）  该表每条串＝画面上的一行显示，形态 `＞<件名>` / `宛先：X` / `―――…` / 本文行 ×n。三种粒度：
  - ❌ **一屏＝一行**（整封 join）⇒ 出现 200~3000 宽巨行，用户：「这有点太长了吧」。
  - ❌ **一显示行＝一行**（逐串成行）⇒ 正文被拆成一堆碎句，用户：「还是有啊」。
  - ✅ **件名・`宛先：`・`送信者：` 各自成行；同一件的正文行（软换行）合并为一行**（本作 `mail_join` 1,143 次）；
    装饰分隔线 `――――…`（309 行）无文本内容 ⇒ **不收**。
