# B · 成行与断框

> **成行主册**：一次点击 = 一个文本框；框内换行一律合并，断框只认代码级判据。
> 硬门槛先过 `S6-lines-proof.md`。
>
> **按主题分五组**：断框与拼装 → 去重与折叠 → 名札、宏与注记 → 选项 → 过滤与清洗。
> 名札在成品里剥还是留见 `S6-lines-names.md`，名札与备注的边界见 `B-name-note.md`。

**速查**：

- 续写形态**全集 5 种**；安全＝「默认新框，见追加码才合并」；**框标记多形态**⇒判据写「集合」；**句中「」「（）」仅探针**；**换行vs翻页⇒引号配对＋框几何**；**选项 op 可独立、双写取组 1**；**断框须含名札/变量 op**；**另一形态＝纯「连续 `FFFF` 链」**（组内首条无样式符／单符号 run＝组分隔符／含系统项则**整链弃**；就地输出）
- 纯标点记录别无脑断链
- 标签/调试串断链
- 互斥随机台词靠新 `*label` 结页
- 大字号演出会把话者名写进正文流
- 页粒度**不要跟随**引擎宽窗模式

## 1. 断框与拼装（一次点击 = 一个文本框）

### 1.1 互斥分支＝同一点击多版本正文（`goto`/换框符只断段不断点击）

⇒ 同段取一、优先无 `#Name[`；也可能把「整段场景」重复发射 ⇒ 按「整段全同」折叠、且须在宏展开后的文本层比；守卫块成对折、仅同文才折；⚠ 守卫块也可能 0 正文 ⇒ 先量化块内文本数，为 0 不折叠（`S6-lines-options.md`）。

### 1.2 记录「框」有语义：连续同类记录＝同一文本框，由「换箱记录」分隔；逐条断行＝碎片行＋引号不配对假象；跨槽拆分/回声⇒括号探针＋滑窗去重
　★**合并类判据一律禁链式**（2026-10-18 アンジェリーク トロワ 两次返工）：① **合并过的记录不得再参与合并**，否则「并列变体表」（同一前缀配 N 条后缀、每条都以 `　` 收尾）会被串成一行 365 宽；② 残片合并**必须有闭合证据**（跨框心声＝上段 `（`>`）` **且** 下段含 `）`），只凭「上段以 `　`/`（` 收尾」会并掉两条各自成句的心声。
　★**选项块未必以单 `\n` 结尾**：双 `\n\n` 结尾也可判——「首行是完整问句/心声（以 `？…。` 收尾）＋ 选项 ≤3 条 ＋ 首行不以 `「『` 开头」（485 例实测：407 中、180 例折行叙述不中）。问句自身折行＝括号未闭合就并下一行。

### 1.3 别尽信长度/边界字段 —— 用「结构自洽」自停，并容忍跨起点记录。
　★**尾随标记的语义＝「槽 k × 标记 cmd」联合**，**同 cmd 在不同 k 下含义不同**（`cmd=1`：k=12 正文／k=24 章菜单）
  ⇒ 判据须 **k+cmd+内容** 合并；只收 `cmd∈{210,211}` 会**静默丢正文＋全部选项**（选项常另有标记230/231）（00c3㉜）
　★**名札自举的「可用字」不能限「须含假名/汉字」**：`？？？`(U+FF1F)、`ＭＣ`(全角拉丁)、`？？？・？？？`(合署) 会漏判
  ⇒ 名札并进正文(189行)；**复核**＝对成品跑 `^([^\s「」（）]{1,12})「` 词频，只剩叙述句即干净（`pitfalls/B-tags-resume.md`）

### 1.4 ★★文本框会被「换页命令」拆分 —— 别只认 `0A 00`（2026-10-14 用户指出长行后查明）。长旁白 / 选项列表是多个页，页与页之间是
   `FB FF <u16> <u32 B> <u32×B>`（B＝其后 u32 的个数）或 `FE FF <u16> <u32> <u32> <u8>`，随后才是正文。
   只认 `0A 00` ⇒ 会把整段并成一条 **超长行**（实例：マスケティア 学园说明 321 宽 → 正确拆成 9 条、最长 61），
   且**选项会被并进同一条**（`辞書のように分厚い専門書。` / `恋愛小説にします。` 本是两条选项）。
   ⇒ 终止符集合＝`{0A 00, FB FF, FE FF}`；页参数照旧由「非字符字节跳过 + 前字节∈{00,02,1F}」自然跳过。

### 1.5 ★一条正文常由多个「片段」拼接而成（内联变量把串切开）⇒ 必须按片段顺序拼接；漏拼＝丢文本＋制造
「行首 `「` 未收尾」的**引号不配对假象**（Naninovel `PrintText.parts` 实例，`S4-unity.md`）。

### 1.6 ★「NUL 结尾串扫描法」（无结构解析时的兜底）必须设两道闸门，否则指令字节会当成正文：
  ① **纯 ASCII/纯宏串一律不收** —— `26 26 00`（op `0x2626`）会被读成 `"&&"`，替换宏后输出「アキアキ」
     （カヌチ 黒翼 563 行都是这个）；兜底条件＝「纯标点/纯宏串**须含至少一个日文标点**（`…‥、。！？・`）」，
     且**单字符串永远不收**（`26 00`→`"&"`、`24 00`→`"$"`、`0x24 00 00 00` 都是 op）。
  ② **字符白名单**：平假名/片假名/汉字/`3000-303F`/全角/`2026 2015 2014`/ASCII 白名单（**`5C` 必须在白名单里**，
     漏了会把带 `\` 的正文整条丢 —— 卡努奇曾因此少 3 万串）。半角假名 `U+FF66-FF9F`、PUA、希腊字母出现即「字节错读」。
  ⇒ 名札判据配套：`名札串与正文串零间隔`，但**选项列表也零间隔** ⇒ 先扫选项块（`FD FF FF FF`+8B+N 串），
     块内不判名札；再补「≥4 字且以平假名动词/助动词尾结尾（`いくすよかてるなわねのどばらりけせめろぶぐず`）不判名札」。
  细节见 `engines/idea-factory-ydp-lsb.md` §5。

### 1.7 ★「行内宏」判定要带「链」：同族宏相邻时（`FFE6`姓 紧跟 `FFE7`名）不能只看「前一 token 是否正文命令」⇒ 否则丢名（`S6-lines-options.md`）。

## 2. 去重与折叠

### 2.1 每个文件开头的共通导入块会重复 ⇒ 去重只留一次

### 2.2 互斥双写 → 「槽位替换后相邻去重」归并（去重只比整行）；框内 `\n`≠翻点击（判据＝框语音数＋文本框数）。

### 2.3 ★互斥分支去重判据别写成「行号差 2」（普通相邻行也常差 2）⇒ 写「紧邻上一条是 `@else`/`@elseif`
且**（行内标记清理后的）文本全同**」；⚠ 同文但**说话人不同**者是真两句，**不可去重**（`S4-unity.md`）。

### 2.4 ★★别默认折叠：先量化双写块数，为 0 ⇒ 禁用折叠（折叠误删行、并使引号计数失衡当作探针）（`S6-lines-options.md`）。

### 2.5 ★★同一「记录槽位（scene＋lineNo）」可能挂多条同类记录 ⇒ 引擎逐条执行、文本框「后写覆盖」，生效的是 `param` 最大者
（判据＝引擎 SQL 出现 `WHERE sceneId=? AND lineNo=? ORDER BY type,param`；旁证＝找一处「空记录＋正文记录同槽」且游戏能正常显示）。
成因＝**作者改稿时编辑器追加新记录而非覆盖**（Aromarie ATL 的 FD：135 组「旧録音 `X…` vs 改稿 `Y…`」并存）。
不处理 ⇒ **成片相邻重复行**＋混入改稿前旧文。⚠ 改完须对上一作 `cmp` 回归（`S6-typing.md`）。

## 3. 名札、宏与注记

### 3.1 无名表时话者名用「脚本内自举挖掘」：短行＋下一非表现类行以 `「/『/（` 开头 ⇒ 名札，收敛后丢整行

### 3.2 ★★同作可并存「两种插入宏形态」——`%s`+槽位 之外，还有「文本宏」写死在字符串里（2026-10-15，カエル畑DEつかまえて☆彡）：
本作主角名有两种写法：① `0xfc` 的 `%s` ＋其后 type6 槽位（875/343/303 次，主流）；
　② **`0xf0`（章节/场景标题卡）里的文本宏 `@GameLast`**（仅 2 处）。差异成因＝
**`0xf0` 只有「一个字符串操作数」、没有槽位可替换** ⇒ 作者在标题里改用文本宏。
- 实例：`COM013@0x10` `おはようございます、@GameLastです` ／ `MATO003@0x10` `@GameLast愛護週間で優先です`。
- **还原（零猜测，两条独立判据）**：① 标题**紧接着的正文**就是本人报名 `「菅野です」`；
  ② 标题与全篇 5 处同义句 `菅野愛護週間` 对照 ⇒ **`@GameLast` ＝ 姓 slot `1802`**。
- **通用做法**：交付前对**全部文本 op 串**做一次 **ASCII 扫描**（本作除 `%s` / `\n` / `\c` / 选项 flag 的 `,`
  之外，ASCII 只有 `@`×2）——**任何非预期 ASCII 都要逐条看**：`@标识符`、`{标识符}`、`<标识符>`、
  `%` 非 printf 者、残留 `\x` 码，都是「未还原的宏/占位符」。
- ⚠ **别只扫正文 op**：宏可能只出现在**标题/选项/特效**这类**没有槽位操作数**的 op 里（本作就是 `0xf0`）。
- 机器化：`check_text.py` 已加 **[E] 未解析插入宏/占位符**（旧判据把 `o<0x80` 全跳过＝盲区，见 `S7-selfcheck.md` §1）。
  反向自测法＝**把该处改回宏再跑品检，退出码须为 1**（本作实测 1／修正后 0）。

★ **同引擎续作：数据表「字段名」与「字段类型」逐作可变 ⇒ 写 walker 前先 dump 一层 JSON**（2026-10-15，ときメモGS1）
- 实例：GS2 的スキンシップ台词键＝`Params[].DlgText`（**列表**），GS1 同位置＝`Params[].DialogueText`（**字符串**）。
  照抄「`for dt in par[key]`」⇒ 对 **str 按字符迭代**，静默产出 **56,748 行单字垃圾**（`…`/`あ`/`い`…），
  行数暴增 12 倍且 `check_text` 只报「相邻重复行」，**不会报错**。
- **正解**：`v = par.get(key); v = [v] if isinstance(v, str) else v; if not isinstance(v, list): continue`
  ⇒ 即**同时取两作键名 + str/list 双兼容**。**判据（跑之前就能发现）**：先 `json.loads` 打一层 Records→Params 看类型。
- ★ 推论（与 §「同族续作」同源）：「同引擎」只保证**容器头 + 块骨架**，**业务数据表的 schema 逐作独立**；
  换作时**表名/键名/类型三者都要重新 dump**，别沿用上一作的 walker 字段名。

★ **「在每个脚本文件里逐字相同的大字符串表」＝编译期注入的全局元数据 ⇒ 剔，别当正文收**（2026-10-16，STCM2L ニルアド）
- 症状：某个 `KIND` 的表在同一作**每个脚本文件里都出现一份、且内容逐字节相同**（本作 `k=2 KIND=0x4C0`：
  本体 169 文件 × **131 项**、FD 188 文件 × **115 项**，全等）；条目形如**场景/章节名**（`序章`・`帝都心中`・`黒百合の聖女`）。
- 三条判据（齐了就拍板，不必猜用途）：
  ① **逐文件全等**（不是「相似」）⇒ 编译期注入的全局常量，不是剧情；
  ② **全库从不作为正文/选项出现**（跑一遍「该表的每条串在 `0x4BA`/选项里出现过几次」⇒ **0 次**）；
  ③ 条目数＝**按标题分的总数**（本体 131 / FD 115 各成一表 ⇒ 与「画廊/回想条目数」量级相符）。
- 处置：**剔**（SKILL.md §0「不收回想/画廊载体」），在报告里写明**用途判断＋一键导出命令**（用户若要可自取）。
  ⚠ 别因为它「看起来像章节名」就当**扉文/章题卡**收 —— 真章题卡会**在流程里被显示**（另有正文/特效记录），不会只活在这张表里。

### 3.3 ★★ 同一标签名有多支语义：`<wait key="true">` vs `<wait time="1000">`

（2026-10-27 もし神様）

该作 DSL 里 `<wait …>` 出现 8,916 次，一开始整类当「演出指令」跳过，结果 **642 次点击被并进上一行**：

```lisp
それは私の中でのシュリくんの認識が
大きく変わった瞬間でもあった。
<wait key="true">        ← 等待按键＝一次点击（旧判据忽略了它）
今までだって頼もしい人だとは思って
いたけれど……。
<wait key="true">        ← 又一次点击
　                        ← 空行写在点击「之前」⇒ 只有文字留在屏上才有意义
強さみたいなものを感じたのは
これが第一次のことだったと思う。
<pb>                     ← 换页（清屏）
```

| 形态 | 数量 | 语义 | 处理 |
|---|---:|---|---|
| `<wait time="500/1000/1500…">` | 8,274 | 演出停顿（多跟在 `<se>` 后） | 不动 |
| `<wait key="true">`（含 `key = "true"` 带空格写法） | 642 | **等待按键** | **段边界** |

**两级结构**：`<pb>`（换页清屏）＝页；`<wait key>`（框内等按键）＝段。
⇒ 一页 ≥2 段就是**双版对照**（段行…＋合并行），别再当单版。

**判「清不清屏」的可用证据**
1. 点击**之前**有单独的空行（`　`/空行）—— 若点击清屏，这行空行会被丢掉，作者不会写；
2. 页内正文行数（本例中位 4–5、最多 10）与整屏 NVL 容量吻合；
3. 同级还有 `<clear target="all|object">`，那是**画面/立绘**清屏，不是文本框 —— 别混。

**同批连带**：选项常有两个容器 —— `<select>`（普通）与 `<moshikami>`（本作「神様選択肢」），
都靠 `<case value="…">` 载文本；`<selectitem>` 是**另一个**标签（跳过块），
用 `startswith('<select')` 会把它一起吃掉；`value="…"` 还有 `value = "…"` 带空格写法。本作补齐 **396 条**选项。

★规则：**看到一个标签名先枚举它的全部属性组合**（`grep -o '<wait[^>]*>'` 去重计数），
再决定哪一支是边界；「标签名相同 ⇒ 语义相同」是最常见的漏判来源。

### 3.4 ★ 注记行里的资源 id 会漏进正文：`c04p0`

（2026-10-27 レッドベル）

Naninovel 类脚本的注释行（`CommentScriptLine`）里混着作者写的演出指令，正文提取按「`@` 开头整条丢」处理。
但**资源 id 会挂在正文注释的行尾**：

```
Comment '「あるよ。'
Comment 'ヴァンパイアの始祖は人間に『死』が訪れたことを理解するとc04p0'   ← 行尾挂 id
Comment '寂しさに耐えられず…行きたくなったんだ」'
```

`c04p0` 来自 `@cCharaAdd c04p01_a,C,C,N`（角色 04 / 姿态 01），全库同类 179 处
（`c03p0`×34 / `c02p0`×32 / `c01p0`×12 …），**只有这一处贴在正文行尾** ⇒ 只漏 1 行。

**判据**：`[a-z]\d{2}[a-z]\d+` 这种「小写字母+两位数字+小写字母+数字」的组合在日文正文里不可能自然出现 ⇒ 剥。
剥完句子要**接回去**（`…理解すると` + `寂しさに…`），不要留空格或断行。
**自查**：成品里跑 `[a-z]\d{2}[a-z]\d` 应 0 命中；>0 就说明某条注记行的 id 尾巴没剥。

### 3.5 ★★ 「作者注记」在源里常与正文同框：两种结构 + `is_note()` 判据

（2026-10-27 レッドベル）

用户看到 `ここから私服立ち絵宿に戻ると、…` / `時間経過そんなことがあったというのに——` 这类行，
指出「这显然不是屏幕上显示的文本」。源里注记与正文有两种贴合方式：

```
（A）注记＝独立注释，与正文之间隔一个 EmptyScriptLine
Comment 'ここから私服立ち絵'      ← 注记
EmptyScriptLine                   ← 分隔
Comment '宿に戻ると、まずは着替えを済ませてから'
Comment 'ベッドに腰かけて足首の状態を確かめた。'
CMsg

（B）注记与正文**粘在同一条注释**里（没有分隔符）
Comment '「今は」をカットするとシナリオがつながります今は私の背後に部屋の入口がある。…'
```

**关键动作**：回溯遇 `EmptyScriptLine` 时**先看外侧那条是注记还是正文**：
- 像注记 ⇒ 停（注记不进正文）；
- 像正文 ⇒ 只是被空行切开的**同一框两段**，继续收（否则会把 `『別の世界』での記憶を辿りながら…辿り着いた` 这类正文切掉半句）。

`is_note(s)` 判据（本作实测 0 误伤）：
```
　① 以 @ // # ◆ ◇ ■ ● ＝ ※ ↓ ↑ ← → ・ 开头
　② 短头+冒号（`演技：…` / `話者名：…` / `立ち絵IN：…`）
　③ 前 12 字含  立ち絵 非表示 暗転 時間経過 場面転換 回想 カット 選択肢 汎用
              名前呼び変え 演出 フェード 画面 立ち位置 モヤ スチル
　④ ≤14 字且无句末标点（。！？…」』））⇒ 名簿/指示
```

（B）型按句式剥，实测命中这些：`ここから…立ち絵` / `「…」をカットすると…ます` / `「…」もカットしたほうが…思います` /
`「…」とありますが…、、、` / `引用ここまで（…）` / `EV02_0001から引用` / `↓…カット` / `前セリフの名前呼び変え` / 行尾 `※修正前「旧稿」`。
⚠ 正则要**紧贴句尾**（`…ます` / `、、、`），用 `[^。]{0,40}` 兜会把后面的正文一起吃掉（本作吃过一次：`今は私の背後に部屋の入口がある。` 全灭）。

**验收**：注记型行 0、**行首孤立标点 0**、行数不因清理而减少（除纯注记框）。

## 4. 选项

## 5. 过滤与清洗

### 5.1 ㊸ ★「资源名表」可整体滤除「公共前导块」，勿按文件删（2026-10-16，同上）。
  本作**每一个脚本开头都有一段逐字节相同的公共前导块**（`色変化判定`×4／`1sho`〜`7sho`／`1day`〜`3day`／`makuai`／`wipe_*`／`suma`…），
  且 **85 个脚本（`3400`–`3484`）只有该前导块、零台词**。若按「文件里没有台词就整文件删」，会连带删掉所有剧本的同一段；
  ⇒ 正解＝**在行层用资源名规则滤除**（ASCII/PUA/已知符号表/`wipe_*`/`bg*`/`oboe*`/`Nsho`/`Nday`…），文件层只按「有无独立内容」取舍。

### 5.2 ㊹ ★样式标签须「先剥再 strip 空白」（2026-10-16，同上）。
  记录形如 `#Pos[0,23]#Scale[1.4]　　 「嘘だ嘘だ嘘だッ！」`。若先 `strip()` 再剥标签，行首会残留 `　　 `（成品 3 行）；
  正解＝**对每条记录先 `clean()`（剥 `#Color/#Scale/#Pos` 等）再 `strip()`**，然后按槽拼接。
  ⇒ 与「行首孤立标点」同源：**清洗顺序错了，判据会以为源数据脏**。
