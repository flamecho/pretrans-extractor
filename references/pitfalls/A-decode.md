# A · 解码层坑（全）

> 按主题分六组：**先判要不要解密** → 编码与码表 → 变量与元数据 → 容器与归档 → 脚本结构 → Unity 特例。
> 下面五条速查是最高频的入口，命中就跳到对应组。

**速查**：

- 主循环**字符宽度感知**（否则静默丢 20% 文本）
- 替换槽不能信 cp932；**PUA 槽＝大号标点/记号**、**单字节 kana 码位亦可改写**⇒以 **ELF code→Unicode 表**为准；**码表可分区错位**⇒低区用已知明文核
- 变量表先锁人名映射
- eboot 串表有他作遗留串，整体排除
- **PSV 两层解密**：`pkg2zip` 只解容器，再跑 `psvpfsparser` 解 PFS（**前台联网**；`zRIF`≠可用看 signature）；⚠ `files.db…`＝取密钥**被拦**（非损坏）（01/`S5-basics.md`）

## 1. 先判「要不要解密」（最便宜的三招）

### 1.1 ★「先查主数据文件是不是明文 SQLite（头 `SQLite format 3`）」——命中即零解密、零逆向：
  引擎把剧本库做成 `.db`（实例：Aromarie「ATL」的 `scene.db`）。做法＝`sqlite3` **只读**打开 ＋
  从 **exe 里静态链入的 SQL 常量**反推表义（`SELECT text FROM talkText … ORDER BY phrase` /
  `SELECT eval,text,no FROM choice … ORDER BY no` / `… FROM line … ORDER BY type,param`）。
  ⚠ 文本列多为 **CP932 字节**⇒ 必须 `conn.text_factory = lambda b: b` 后手动 decode，否则 sqlite3 直接按 UTF-8 解码**报错**；
  ⚠ `.db` ≠ 全部是文本（`*.axr` 等同目录资源仍可能是加密归档，**别连它一起啃**）（`S3-archive.md` 文末补注 ／ `S6-typing.md` A25）。

### 1.2 ★★「未压缩」不能靠"能读到明文片段"下结论 —— LZ 的字面量本身就是明文（2026-10-14，裏語 薄桜鬼）。
  条目表 `{size|0x80000000, size2, offset}` 的 **bit31 ＝ 压缩标志**、**`size2` ＝ 解压后大小**；
  旧版本据"明文可读"判「未压缩」⇒ 只拿到约 1/4 文本（旧 20 万字，实为 80 万字）。
  ⇒ **见 `size2/size` 稳定 ≈2~3 即按压缩处理**；解压器＝EBOOT 里的 `init/decode/fini` 三件套。
  本作＝ **LZO1X-1**（特征：`op-1-((t>>2)&7)-(*ip<<3)`、M4 的 `-0x4000`、first_literal_run 的 `op-0x801`、`t=ip[-2]&3`）；
  移植 `scripts/lzo1x.py`（01/`S3-archive.md`）。

### 1.3 `WSC` 全字节 `rotl_8(c,6)` —— 易误判明文

### 2.1 自建码表：用一条已知明文锚定基址；先查参考实现是否同变体

### 2.2 ★自建字符集（高码区读不通）⇒ 找「自带字形图集」

判据见 `S5-selffont.md`。★同族续作槽序逐作独立、字体可重绘、高码槽或为语义标记/绘文字（按文脉改写）；36px 辨字必错 ⇒ 台词仲裁；★★先自检「槽序 == cp932 序」是否严格单调：成立 ⇒ 当候选窗口压缩器（未定槽夹在相邻已知槽间，实例 57 槽秒级定完／零枚举零 OCR），不成立 ⇒ 仅纠错提示（`S5-selffont.md`）。

### 2.3 ★★自研「字符串池 XOR 键随池内偏移变化」（2026-10-15，ときメモGS2 NS，KONAMI Unity `.bytes`）。
  `K(off) = 0x3C ^ ((off & 0xC0) | (off & 0x03))`（off＝条目在池内起始偏移）；**同条目内 K 恒定**、跨条目变。
  ⇒ 症状＝「同一文件里有些串用 0x3C 解得出、有些要 0x3F/0xBF/0xFC…」，易误判为「每串一密/流密码」。
  **★ 且解码出的 `0x00` 须还原为 `K`**：`（`/`？`/`好`/`何` 等**中间或末位字节 0xBC/0xBD** 被编码器
  写成 `0x00`（规避 raw=0 撞分隔符）；不还原会生出 `ｈ`(EF BD 88)、`！`→`ａ` 之类假字，
  且**引号/括号计数会失衡**。定键法＝「对每条试 256 键，取唯一使结果成为合法日文者」再拟合（本作 217/218）。
  细节 `S4-unity-bytes.md`。

## 3. 变量、人名与元数据金矿

### 3.1 内联插入可能是「定长表引用」：表基址靠「空槽字面」反推（勿假定 base=0）；逐文件验字节序、偏移须 NUL 起点、键集合双向零差自校验

### 3.2 同引擎跨作 opcode 语义可变 ⇒ 换作必回查；eboot→ELF＝元数据金矿（名表/总表/码表）

### 3.3 ★★用語辞典/豆知識可能嵌在 assembly（`Assembly-CSharp.dll` 等）的 .NET `#US` 字符串堆里 —— 不是 TextAsset（2026-10-15）。
  本作 Unity 包的 StreamingAssets/resources.assets 里查不到「辞書」，`grep` 全树只有 DLL 命中 ⇒
  **去 parse PE → CLI header → metadata root → `#US` 流**（堆格式＝`[compressed len][UTF-16][1 flag]` 连续）。
  堆内记录 = **`[読み][見出し語][解説]` 三元组连续排布**（解説含 `<br>`），ID 串另置堆中。
  **锚定法（免猜、免枚举）**：拿**脚本里已有的引用**（本作 `<tips name="HM辞書NNN">見出し語</tips>`）当钥匙，
  用「見出し語」回堆里定位三元组 ⇒ HM/SM/DC **329/329**；无引用的 `Z辞書` 用「ID 紧邻三元组」回收 131/147。
  ⚠ **同一个堆里常混其它标题的遗留串**（本作另有 `辞書001–219`＝江戸/天下五剣系、`回想NNN`＝别作回想一覧）
  ⇒ **判据＝「该词在本作脚本里 0 命中」**，整体排除（对齐铁律 12）。
  ⚠ 字符串**去重**会让三元组缺项（同一 `見出し語/解説` 只出现一次）⇒ 允许 3/2/1 元组，缺项用脚本侧引用补。
  ⚠ 堆内容≠IL 可用：本作**解说串没有任何 `ldstr` 引用**（IL 疑似被保护），但**堆顺序仍可用**；
  另 `ldstr` 的 token 指向**长度前缀**（`token = 数据偏移 − 1`），按数据偏移找会 0 命中（`S3-archive.md` ／ `S4-unity.md`）。

## 4. 容器与归档

### 4.1 容器 / 归档的四个「静默错」

- 多个 zip 串联：**必须 512B 对齐**。
- 归档块单位不是常量：`max(offset) × UNIT ≈ 文件大小` → A16。
- CRI CPK 有两处静默错 → A19。
- PSARC 的 `size==0` 语义不唯一 ⇒ 取「offset 命中最多」的解 → A20（`S3-archive.md`）。

　★**子文件「遍历终点」别信 FAT / 导出表**——记录流会**跨文件边界**：`sizeBytes` 会截尾 ⇒ 先用**簇对齐**，仍不够 ⇒ 终点放宽到 **「下一子文件起点 + 前缀区大小」**（STCM2L/CRI·UNI2 实证，丢 16%；267 文件里 266 个跨界）（`S3-archive-delta.md`）

### 4.2 ★Switch XCI 内可同捆「全量替换型」更新（同 Title ID 两个 Program NCA；带 Rights ID ＋ `Patch RomFS`(BKTR)）
⇒ **先比 RomFS 文件表**；BKTR 用 `--titlekey=<tik[0x180:0x190]>` ＋ `--baseromfs=<本体 section1>` 可解（`S4-unity.md`）。
  　★**且 NCA 可整段压缩**（fs header `CompressionInfo`@+0x178 非零 ⇒ section 数据是 **LZ4 桶树**；表偏移相对 **IVFC level5 起点**，
  physical 按 0x10 对齐 ⇒ **须按 comp_size 截取**）：**四款现成工具 hactool(2020)/hactool1.4.0/nstool1.9.2/Kuriimu2 全不支持**，
  **别在工具上耗时间，直接自写**（千銃士R `scripts/senjyushi_extract.py`）（`S2-switch-nca.md` 的「全量压缩 NCA」那节）。

### 4.3 ★容器内层可能再套自定义压缩（别以为同引擎＝同链路）：Takuyo gss 的 `LSDARC V.100`，
PSV=`SCR 2.00` 未打包，**NS=`SCR 3.00`＋`LSD\x1a` 打包**（pack `H`=Huffman/`D`=16bit增量/`R`=RLE）。
★**enc 层是「就地前向差分」——「前一值」取已解密值**（用原始前值会「前 2 字节对、其余全崩」的假象）；
★**验证锚＝解出必须 `"SCR 3.00"` 开头**；参考实现 `GalgameReverse/src/gss/gss_arc.cs`（GARbro 同名文件 `UnpackD/H/W` 全空）

### 4.4 ★「大小前缀＋LZSS」类自研压缩的变体同定：别枚举参数，用「≥MB 级文件」当判别器（2026-10-15，明治活劇 ハイカラ流星組）。
  小文件（几 KB）常「**碰巧**长度吻合＋流刚好耗尽」⇒ 4KB 文件能同时通过 6 组错误变体；
  换 **2.27MB 的 `DEBUG.lzs`** 后只剩唯一解。判据＝**输出长ぴったり ＋ 输入全消费**（两条件同时）。
  ★★ **环起点 `r0 = N − F`（Okumura 传统，N=4096 则 0xFEE）必须列为候选**：r0 误取 0 时，
  「**绝对环索引**」会伪装成「**距离 = off − 1**」——**长度照样吻合，只有数%的字化け**（读得通、查不出）。
  实例：`len=(b1&0x0F)+3`／`off=b0|((b1&0xF0)<<4)`／フラグ **LSB-first・1=字面量**／`[b0][b1]` **字节互换**的 Okumura 变种。
  判定辅助：同一引擎的**大文件**（数 MB〜百 MB）能一次「全消费」＝变体对；小文件不算数（`S3-archive-family.md`）。

### 4.5 ★★`hactool --pfs0dir` 对 >1.7GB 的成员会写全零（2026-10-15，ときメモGS2 NS）。
  NSP 里的 Program NCA（4.27GB）抽出来后**从 ≈0x65DD1999（1.7GB）起整段 0**，
  于是 `-t nca` 报 **`Invalid NCA header!`**（cnmt）／**`section 0/1 is corrupted!`** —— **全是假故障**
  （源 NSP 该处非零，已逐偏移比对证实）。小文件（cnmt/tik/cert）**同样被写 0**。
  ⇒ **NCA 一律自己用 Python 按 PFS0 表逐块拷贝**（`f.read(1<<24)` 循环），再喂 hactool。
  ★ 同类：**`--titlekey` 收的是「加密」titlekey**（＝`.tik[0x180:0x190]` 原值），
  hactool 会自行用 titlekek 解并打印 `Titlekey (Encrypted)/(Decrypted) (From CLI)`；
  **传明文会再解一次 ⇒ 全错**（现象＝各候选键全试也不通）。

### 5.2 ★脚本前可能有一段「样式/字符定义表」区，且内含真命令码（`FFFF`/宏 `FFE6`…）⇒ 解析须从首个正文类命令起

### 5.3 同引擎 opcode 可能逐文件平移（Δ 常为常数倍、builtin 不动）⇒「含日文串 opcode 平均长度最大者」定 `text_op`；或不平移（B/D/E/F 型），先判有无 Δ

### 5.4 同族指令头布局随平台变（STCM2L PS2/Switch vs PSV）
★同一平台也可能连「脚本版本号」本身都换 —— Takuyo gss 同为 NS 版：`神さまと恋ゴコロ`＝`SCR 3.00`＋LSDARC 内层打包，`カエル畑DEつかまえて☆彡`＝`SCR 2.00`＋未打包 ⇒ 一律读文件头的版本串定格式，别按平台或「同厂前作」推定（2026-10-15）。

  　★**且节点「尾部签名相同、头长不同」的情况极常见**（STCM2L ニルアド：头长＝`28+12k`，`k=3` 才是选项）⇒ **扫描必须 k 泛化（k=1..6）**，否则**静默丢掉 k≥3 的整类文本**（实证选项 525／569 条全失）（2026-10-16）。

### 5.5 ★★同引擎不同作品的 opcode 表会「整体平移」—— 不可照搬上一作的编号（2026-10-14，裏語 薄桜鬼 → ～暁の調べ～）。
  实测：台词/选项/人名/无说话人文框/字库 **五者一致 +5**（`0x2f→0x34`、`0x21→0x26`、`0x2d→0x32`、`0x2e→0x33`、`0x31/0x20→0x36/0x25`）
  ＝ 枚举表前部多了 5 项。
  **判别法（不靠猜，四问定表）**：① 哪个 cmd 承载**长日文句**＝台词 ② 哪个**成组出现**（连续 2–6 个）＝选项
  ③ 哪个内容是**单字**＝字库 ④ 哪个块紧跟「名札」后＝人名。⚠ 直接用旧表 ⇒ 文本块一个都取不到（数量级掉到 1/10）。
  **同族既有坑**：`S3-archive-delta.md` A17（STCM2L 的 opcode **逐文件** Δ 平移）—— 与本条（**逐作品**整体平移）合看＝「opcode 编号一律不可当普适常量」。
  实现＝把 opcode 表做成按作品名索引的 dict（`scripts/urakata_extract.py` 的 `OPCODES`），**改表不改逻辑**；
  ⚠ 改完驱动务必对**上一作做字节级回归**（sha 一致）再交付（`S3-archive.md`/`S6-lines-cases.md` B27＋B29）。

### 5.6 选项指令 `07 <名>`/`06 <5B>` 须按表分派，勿硬跳 4B

### 5.7 ★条目尾部可能有「哈希/校验/对齐」字节 ⇒ 解析前按尾部签名切掉：症状＝末个文本 op 的 run 掺入随机字节
  → 凭空多出**含 `PUA`** 的文本/选项（Vamwolf：147 个假选项）。★**PUA＝「二进制被误读成文本」的强信号**（见 `S4-record-patterns.md`）。

### 5.8 ★Takuyo gss `SCR 2.00` 的行内 op 补遗（2026-10-16，ソラ*ユメ）：
  `0x108`＝**槽←串**（本例唯一用处＝`PRG_ROUTE` 写默认名 `皐月`；**别当文本收**）、`0x106`＝**清槽**、
  `0x10c`＝**sprintf→槽**（组装名札 `FullName`，剔）、
  `0x3a`＝**OR**（链式折叠＝「多旗任一」；判据＝`COM050` 四重 `0x3a` 折叠。据此 `COM049` 的 `d803|c808`
  在正常 play 由故事旗成立 ⇒ 其 25 行**保留**，别当 debug 一起剔）、
  `0x22`＝**条件为假则跳**（`0x23` 为标号 ⇒ `0x22..0x23` 之间＝条件为真时执行）。
  ★**`0xf0` 章题里可出现「文本宏」**：`【妄想家　@GameFirst】` 的 `@GameFirst`＝姓槽
  （同 カエル畑 `@GameLast`）—— `0xf0` 只有 1 个串操作数、**无槽操作数**，故作者改用文本宏；同类一律补 `NAME_MACROS`。
  ★**别把「版本串后紧跟的 u32」当版本后缀**：`SCR 2.00` 后的 `42 00 00 00` 是 **u32 A=0x42**，
  误读成 `SCR 2.00B` 会去找不存在的「B 版格式」。
- ★ **反过来也成立：版本串不同 ≠ 格式不同**。Takuyo `SCR 1.10`（Little Aid PSP）与 `SCR 2.00` 经**逐字节 diff**
  只差版本串本身，指令编码同构 ⇒ **不必另写解析器**（同族先 diff 再决定，别按版本号推翻重做）。

### 5.9 ★★「同捆源脚本 `.txt` ＋ 编译体」双出货 ⇒ 先验「源未过期」再决定路线（2026-10-16，新宿羅生門）。
  有些引擎把**源脚本**（SJIS 纯文本 `@命令`）与**编译体**（自研 `ASB` 等）**一起打进 RomFS** ⇒ **别默认去逆字节码**：
  先用**零成本一致性判据** ——「**编译体头部的语句数 ≈ 源脚本语句数**（±0.5%）」。实例：`.asb` 头第 3 个 `u32BE`(语句数) ↔
  `.txt` 计数逐文件吻合（`001/s00` 4871↔4861，全库 180 文件）；另证 `main`(NSO) 内含 `.asb` 字串（运行时确实读编译体）
  ⇒ 二者同源 ⇒ **以 `.txt` 为权威源**（§6.3 的另一变体）。⚠ 别把源脚本当调试残留排除；也**别因编译体里搜不到明文就以为被加密**
  （本作 `.asb` 无任何 raw 日文串）。
  ★★**同法识破「出货即占位」**：副线剧本可能整块是 `テストシナリオ`，此时**编译体尺寸同样极小**（2 KB）
  ⇒ **「源未过期」与「数据本就如此」是两件事**，须逐文件分开证伪（比计数 ＋ 采样内容），否则误判为「源过期，该逆编译体」。

## 6. Unity 系特例

### 6.1 ★Unity IL2CPP 的 bundle 无 typetree ⇒ `obj.read()` 段错误（常连 stdout 一起吞）；用
`TypeTreeGenerator(UnityPy) + load_il2cpp(exefs/main, global-metadata.dat)` 生成再 `read_typetree()`；
更新版 main/metadata 可能让 LibCpp2IL 挂 ⇒ 退回本体版本读更新 bundle（`S4-unity.md`）。

### 6.2 ★Unity(IL2CPP) 系：可改名主角的「默认名」常直接写在 AssetBundle 内的旁车表里 —— 先去找
  `Data/StreamingAssets/<ab>/data`（或 `resources.assets`）里的 **`DataGlobalValue`／`DataSystemFlag` 一类 MonoBehaviour**，
  读 `ADV・主人公デフォルトネーム`（实例：神凪ノ杜＝`ADV・主人公苗字=木南`＋`ADV・主人公デフォルトネーム=瑞希`），
  **不必反推 eboot／IL2CPP 代码**。同表常附 `名前入力` 提示文（`主人公の名前は[n]木南　<pf>で…`）⇒ **可反证宏的位置与语义**。

### 6.3 ★Unity 自研 ADV 的又一变体：AssetBundle（如 `ab_switch/script`）里装「纯文本 @命令脚本」——
  文法 `;注释` ／ `@命令 [arg=val]` ／ `*标签|`；**`@talk … @hitret` ＝ 一个文本框**（框内行**直接拼接**、一次点击＝一行）、
  **`@choice text=… file=…` ＝ 选项**。**完全不是字节码 ⇒ 先看脚本是否直接可读，别默认上 VM/码表**。
  ⚠ 解析须容忍源内笔误：闭合命令变体（`@hitre`）＋**漏写闭合**（框内遇任何 `@` 命令即**先闭合当前框**再执行该命令）。
  同 bundle 里其它 TextAsset 可能是**立绘部件 XML**（`OV001_body_a.png` 坐标表，非文本）；UI/画廊/章节表另存于 `data` bundle ⇒ 判「是否上屏」再定弃取。

**★ 源为 `.chd`（MAME **CHD v5**，压缩器 `zstd`）⇒ `S1-image-chd.md`**（2026-10-17）：无 chdman 时自写解码，
判据链＝`MComprHD`＋**头部全大端**／`hunkbytes` 可能仅 2048／map＝Huffman(**numcodes=16,maxbits=8**,码长位宽 4)
＋位流(`lengthbits/selfbits`)／Node 22.15+ `zlib.zstdDecompressSync` **须自算帧长逐帧解**（`createZstdDecompress` 不接续多帧）；
**收尾必验「整盘 SHA1 == 头部 `rawsha1`」**。

**★单字节参数 `0xA1–0xDF` 会被 cp932 解成「半角假名」正文**（2026-10-18，マイナスエイト／PSP）
症状：成品出现整行 `ｴ`／`ﾈ`（54 处），`check_text` 报 [E] 半角假名。实为「4 字节记录装一个 u8 数值」：
`[0][1][1][4] ＋ 0xC8 00 00 00` ＝ 200（音量/速度类参数）。判据：**解码字符合集 ⊆ U+FF61–FF9F ⇒ 丢**。
同族噪声：私用区单字槽；以及**字面 `\n` 的调试串**（`処理開始\n` —— `\n` 是两个字符，`strip` 不掉 ⇒ 须整串相等判）。

### 6.4 ★Unity 自研 `.bytes`（KONAMI ADV）的块语义与选项判别（2026-10-15，ときメモGS2 NS）。
  `[28B 头][4B 指令 <u8 A><u8 B><u16 BE>][字符串池]`；指令 **`05 03 <u16>`＝引用池**；
  消息块 `0316…0317`，**块后 `0402` 再跟 `01 04` ⇒ 选项块**（0503 全是选项；无说话人名），
  否则＝**名札＋正文**（第 1 个 0503＝人名，第 2 个＝正文）。
  ⚠ **两者骨架完全相同**，只能靠 `01 04` 判 —— 用「第 1 个是不是人名」判会把「要不要邀请」类选项吃掉。
