## 1. 同一框的第二段文本可能挂在**别的 opcode** 上

- 现象：`FFFF <主文>` → `FFFE <续行>` → … → **`FF8F <末段>`** → `FFFB`。
  `FF8F` 的 run 是**同一框内的另一段**（本作＝咳き込み特效 `コホッ、コホッ――」`／`クシュン」`），
  不是参数。若只认「已知的 2 个文本 op」，这些框会**静默少半句**。
- **探针＝引号配对数**：本次 `「`=26,347 / `」`=26,343（差 4），补上 `FF8F` 后降到 1（剩 1 处系源数据截断）。
  凡「正文读起来通顺但引号差几条」⇒ 先怀疑**漏了一个文本 op**，别急着当「源数据笔误」。
- 定性判据（照这个顺序，不要凭 opcode 名字猜）：
  1. 先做 **opcode × 带日文字符串** 全量统计（含长度分布），列出「除已知文本 op 外还带成句串」的 op；
  2. 逐个看上下文：**该 op 是否夹在 `FFFF` 与 `FFFB`/`FFFD` 之间**（＝同框）→ 是则并入当前框；
  3. run 若只是标点/风格符串（如 `、，／．`）或 `〔未解析〕` 连发 ⇒ 是头部噪声/参数，丢。
- 反例：本作 `FFAF`/`FFC2` 也带「串」，但全是 `、，／．` 这类标点串（头部字库网格残留）⇒ 不能收。

## 2. 选项装饰有两层，都要剥

- **a) 每个选项 run 的首码/首字形是按钮图标**：本作 `<0x20` 的标点槽（`、。，．・？！` 等）
  或 `《〕［『≠♂｛｜”‘～＜；：゜？` 这类被当图标用的标点。
- **b) 框线括号会单独成一个框**：`《` / `［` / `』` / `（` / `〕` —— 它们各自是一条「消息」，
  只剥 a 会剩一堆单字符行，`（` 计数当场不配对（本次 2 处）。
- 做法（两条都要，缺一不可）：
  1. 框首 `<0x20` 的码**全剥**；
  2. 首字形若是图标集，**剥一个**，但**剥完必须立刻是正文起首**（假名/汉字/数字/`「『（`）——
     这条护栏能防止把「…」「―」开头的正文剥掉；
  3. **纯装饰符号行**（无假名/汉字/数字，且不是 `「…」` 整体引用）整行丢；
     收括号在行首（`〕】【`）也按装饰剥（它们从不合法地开启一行）。
- 反向坑：`『` 开头既可能是**引用**也可能是**选项框**。判据＝**本行有没有配对的 `』`**：
  有 ⇒ 引用，保留；无 ⇒ 装饰，剥掉（本作 `『いいえ` 即此例）。

## 3. 「cp932 索引 < 3456 必属基础区」不能当排除判据

- 本作把 **誉・痺・麻・菓・墜・疵** 等**常用汉字**也放进自用槽（3456..3512），
  所以「语境像 X，但 X 的 cp932 索引 < 3456 ⇒ 不可能是 X」这条推理会**把真值否掉**。
- 正解两条一起用：
  1. **字形定值**（渲 16×16 / 18×18 图集，人工目视）；
  2. **反查该字的基础码是否真被正文用过**：
     `華`=736 在正文用了 **14 次** ⇒ 槽 3486 不可能是 `華`；`豆`=2564 用了 3 次 ⇒ 槽 3503 不可能是 `豆`；
     `惑`=3443 用了 59 次 ⇒ 槽 3470 不是 `惑`（实为 `矮`＝矮星）。
     反之 `眩`/`儚`/`嗜` 基础码 **0 次** ⇒ 才允许它们落到槽里。
- ⚠ 这条「基础码使用次数」反查**极便宜**（几秒），却能秒杀「语境像但码位不可能」的错读 —— 定槽前人手一份。
- 附带教训：**候选字的码位要 `ord()` 验一遍再写进表**。本次 5 个字（凛/恫/掟/羨/藉）因手写 `\uXXXX` 偏了一位，
  成品里出现 `凜/恨/揟/稈/籍` —— 全是「看起来对、其实换了个字」的类型，**抽样复读时用词频 grep 才抓到**。

## 4. NS Vridge（`script.memfs` + 纯文本脚本）：块内**空行不是分页**，但「台词+旁白同框」要单独判

（2026-10-27 ビルシャナ戦姫）

**脚本语法**：`<KW>` = 等待点击 = **唯一断点**；一条 `<KW>` ≈ 一框 = 一行。`<WinClear>` 跟在其后清框。

**踩到的形态**：

```
｛平　教経｝
「村の者にやり方を聞いて、なんとかな。
　最初は全く釣れなくて焦ったが、
　どうにか今日の夕餉には間に合ったようだ」
                                        ← 空行
慣れない釣りで成果を出せたと
得意げに笑う教経に、
私まで嬉しくなってきてしまう。<KW><WinClear>
```

`<KW>` 只有一个 ⇒ 语法上就是**一框**（台词 3 行 + 空行 + 旁白 3 行同屏）。
`''.join(块内非空行)` 的成行法会把空行吃掉 ⇒ 输出 93 字一行，「ようだ」与「慣れない」直接相接。

**判据（先问三件，别凭形态拆）**

| 检查 | 结论 |
|---|---|
| 块内有几个 `<KW>`／`#KW`？ | 只有 1 个 ⇒ 引擎层就是同一框（一次点击）|
| 作者全篇是否用空行分段？ | 本作 24,558 块里「块内纯空行分段」**仅 1 处** ⇒ 空行不是分页机制，是书写特例 |
| 相邻同类段落怎么写？ | 同场景前后都是「台词一框、旁白一框」两块 ⇒ 这处是**作者的特殊写法**，不是待修 bug |

⇒ **默认按 `<KW>` 判（不拆）**：一次点击一行，信息完整；空行丢失属可接受代价，报告里登记「本作唯一 1 处」。
若要拆成两行（台词／旁白），会偏离本作断框判据，**必须用户明示**。

**落地**：`scripts/bir_extract.py` 已内置检测 —— 统计「两条正文行之间只有空行」的块，跑完打印
`块内被空行分段 N 处（需人工确认是否同框混排）` + 样例。本作复跑输出 **1 处**，与人工核对一致。

⚠ **反例警惕**：全批「`^「…」` 后紧跟文字」有 600+ 行，绝大多数是合法内联引用
（`「あ」と思った時`／`「誰？」という顔で`／`「はい」と答えかけて`）。
**「引号后就该断行」是错的判据**——必须回到「块内几个 `<KW>`」这个结构问题上。

## 5. 「一页」≠「一屏」：novel/NVL 模式的页边界只是清屏

（2026-10-27 泡沫のユークロニア）

Unity 剧本（TIS 风格 `[命令]` 脚本）里有 `[textmode=3]`（NVL／全画面）… `[textmode=0]` 的区段，
页边界还有 `[nextpage]`。**不能把「页」当一次点击**：

```
[textmode=3]
彼の記憶の鍵になるものがないか、／しばらく高台を探してみたけど……。
（空行）
特に何も見つからず。／鳴神の他には誰も現れず仕舞いだった。
（空行）
【player】
（それもそうだよね。ここ、わたしの／　秘密の場所なんだもん）
（空行）
昨日まで、この高台で他の誰かに会ったこと／なんてなかった。
[nextpage]
```

旧实现把整页 4 块 `''.join` 成一行（117 字），台词/心声/旁白全粘在一起。

**判「页 ≠ 一屏」的三条硬数据**

| 判据 | 本例 |
|---|---|
| 页内名札会变 | novel 页 228 个，其中 **26 个页内 ≥2 个 `【…】`**（181 个 0 名札）⇒ 名字窗不可能一屏换两次 |
| 容量不符 | ADV 单框字数 中位 29 / 99 分位 56 / 最大 130；novel 页 中位 89 / 90 分位 131 / 最大 169 ⇒ 塞不进一框 |
| 书写习惯 | 每块固定 2 行、每行 19–24 字（手工折行）⇒ **一块＝一框**；`[nextpage]` 只是清屏 |

⇒ **块 = 一行**（NVL 与 ADV 统一），`[nextpage]` / `[textmode=N]` 只切页、不产生行。
影响：260 处并框拆开（+431 行），最长行 169 → 81 宽。

⚠ 别用「页字数超过屏幕高度」当唯一判据 —— 得先确认该作的窗口容量（本作用 ADV 单框字数分布反推）。

## 6. `ANYCMD = re.compile(r'\[[^\]]*\]')` 这种兜底会**吃掉正文**（同日，同作，75 块）

「先把所有 `[…]` 删掉、只留行首命令」是常见写法，但行内方括号里可能**装的是正文**：

| 源 | 兜底输出 | 正确 |
|---|---|---|
| `「……あんたは[扶桑'ふそう]――禁域にある…` | `「……あんたは――…`（丢词）| 保留 `扶桑` |
| `「問題の事件は今も[起'・][き'・][続'・][け'・]てるから。` | `「問題の事件は今もてるから。` | `起き続けてる` |
| `[本業に勤しむ'カラクリをいじる]。` | `。`（整行只剩句号）| `本業に勤しむ。` |
| `【柊】「[主人公]にも、助けて…」` | `「にも、助けて…`（主体没了）| 回填主角名 |

**先枚举该作行内标签的全部形态再决定**（`grep -o '\[[^]]*\]' | sed "s/'[^]]*//" | sort | uniq -c`）：

| 形态 | 处置 |
|---|---|
| `[dic no=N text=WORD'ruby]` | 取 `WORD` |
| `[汉字'读音]`／`[汉字'・]`／`[整句'整句]` | **取 `'` 之前**（＝正文） |
| `[主人公]`／`[Name]` 等名字宏 | 回填主角名；与紧邻死写版重复时**去泛称留点名** |
| 行首 `[wait …]`／`[nextpage]`／`[角色 voice=…]` | 噪声，删 |

★ **自查信号**：成品里出现「句子缺主语/缺名词，却仍然通顺」的行（`「にも、助けて…」`、`表情がる瞬間`）
＝ ruby 或宏被当命令删了。收尾时扫一遍「行内出现连续两处标点」或「助词紧贴」的形态。
