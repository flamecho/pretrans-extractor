# B · 名札剥离的边界（成行层／跨引擎通用）

> 分三组：**名札形态** → **判定实现与验收** → **选项侧**。
> 主要来自 アンジェリーク 魔恋の六騎士（Otomate STCM2L/PSP，2026-10-18）抽读退修；1.4 另见 VitaminZ、3.2 另见 マイナスエイト。
> **与引擎无关**，凡「名札独立记录 + 正文记录」的布局都适用。

## 1. 名札形态

### 1.1 后接符是 `「` `（` `『` 三选一，不是只有 `「`

- `「` 台词、`（` **心声/独白框**、`『` 引用/书信（或中文式内层引号）。
- 只写 `(?=「)` 或 `(?=「|』)` 会漏掉**全部心声框的名札**：本作 4 处 `？？？？？（恐ろしいほどの魔導の気配を…）`。
- 判据模板：`^([^\s「（『]{1,12})(?=[「（『])` —— 三个起始符一个都不能少。

### 1.2 名札槽可能「误带一个句号」

- 实例：`script/03142` unit 2265 的名札槽原文是 **`ジョヴァンニ。`**，而同档 unit 2263 同角色名札无句号
  ⇒ 原作打字顺手多了一个 `。`。全档仅 1 处（另 34 条「带句号的候选」全是叙述句，不能剥）。
- 做法：判定前先剥**一个**尾随 `。`，再判「≤12 字・无其他句读」；**不要**放宽到任意句读，
  否则 `以上、会話終了。`／`喉元の剣が鈍く光る。` 这类叙述会被当名札吃掉。

### 1.3 名札槽里的 PUA 填充

- 名札字段常以 `U+F8F3` 等私用区字符补位（`カインﾟﾟﾟﾟ`）⇒ 判定前先剥 `[\ue000-\uf8ff]`，
  再算长度 / 判句读；否则「≤12 字」永远不成立（或被算进正文）。
- 同时：`^？` 形态的占位名（`？？？？？`）也是名札，**不要**当成叙述保留。

### 1.4 地の文里写进去的说话人：整行 `名前「…」`

- 形态：不是独立名札记录，而是 **`0x44`（地の文）记录本身**以「角色名 + `「`」开头、以 `」` 收尾，
  原文常带前导 `　@n`（缩进＋软换行）。本作实例（VitaminZ PSP，演唱会合唱轮替段，block 40，共 4 处）：
  `　@n八雲「コールっ。」`／下一行 `　@n「ヤクモーッ。」`。
- 判据：**行首姓名 ∈ 名札白名单**（从本作 `0x3E` 名札表自举，297 种；**不要硬编码**）＋紧跟 `「`＋**整行以 `」` 收尾**。
  满足即删姓名、保留引号（`八雲「…」` → `「…」`）。
- **反例（不能剥）**：姓名后面不是 `「` 而是助词/系词 —— `成宮君の家は「成宮財閥」と呼ばれる…`／
  `劇の内容は「ロミオとジュリエット」…`／`真壁先生は「あの、オッサンが……！」と…`；
  以及长行（>12 字前缀）。这些都靠「姓名必须**完整等于**白名单项 + 紧随 `「` + 行尾 `」`」挡掉。
- 留开关：`--keep-prefix` 可保留原样（万一某作确实是"引用风格正文"）。

## 2. 判定实现与验收

### 2.1 ★ Python 空串陷阱：`nxt[:1] in '「（『'` 永远为真

- `'' in '「（『'` → **True**（空串是任何串的子串）。
- 后果：`[名札 or 叙述, '']` 这种「第二条是空记录」的框，空记录被当成「引号起头」⇒
  叙述首句被误判成名札后丢弃（本作实测丢 3 行：`喉元の剣が鈍く光る。`／`そんなある日。`／`そこに言葉はない。`）。
- 正确写法：`return bool(nxt) and nxt[0] in '「（『'`。

### 2.2 验收探针（成品跑完必做两条）

```bash
grep -c "^？" 成品.txt                                   # 期望 0（占位名残留）
# 行首「短词 + 引号/括号」清单：应只剩真叙述，逐条人工看
python -c "import re;[print(x[:60]) for x in open('成品.txt',encoding='utf-8-sig') if re.match(r'^[^\s「（『]{1,12}(?=[「（『])',x)]"
```
- 第二步靠**名札白名单**（从语料自举：`records[0]` 形状合规且 `records[1]` 以引号起头者）过滤，
  不要硬编码人名 —— 副角色/泛用名（`皇帝の兵`/`指揮官`/`？？？？？`）会漏。

## 3. 选项侧

### 3.1 裸名过滤**不能**套在选项上

- 选项文本常常很短且无句读（`一生懸命に帰りたいと頼む`／`はい`），会被「裸名＝短且无句读」规则删掉
  ——本作 169 条选项里因此一度丢 **93 条**。
- 正解：**先按结构标记选项 unit**（本作＝`SEL_nnn` 组标记到 `select` 之间的连续单记录 unit；
  同族另有 `xls/0` 定长表、`sel_xxx_NN` 组名等），标记过的一律放行，再走正文的裸名过滤。

### 3.2 ★选项文本可能整批不在脚本里，而在独立的「定长选择肢表」

（2026-10-18，マイナスエイト／PSP STCM2L）`xls/0`＝`96 B × 502` 定长表 `[group 16][本文 64][场景名 16]`，
group＝`sel_pro_00`/`sel_may_03`…；脚本侧只存**`select` ＋组名**两条记录（偏移 24）⇒ 提取时在该 unit **flush 后插入该组全部选项**。
★**必跑「双向零差」**：表内 162 组／502 条 ⇔ 脚本内 162 处引用（一组一引用、无孤儿组、无重复引用）——
一次比对即证「不重不漏」，比逐条抽读可靠。
⚠ 同目录的 `xls/100`（mail 件名/差出人）是 **UI 表 ⇒ 不收**；邮件正文仍在 script 内（`『…』`）——
**别把整个目录当正文收，也别因为「有 UI 表」就整目录丢弃**。
