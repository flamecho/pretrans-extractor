# 文本记录形态库（认出「记录长什么样」，就能定界）

> 面对未知字节码，**不要先猜 opcode 语义**，先认出**文本记录的形状**：形状决定定界方式，
> 定界对了，opcode 只用区分「正文 / 名札 / 选项 / 断框」四类即可。
> 每型给：**识别特征 → 定界算法 → 已见引擎 → 坑**。只需认出 2~3 个相邻记录即可确认。

## 通用判定流程（按顺序做，别跳）

1. `probe.py jp` 找**假名/汉字连续区** ⇒ 文本一定在附近；
2. 取一处文本前后各 32 B，找**重复出现的结构**（长度字段常复写两遍、样式字段常全 0）；
3. 用**一条已知明文**（界面串、标题、文件名）反推基址/键（禁穷举、禁 OCR）；
4. 认出记录形状后，**按记录长度自定界**走完全文件 ⇒ 统计「串数 / 总长 / 是否有残片」；
5. 残片率 > 1% ⇒ 形状认错或漏了变体（常见：尾部填充、对齐、尾随命令）。

## P1 · `[addr][样式*u32][0][L/4][1][L][text]`（定长头 + 双写长度）

- **识别**：文本前 12~28 B 是 `…00 00 00 00` 段；`L/4` 与 `L` **成对出现**（差 1 个字），`L` ≈ 文本字节数对齐到 4。
- **定界**：读到 `L` 字节即止；`L/4` 复写是**校验字段**，用来确认没读错起点。
- **已见**：Idea Factory **STCM2L**（PS2/PSP/PSV/NS 全平台）、部分 Otomate 自研。
- **坑**：① 头长随「样式段数」变（k=1/2/3…），**不能写死偏移**——用「`0` 字段位置 + 双写长度」定位；
  ② 正文/选项/名札靠**样式段数**区分（4 段＝正文、1 段＝名札、2 段＝选项），判据是**槽数**不是 opcode；
  ③ `exports_offset` 常**不是**代码链终点（其后仍是合法记录）。

## P2 · `<u16 len><cp932 text> 00`（长度前缀 + NUL 收尾）

- **识别**：`08 00` 之类小端 u16 紧跟日文；结尾固定 `00`；`len` 常**含**结尾 NUL。
- **定界**：读 `len` 字节，跳过尾部 `00`。
- **已见**：Koei **CDAR**、Plan Peace **PCT**、Marvelous **MZ**（`[u16 tag][u16 wc]+wc*4` 变体）、部分自研归档。
- **坑**：① `len` 有时是**字数**不是字节数（`wc*2`）；② 同文件里混用两种长度单位时，用「解出来是否全为合法 cp932」判定；
  ③ 串内可含 `0A`（软换行）——**不要当结束**。

## P3 · `<u32 len><utf8 text>`（4 字节长度前缀）

- **识别**：`xx 00 00 00` 后紧跟 UTF-8 日文（3 字节/字）。
- **已见**：Otomate **DAT+PAK+SCD**、M2 **PSB**（`Scn` 内 `texts[]`）、部分 Switch 自研。
- **坑**：① UTF-8 与 CP932 混排时，**先按 UTF-8 试解**（非法序列立即暴露）；② 长度可能含/不含 NUL，用相邻记录对齐验证。

## P4 · 4 字节对齐槽（`[data][NUL][垃圾填充至 4B]`）

- **识别**：每条串起点都在 4 的倍数上，串后常有 1~3 个**非零垃圾字节**（不是 `00`）。
- **定界**：**按对齐网格行走**，读「到 NUL 或到下一个槽起点」；不要用「连续 NUL」当界。
- **已见**：澪 **System-NNN**（`.spt`）。
- **坑**：垃圾填充会让「串首零污染」——反扫（从后往前找 NUL）会把填充当正文开头。

## P5 · `[tag][len][ASCII 标签][payload]`（标签即数据表标识）

- **识别**：记录前部是**可打印 ASCII**（如 `msg_003`、`sel_A`），长度字段 = 标签长 + 1。
- **定界**：`len == len(tag)+1` 是**可靠签名**；`tag` 字节本身任意，不能拿来做类型判据。
- **已见**：Otomate/Idea Factory 后期作品的数据表串。
- **坑**：① 一条命令后可能跟**多条串**（只取第一条会丢整段）；② 标签族（`msg_*` / `sel_*` / `sys_*`）用于区分**剧本成员 vs 系统成员**。

## P6 · 文本池 + 索引表（串在池里，表给 offset/size）

- **识别**：文件头有 **N 条 × (offset,size)** 的整齐表；表后是大段文本池。
- **定界**：按表遍历；**表的有效项数**可能小于表容量（尾部填充 `0xCD`/`0xFF`）。
- **已见**：KONAMI `.bytes`、CRI **AFS**、MAGES. AFS 文本池、部分自研。
- **坑**：① 表可能被**压缩/加密**（池则单独键）；② 顺序常由**另一张表**决定（`scenelist.json`、事件表），不是池顺序。
- **变体（池 + 代码内联指针，无表）**：HuneX「ALS」`SCENE%02d.ALS`＝头 ＋ 16 位 op 流（操作数里直接放 u32 串绝对偏移）＋ 末尾文本池，
  池起点＝代码区**最后一次**某条无操作数 op（本作 `0D 02`）之后。**池序＝流程序**（选项组精确插在对应台词后，可实证）。
  ③ ★**池的终止判据不能用「不含假名/汉字即止」**：`ＯＫ`/`ＢＢ` 一类纯全角选项会被当成非文本而**截断整池**
  （实测 215 条掉到 89 条，静默丢一半）。改用「控制字符 / 解码失败 / 池尾标记」判止。
  ④ ★**池尾有 24 B 收尾区**（1 B 标记 ＋ `00` ＋ 若干 0/小整数），会被读成 `先`/`ｸ`/`n` 之类单字串 ⇒ **只从末尾剥 1 字尾项**；
  别用「距 EOF < N 字节」的硬阈值（会连末条正文一起删，实测丢 3 条）。
  ⑤ 池内可**夹非字符串数据表**（如单字表 `空/海/土`）⇒ 也不能「遇单字即止」。

## P7 · 2 字节大端字符码串（非 cp932）

- **识别**：每 2 字节一个值，高位多在 `0x81~0x9F`/`0xE0~0xFC` 但**整串解出的日文不成词** ⇒ 是**游戏内码**，需字符表。
- **定界**：按 2 字节步进；遇到「控制码」（不在字符表的值）即断。
- **已见**：Otomate 自研 **`.evb`**（マスケティア / Confidential Money）、部分 PSP 自研。
- **坑**：① **成框必须前向扫描**（反扫会把 `(0x81,0x0A)` 当成字符，起点多吃 1 字节 ⇒ 首字变错字）；
  ② 字符表**逐作可增补**（同族不同作可能多几槽）。

## P8 · 纯文本 / 标签脚本（无二进制结构）

- **识别**：肉眼可读，含 `*label`、`@cmd`、`【名】`、`\n` 字面量。
- **定界**：按行；`@` 命令决定换框。
- **已见**：KiriKiri `.ks`、KAG3、LTEngine、Matatabi 纯文本 ADV、Aromarie ATL（SQLite 表内文本）。
- **坑**：① `@n`/`@wait` 语义**逐作不同**（有的断点击、有的只停顿）；② 注音标签（`%R`、`<词,读>`）要**留正文去读音**。

## 附：四类语义的最小判据（认完形状再分这四类）

| 类别 | 通用判据 |
|---|---|
| **正文** | 长度最长的串族；后随「断框标志」；含句末标点 |
| **名札** | 独立短串（≤12 字、无句读、后随 `「`）或专门 opcode；**输出时丢弃该行** |
| **选项** | 常在**另一张定长表**（`xls/0` 96B/条之类）或被 `select`/`eval` 引用；同一位置多条互斥 |
| **断框** | 两条正文记录之间**必现**的固定字节（12B `[0][cmd][flag]`、`_ZM`、`0x10/0x11` 节点…）；**找不到不许退回「指针连续＝同框」当结论** —— 继续攻坚定框（`S6-lines-proof.md` §3/§6）；确实只能用连续性假设时，判级 **L1** 并补一条交叉验证＋报告标「未证」 |

> 认不出形状时的兜底：**记录驱动扫描**（记录自带长度 ⇒ 自定界）＋ **引号配对**验收（`S6-lines-echo.md`）。
> 仍未收敛 ⇒ 按 `00-discipline.md` 决策纪律停手汇报，不要加码穷举。

## P9 · `[text][u16 slot_id]×n`（文本＋名变量槽；`%s` 版台词）

**识别**：文本 op 的串里含 `%s`，**串后紧跟 n 个 2 字节槽 id**（n ＝ `%s` 个数），再跟一串 `0xFFFFFFFF` 填充。
**读法**：槽 id **小端**——十六进制串 `"3002"` ＝ 槽 `0x230`，`"3c02"` ＝ 槽 `0x23c`。
⚠ 直接 `int(hex,16)` 会得到 `0x3002`（不存在的槽）⇒ **名变量静默变空**，而品检「引号/控制符」全过、**只有「主角名出现性」能抓**。
实例：Takuyo gss `0xfc`（怪盗アプリコット 726 条；`0x5a` 是无变量的同型正文）。

> ★ **分节脚本的「节序 ≠ 字节序」**：按 `[label][code]` 分节后，字节序只是编译顺序。
> 脚本被表/调度器按名调用时，**以调度脚本里 `call (script,label)` 的出现序为准**；未被调用的分支节追加在该文件末尾。
> 实例：Takuyo `ANZU00` 字节序 `KISYOU_F,G,H,I,J,A…E`，按 `ANZU.SCR` 调用序恢复为 `A→J`。

## P10 · `0xFF` 起始的定长头 op 流 ＋ **XOR 0xFF 的 SJIS 文本**（Broccoli 自研，NS うたプリ）

**识别**：整文件**大量 `0xFF`**；文本区是成对的 `0x7C–0x7F` 打头字节（看着像乱码、但坏字节全是 `0x8x–0x9x` 的高位被翻）。
**判据（30 秒锚定）**：`raw ^ 0xFF` 即 SJIS —— `7e 8a → 81 75 「`、`7e bd → 81 42 。`；
统计「`7e8a` / `7e89` 出现次数」**近似相等**（开引号＝闭引号）即可确认，**不要**去建码表。
**记录**：`ff <op> <u16 id LE> <u16 b> <u16 c> [载荷]`
- `0x0A` 头 12B（文本；样式 id `0x00CC` 续行 / `0x07DE` 段首 / `0x00D5` 主角名槽）
- `0x00` 头 4B（无样式文本）
- `0x0E` + id `0x0074`、头 16B ⇒ **选项**（组内 2–3 条，前置 `0e/0003`、后置 `0e/0072`）
- 任意 op + id `0x07DD` ⇒ **ruby 文本**：载荷 `[基底][00 00 或 ㌻][基底+正文]`，**只取后半**（不去重会出「良きライバル良きライバル」）
**成行**：`0A/0x00CC` **空载荷** ＝ 框结束（其后固定 `0x08/0x0400` wait）⇒ 一次点击一行。
`0x876E`(㌻)＝框内改行，与同框文本**合并**；`0x32A4–A6`(㊤㊥㊦)＝演出标记，剔除。
**易错**：① 载荷里的 raw `0x01` 等控制字节解码成 `<0x20`，须**跳过**否则出 `〔FE〕`；② 别把 `memorial*.dat`（回想）当正文。
实例：うたの☆プリンスさまっ♪ All Star After Secret(NS) 29,824 行；`scripts/utapri_extract.py`。

## P11 · **文本全部外置的 `*.hdlg` 表**（Unity＋HuneX HESL，NS Starry☆Sky Spring Memories）

**识别**：`script.heslnk`→`HESE` 解压后**假名数 = 0**（内联串只有 `max`/`min`/`value`）
⇒ 台词不在字节码里，找同目录 **`script_dialog_ja.hdlg`**（`en/zhcn/zhtw` 同构）。
**容器**：`HLZS@0x200`（LZSS dict 0x1000/maxlen 0x12）→ **`HDLG`**：
`HDLG + ver + count + dataOffset + u32 offsets[count]`，UTF-8 内联、NUL 结尾。
**判据**：兄弟语言表**只存键名**（`TRANS_W000_0000_0`）⇒ 直接给出「索引 ↔ 脚本块/行号」映射，
`TRANS_W###_####_#` 条数与正文区间长度**逐条相等**即可当断框自证（L1）。
**成行**：一条表项＝一框；`<br>` 合并；`<firstname>/<lastname>`＝主角名宏；`<firstname2>/<lastname2>`＝**第二可改名槽**（默认值常查不到 → 占位并注明）。
⚠ 前半段常混 **UI 区**（`TRANS_M/S/N/MEM*` 键、日期、章題、改名提示）⇒ 用键名是否为 `W###_####` 切分，别按字数猜
例：28,931 行；`scripts/sspm_extract.py`
