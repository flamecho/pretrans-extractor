# 坑 · 解码层 A14–A18（WSC / 前缀区 / 块单位 / opcode 平移）

> **一次性总览看 `pitfalls/A1-decode-core.md`**（那条索引已覆盖全部坑）；本文件只在**对应阶段**才读。
> 见 `03-archive-delta.md`。

**A14. WSC（WillPlus / AdvHD）は「全バイト rotl」されている —— 未解密でも「っぽい opcode」に見えるので明文と誤認しやすい**
- 容器 `*.arc`：`u32 extGroupCount` → 每组 `[ext 4B][count u32][tableOffset u32]`；
  条目表 `[name 13B][size u32][offset u32]`＝**21 B/条**（`Rio.arc`＝ext `WSC`；`CHIP*.arc`＝ext `ANM` 子表 MSK/PNG/TBL/WIP；
  `Bgm/Se/Voice.arc`＝ext `OGG`）。**条目长度随 ext 组而变**（ANM 主表是 24 B/条），别套用 21。
- **★ 解密＝每个字节 `rotl_8(c, 6)`**（`(c<<6 | c>>2) & 0xFF`）。
  **不解密时字节流也像结构化 opcode**（如 `0c 04 XX 0c` 反复），极易误判为「明文直读」而空手而归。
  → 判断法：拿一段**必然有 UI 文案的运行期脚本**试 `rotl_8(c,6)`；解密后才会出现能通读的 cp932 文本。
- 文本 opcode（可配 wareya/will `wsc.cpp` 的 8bit opcode 表）：`op41`＝旁白、`op42`＝**人名＋台词**、
  `op02`＝选项。**同族引擎版本间 opcode 长度会差**：本作补 `0x61`＝1 参数、`0xE6`＝2、`0x0D`＝7
  （照搬他作表会中途失步 ⇒ 用「整脚本能否走到 `0xFF` 收尾」验证表）。
- **★ 选项项＝`2B ＋ 选项\0 ＋ 3B 头(01 XX 03) ＋ 1 条目标指令`；目标指令通常 `07 <脚本名>\0`，也可能是 `06 <5B>`（间接跳转）**
  → 必须「**跳 3 字节头后按 opcode 表分派一条指令**」，**不能写死「跳 4 字节 + 读原始串」**：
  后者只对 `07` 成立（4 ＝ `01 XX 03` ＋ `07` 个 opcode 字节），遇 `06` 即失步（第 2 个选项被读成 `･`）。
  实证 Butterfly Lip `BL_10B`（`彼を選ぶ`/`一陽を選ぶ`）；修法已入 `scripts/advhd.py`，对旧 `07` 情形结果等价。
- 行粒度：串尾 `%K%P`＝一次点击；**串内换行是字面 `\n`（0x5C 0x6E）转义、不是 0x0A** → 合并；
  `%O`／`\n\n\n` 之类空演出丢弃；电话/邮件样式 `【名】\n『文』` 去 `【名】`。
- 同捆 `DKGAPPEND.iso`＝官方 `After Love パッチ`（追加 `RIO+.arc` 续篇）；`data1.cab/data2.cab`＝
  InstallShield 安装器＋MSI（**只含 VC++ 运行库，无文本**，用 `scripts/unshield/` 取得后确认）。
- **同族第二作可零改动复用**（Butterfly Rouge，`DKRDISC1.ISO` 单盘、脚本 `BR_*`）：同一 opcode 表即可让
  **全部脚本走到 `0xFF` 收尾、0 失步**——这是「表完备」最省事的验收。共用引擎已抽成 `scripts/advhd.py`，
  各作只写薄驱动（`bgloss_extract.py`/`brouge_extract.py`）。
- **原文笔误 ≠ 提取缺陷**：先用**原始字节**核对（`「」」`＝尾 `81 76 81 76` 多一个；独白缺起始 `（`）。
  确认是作者笔误后，**按作者意图修正并逐条报告**（用户口径），修正是**显式定值表**（如驱动里的 `POSTFIX`），不靠正则泛修。
- 注：**「Nameable」不必然有插入宏**。Rouge 主角 vndb 标 Nameable、`NAME.wsc` 也有 `nameset1/2` 登录菜单，
  但剧本正文与 `op42` 名札**全是固定字面名**、无任何宏 ⇒ 只需做「主角名出现性」自检，不必找宏。

**A15. 子文件「脚本 magic」之前还可能有区块 —— 只扫主代码段会整段丢正文**
许多容器里每个子文件并非「表头 + 一条脚本流」两层，而是 `[前缀区块][脚本(magic 在固定偏移)]`。
**前缀区块常另含可显示正文**（不是纯元数据）：
- PANDORA（PS2 / CRI `UNI2` + STCM2L）实证：子文件 = `[0x1800 前缀区块][STCM2L@+0x1800]`。
  ① 每章「ミッション小测（豆知識，一问＋两答）」在前缀区；② **文件 961/981 的结局场景整段就在前缀区**
  （**不在**代码段内 —— 只解析代码段会整段丢失，且这种丢失很隐蔽：正文总数只少几十行、剧情照样通顺）。
- 判定法：对每个子文件，**除主代码段外，另按同样的「文本记录签名」扫一遍 magic 之前的区块**，
  只看**非系统标签**且落在**已知场景上下文**里的记录。
- ⚠ 前缀区往往**还混着**人名初始值表 / 玩法说明 / 曲目表（系统/UI）→ 逐条按内容判收/丢，别整块收。
- 同族注意：**外层容器自身也可能带一份同格式脚本**（PANDORA 的 `SCRIPT.UNI` 自身 magic 也在 `0x1800`），
  别漏，也别把它和子文件脚本重复计。
