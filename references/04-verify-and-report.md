# 自检 / 外部核对 / 验收 / 报告

## 1. 交付前自检（必跑）

```bash
python scripts/check_text.py "提取结果/XX_全文本.txt" [其它.txt...] --name 主角名
```
（项目内另有同版 `scripts/check_text.py`。）退出码 0 = 通过。

| 级别 | 项 |
|---|---|
| **[E]** | BOM 缺失 / 出现 CR / `U+FFFD` / `〓` / 控制符(C0) |
| **[E]** | **半角假名**（U+FF61-FF9F）—— 多为「双字节字首字节损坏」的化け，不是原文 |
| **[E]** | **私用区 PUA**（U+E000-F8FF）—— 未映射的字形槽 |
| **[E]** | **引号不配对**（`「」『』（）` 数量不等 / 行首 `「` 未以 `」` 收尾） |
| **[E]** | **说话人残留**（独立 `【名】` 行 / 行首 `【名】`+正文 / 行首 `名前：`） |
| **[W]** | 主角名一次都没出现 / 空行 / 超长行 / 相邻重复行 / 非日文字符 |
| **[i]** | 行数 / 字节 / 最长与中位显示宽 |

**自动项之外还要人工做两件事**：
1. **随机抽读** 6 处不同位置（各 10 行）——读得通 ≠ 字对。
2. **外部核对**（§2）——人名逐个比 vndb。

> **检查器本身也要防误报**（收紧规则时要记录）：`行首 名前：` 这一项曾把 Norn9 的人物卡拉黑
> （`結賀駆。ジョブ：魔法使い。…`、`こはる。ジョブ：勇者。` 被当成「说话人残留」）。
> 已把 `NAME_PREFIX_COLON` 收紧为「**前缀里出现 `。、！？…` 即不判名字札**」（名字札不会带句读）。
> → 若某作真有 `名前：` 残留却因前缀带句读漏过，属已知折衷；**唯一办法是逐条人工复核该形态**。

> 历史经验：**半角假名**与**引号不配对**是最高频的两类漏检。
> 前者躲过「非法字节」扫描；后者暴露「行被吞 / 行粘连」。
>
> **例外：出处确是原作笔误时，别当提取缺陷去「猜」。**
> 先用**解密后的原始字节**单条核对（如 `「」」` 恰是尾 `81 76 81 76`＝两个 `」`；独白缺起始 `（`）。
> 确认是作者笔误后：**按作者意图修正**（用户口径），且修正必须是**显式整行定值表**
> （如驱动里的 `POSTFIX`，逐条精确匹配），**绝不写正则泛修**；并在报告里逐条列出「原串(hex) → 修正后」可回溯。
> 反面教材：为过检查而全局正则「把 `」」`→`」`」会碰坏正常重叠引号。

## 2. 外部资料核对（强制步骤）

**「解出来读得通」≠「字对」。** 替换槽 + 自定义码表决定了：语义通顺的句子里仍可能藏 1〜3 个错字。
（例：`完仆`(正:完璧)、`武居拓仭`(正:拓眞)、`赤星英佗奈`(正:英莉奈)。）

| 目标 | 首选来源 |
|---|---|
| **角色人名**（主角/攻略对象/配角） | **vndb** `https://vndb.org/v<id>/chars`；API `POST api.vndb.org/kana/character`，`filters=["search","=",...]`（该版 `vn` 过滤常报 Invalid query） |
| 作品信息（发售日/开发商/平台） | vndb 作品页、官方站 |
| **歌名 / 乐队 / 品牌 / 店名 / 术语** | 官方站、攻略 wiki、まとめブログ |
| 台词原文（疑难字） | 攻略本、实况/プレイ日記、台词集 |

做法：
1. 先产两份清单再核对：① 全部说话人姓名（去重）→ 逐个比 vndb；② 全部命中「非日文字符/罕见字」的行 → 逐条上下文比对。
2. **以外部资料为准**：vndb 写 `拓眞` 而本地解出 `拓仭` ⇒ 该码位也是替换槽 → 补进 EXC 表重跑。
3. **查不到就不猜**：保留原码，报告里单列（码 / 次数 / 原句 / 可能读法）。
4. **反向校验**：外部资料给出的字若**从未**出现在自己输出里 ⇒ 还有未发现的槽位，回去复查。
5. **教训**：「该字在别处也出现过」**不能**用来排除槽位（同一字形可同时存在于槽位与普通码；
   莉 = `0x166c` 与 `0x0da8`，眞 = `0x143e` 与 `0x0da0`）。

## 3. 验收清单

- [ ] `check_text.py` 全绿（或每条 ERROR 都有书面说明）
- [ ] **主角名出现性**自检通过（改名宏已接上默认名，出现次数量级相符）
- [ ] **选项文本**收全、一行一条、顺序与原脚本一致
- [ ] **说话人**零残留（4 种形态都查过）
- [ ] **引号配对**（`「`=`」`、`『`=`』`），行首 `「` 必有 `」`
- [ ] **半角假名 / PUA / `〓` / U+FFFD / 控制符** 全 0
- [ ] **外部核对已完成**（说话人姓名逐个比 vndb；专有名词比官方站）
- [ ] 外部资料给出的字**全部能在输出里找到**
- [ ] 随机抽读 6 处（各 10 行）
- [ ] **只含显示用文本**：日志/backlog 载体已排除；系统/UI 脚本已排除且无附属文件
- [ ] 未解析码位**单列进报告**（码 / 次数 / 例句 / 可能读法）
- [ ] 解析报告写完，含**重跑步骤**与**残留说明**

## 4. 报告与交付

报告（`提取结果/XX_解析报告.md`）建议结构：

1. **源与容器结构**（大小、文件类型统计）
2. **保护 / 压缩方案**（逆向结论；**未解明部分要写明**，别装作全解了）
3. **脚本结构**与「一次点击 = 一行」的落地规则
4. **产物清单**（文件名 / 行数 / 校验值）
5. **外部核对**（来源 URL + 结论）
6. **化け复元表**（**每条注依据**：ルビ / 同型脚本平行 / 字节数吻合 / 年代自洽…）
7. **重跑步骤**（逐条命令）
8. **未决项 / 已知非显示项**

交付走 `present_files`（成品 txt + 报告）；**不要**把中间产物当交付物。
派生/合并版本（如 `@n`）保留原文、另存新文件，不改动原版。
