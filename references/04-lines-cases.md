# 提取成行 · 各引擎实证案例（B7–B13）

> 通用规则 B1–B6、B14–B17 见该文件。
> 见 `04-lines-options.md`。

**B7. 互斥分支 = 同一次点击的「多版本正文」—— 按结构识别，别靠相似度**
同一句对白会按条件（女主是否改名 / 是否在场 / 礼貌级）编译成**相邻的 2–3 份**，仅一份会显示：

```
[cond] Mif → ELSE
  [版本 A（then）] … 0x1f4 ; goto → END     ← A 结束后 goto 跳过 B
ELSE:
  [版本 B（else）] … 0x1f4
END:
```
- **结构判据**：`goto` 断「段」不断「点击」；`0x1f4`（换框）**若下一条是 `goto`** 也只断段，否则断「点击」。
- 同一点击内的多段**取一**：**优先不含 `#Name[n]` 占位符者，其次取最长**（＝直写名版）。
  Norn9 实证：`「#Name[1]ー、七海ー、」/「こはるー、#Name[3]ー、」/「こはるー、七海ー、」` → 取第三版。
- ⚠ **只按换框断行、不识别 `goto`** ⇒ 同一句输出 2–3 份，即「**差一两个字的重复行**」（用户明确反感）。
- ⚠ **按文本相似度自动合并不可靠**：会把 `「（楽）」/「（質問）」`、`「…………」/「あ……」` 这类**真的相邻不同行**
  误判成变体。**以结构（`goto` / `0x1f4`+`goto`）为准**，相似度只作复核。
- **换框符身份要验证**（Norn9）：统计「文本 push 之后的换框符数」vs「文本 run 数」是否一一对应 —— 本作 23,742/24,364 = **97.4%**
  ⇒ 确认 `0x1f4`＝换框符。**别被总数吓退**（53,465 ≫ 24,364，多出的是「特效等待」的独立使用）。
- **「一句话被拆到多个框」是原作风格**：narration 常在 `、` 处断框（`「あの二人の食生活は…」、`／`「誰か何とかしてやれ」`／
  `と案じてもらうほどだ。` **三框各带一个 `0x1f4`**）；同框多行则是**连续 push、只在末尾一个 `0x1f4`**。
  ⇒ **判据＝同框多行中间不夹换框符**；**不要**为「读起来是一句」跨框合并（会粘住台词与旁白）。

**B8. 每个文件开头的「共通导入块」会逐文件重复 —— 去重后只留一次**
连锁章节脚本（Norn9 的 88 个 `SCRIPT/*.DAT`）**各自开头重复同一段导入**（`プロローグに新たな…`＋4 行世界观），
逐文件计会重复 88 次；个别文件（5001–5010）**全文就只剩这段共通块**。
- 判据：取「被 ≥8 个文件作为开头重复的最长行块」，**只保留一次置于全文最前**，其余文件头部删去该块。
- 别把它当正文重复上报，也别整块丢弃（它是玩家可见的导入旁白）。

**B9. 框标记（「一次点击」边界）可能有多形态 —— 判据要取「形态集合」，别取单一取值**

SNOW BOUND LAND（STCM2L PSP 版）实证：框标记是 12 字节 opcode `[u32 a][u32 b][u32 c]`，
**`a==0` 与 `a==1` 两种形态都是框边界**：

| a | 形态 | b 的量级 | 占比 |
|---|---|---|---|
| 0 | `[0][cmd][flag]` | 小（`0xd2/0xd3/0xd4/0xf5/0x3f/0x13/0x33/0x35/0x0…`） | ~85% |
| 1 | `[1][b][c]` | **指针量级**（`0xbf00/0x1954/0x99cc/0xb624`） | ~15% |

- 只认 `a==0` ⇒ **系统性并句**：`「台词」` 与紧随的地の文被粘成一行
  （实例 `「ちぇ、せっかくの料理が冷めちゃうよ」アージェは本当に面倒くさそうに、クラエスは渋々…` 本应 3 行）。
  本作修正后成行 **30,393 → 31,838（+4.8%）**、**最长行宽 187 → 67**。
- **自查手法**：按「opcode 长度 == 标记长度」筛出全部候选，统计**首字段的取值分布**
  （本作 `{0:84705, 1:14645, 其他:279}`）；`其他` 那 279 条是数据误撞（首字段恰为 ASCII 串），用 `a` 的取值集合即可排除。
- **判据落法**：`a in {0,1}`（形态集合），**不要**写 `a == 0`。同理，任何「标记/操作码取值」都要先看分布再定条件。
- 复核：对修改前后两份产物跑 `difflib`，抽出「A 的单行在 B 里被拆成 N 行」的全部样本**逐条目视**
  （本作 1166 处全部为「台词＋地の文」「台词＋台词」「叙述＋叙述」——正确）。

- **变体归并的省事正解：槽位替换后「相邻去重」**（Cafe Cuillere 实证）：同句双写常是
  「**固定名版**（`0x5a` 直写 `藤白さん`）」＋「**`%s` 版**（`0xfc` + 名槽 `7002`）」，二者以
  `0x36/0x22/0x21/0x23` 条件跳转分隔。**把槽位替换成默认名后两版文本完全相同** ⇒ 对输出做
  **相邻重复行归并**即可一次收干净（本作归并 1,058 行；标题/选项 0 误伤）。
  前提：**槽位→默认名映射可靠**（映射来源见 `03-basics.md` A11 的 eboot 名表）。比「按结构取一」省事得多。
- ⚠ 反向：**若两版替换后不同文**（如 `藤白さん` vs `真緒さん`），说明槽位语义/默认名判错，**先回头核 A11**，
  别硬去重（会把真内容吃掉）。

**B13. 框内 `\n` ≠ 翻点击 —— 判据是「语音数 ＋ 文本框数」，不是文本长相**
同一文本框内的字面 `\n`（`0x5C 0x6E`）是**框内换行**，须**合并**（一次点击 ＝ 一行）。
- **判据**：该框**只有 1 个语音文件 ＋ 1 条文本 op** ⇒ 一次点击，`\n` 即框内换行。
  Cafe Cuillere：全稿 `\n` 后紧跟 `「` 仅 **3 处**，全是**「两人同时开口」双行盒**，每处仅 1 语音。
- ⚠ **合并后可能出现「同句两遍」**（`「あ、そうなんだ。じゃあいいや」\n「あ、そうなんだ。じゃあいいや」`
  ＝两人异口同声）—— **属原文演出，不是重复行**：不当缺陷上报，**也**不该被去重吃掉。
- ⚠ **去重只比「整行」（`out[-1] == txt`），绝不碰行内子串**；否则等于把一个文本框拆成两行，违反
  「一次点击＝一行」。用户常拿这种「看起来重复」的行来问 ⇒ **先调源字节自证**（有 `5c 6e` ＋ 单语音）。

## B27 全角空格 `\u3000` 的**双义**（Zerodiv 系；2026-10-14，裏語 薄桜鬼 ＋ ～暁の調べ～）

**一个字符两种角色，判错必出事**：
- ① **折行标记**（日文）：出现在块首（续行）或句末标点后 ⇒ **删除**
- ② **词间空格**（全角拉丁文）：`「Ｐｌｅａｓｅ　ｔｅｌｌ　ｍｅ」` ⇒ **必须保留**

一律删的后果：英文黏成 `Ｐｌｅａｓｅｔｅｌｌｍｅ`（暁 24 行全角英文行）。
**判据**：两侧是否均为**全角字母/数字**（U+FF10-19 ／ FF21-3A ／ FF41-5A）⇒ 保留；跨块同理（`join()`）。
⚠ **全角标点（！？，等 U+FF01-FF0F）不参与判定** —— 否则日文「！　」后的折行空格会被误留。

★ **零成本判据：数「框首 vs 续行」的分布**（2026-10-16，STCM2L ニルアド）
- 统计「**框首节点**以全角空格开头的条数」与「**续行节点**以全角空格开头的条数」：
  实测 **0 / 16,714** vs **11,898 / 17,577（68%）** ⇒ 明确**位置性**（＝续行缩进/折行标记），**不是**作者的行中空格。
- 反之，**行中**（不在节点首）的全角空格若是**成规模存在**（本作 2,924 处，多在 `！`/`？`/`。` 后）⇒ 那才是**作者习惯**，须保留。
- ⇒ **两者用同一条数据就能分开**：先看「框首是否出现过」，再决定全局删还是保留；**别凭感觉**。
  （本作按「不改写原文」原样保留，并在报告写明「要删就用一行命令」，由用户定夺。）

## B28 「字符白名单」必须含**全角拉丁**（同上）

文本判据若只认「假名∪汉字∪日文标点」，「　ａ　ｒｅａｓｏｎ」这类**纯全角拉丁块**会被整块丢弃；
更隐蔽的是它会**打断合并** ⇒ 同一文本框被切成两行 ⇒ 表现为**「行首 `「` 未闭合」**（本例从 3 涨到 10）。
⇒ 白名单加 `0xFF01-0xFF5E`；**「未闭合」突然变多时，先查有没有块被判据丢掉**（不只查原文笔误）。

## B29 ★**过滤忌用「常用词子串」**（同上）

曾以 `'バストアップ' in t or '全身' in t` 判「立绘指令块」⇒ **误杀正文**
（「私は全身が熱くなっていくのを感じた。」；無印 12 条 / 暁 11 条）。
真相：**立绘控制走 opcode `0x105` + 资源名**（`chara_02_1.enc`），**根本不进文本块**；
文本形式的立绘表只存在于**调试 entry**（已整体排除）。
⇒ 判据改成「**所有** `\u3000` 分段都在部位词∪表情词表内」的**全匹配**（实测命中 0，纯保护）。
**通则：过滤条件不得使用正文常用词（全身/正面/横…），只能用「整块全匹配结构」。**

## B30 系统消息关键词表要**穷举到活用形**（同上）

`SYS_KW` 只写 `しました` ⇒ 漏掉「桜の花びらを…手に入れ**ました**。」「〜が追加され**ました**。」
⇒ 系统消息混入正文。**写关键词时用「词干＋ました/ください/ますか」覆盖活用**，并用
「**该 opcode 的全部唯一值列全后逐个过目**」做验收（本例 15 个 / 同类 244 个，一眼扫完）。
