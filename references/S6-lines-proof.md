# 切行证明（一次点击 = 一行必须代码级成立）

> **一句话**：**断框必须是数据里真实存在的边界**；文本形态（空行 / 字数 / 标点 / 相似度）只能当**验收探针**，
> **不能当切行主判据**。拿不到代码级判据 ⇒ 继续攻坚或标「未证」，**不许靠读得通顺就交付**。
> 本册是 S6 的**准入闸门**；具体 op 在哪找见 `S6-typing.md`／`S4-structure.md`／`engines/<slug>.md`。

## 1. 判据分级（先给判据定档，再动手）

| 档 | 定义 | 可否作主判据 | 典型 |
|---|---|---|---|
| **L0 代码级** | 断框由**字节码 op / 显式标记 / 引擎脚本配置**给出 | ✅ 唯一首选 | `0x4bb`・`0x1F4`・`FFFF/FFFB`・`op 0x3f/0x41`・`<pb>`・`<K>`・`LineMode.tjs` |
| **L1 结构级** | 记录自定界（长度前缀 / NUL 串池 / 12B·16B 单元 / voice 1:1），由此推「记录 = 框」 | ✅ 但**必须补 1 条交叉验证** | SCR `0x5a` 串・12B 单元・STBL 偏移・`_ZM` |
| **L2 文本形态** | 空行・字数/行宽・句末标点・引号配对・相似度・语感 | ❌ **禁作主判据**（只作探针/兜底） | 「空行=改页」「≤54 字」「取最长」 |

> L1 的交叉验证＝**任选一条**：① 语音条数 ≈ 框数；② 每框记录数分布有硬上限（如 97.2% ≤3）；
> ③ 单记录字符硬上限 ≈ 行宽；④ 与同族已证引擎的记录签名一致。

## 2. 为什么必须 L0/L1（两个方向都会错，且品检可能全绿）

- **少切（多框并一行）**：文本仍通顺、引号可能仍配对 ⇒ `check_text` 不报错。
  实例：アンジェリーク トロワ 链式合并把「并列变体表」串成 **365 宽一行**。
- **多切（一框拆多行）**：碎片行 + `行首「未闭合`；引号探针能抓到，但**根因仍在猜**。
  实例：O＊G＊A 旧「句末优先＋3 行窗口」拼出**不存在的句子**（`「どんなことをやるんですか?」`，串表 0 命中）。
- **同引擎跨作语义会反转**：`@n` 在 カレイドイヴ＝拆新行、在 マジきゅん＝框内暂停须合并
  ⇒ **换作必回查**，不许照抄上一作。

## 3. 取证流程（S6 五步，缺一不可）

1. **列候选**：在连续正文记录之间找「**框内绝不出现、框末必现一次**」的字节/记录 —— 这是定框的**定义级**条件；
   找不到就换载体/换层，不要退化成「看文本像不像一句」。
2. **自证**：① 终止记录 `id ＝ 末行 id ＋ 常数`；② **覆盖率**（O＊G＊A `op 0x3e` 命中串起点 **732/732**、
   文本引用率 **99.2%**；オルフレール STBL **122,212/122,212**）。
   ★**覆盖率数的是「断点」不是「记录」**：一条记录可含多个待键码（HuneX ALS：10,207 条里 4 条含 2 个 `%K`）
   ⇒ 成行必须**逐处断行**，禁 `split(码)[0]`／「每条取第一段」（后者静默丢后半句、行数还对得上）。
3. **反例检验**：用「更激进」与「更保守」两套断框规则各跑一遍，**差异行必须能被判死**：
   `」「` 粘连、行首 `「` 未闭合、行尾无标点异常、一行出现两个说话人 —— 哪套归零哪套对（REVICE[D]：`」「` 98→0）。
4. **量化**：每框记录数分布 + 单记录字符上限 + 框容量（如 3 行 × 28 字）；能拿到**官方截图/说明书**
   就用「截图断行点 ↔ 脚本落点」对照（几何对照最硬）。
5. **落报告**：按 §7 三行模板写死；报告里**没有判据 = 视为没做**。

## 4. 判据优先序（先想最硬的，别一上来解析文本）

| 序 | 来源 | 说明 |
|---|---|---|
| ① | **引擎脚本 / 配置** | `LineMode.tjs`・`macro.ks`・引擎文档（篠田：`mode=free` ⇒ 空行 = `[p]`，这是**代码级**而非猜） |
| ② | **等待/清屏 op** | `0x1F4`・`0x4BB`・`op 0x3f/0x41`・`FFFF`・`0x0003`＋`0x0004`・`0x5a` 每串一框 |
| ③ | **分隔记录 / 空文本记录 / 名札记录** | 12B `[0][cmd][flag]`・16B `[0][0x4BB][0][0x10]`・空 `0x4ba` |
| ④ | **顺序表 / 分派表** | STBL・STORYCTRL・`@goto` 链 —— **只解决顺序，不解决切行**，别混用 |
| ⑤ | **文本内显式标记** | `<pb>`・`<K>`・`▼■▽`・`\c`(清框)・`%P`・`@click()` |
| 末 | 文本形态 | 只当探针（§5） |

## 5. 黑名单（禁作主判据；用了就是「猜」）

- 「**空行 = 一次点击**」——**除非**在引擎脚本/配置里查到依据（篠田 ✅ / Lamento ❌ 仅样例）。
- 「按**字数/行宽**切」——反例：只允许**反用**（记录有**硬上限** ⇒ 记录=显示行，这是结构证据）。
- 「**句末标点**断开」「**引号未闭合**就并入下一行」当主边界 —— 只能是**修残片的兜底**，且须注明。
- 「相似度 ≥0.75 取前段」「同点击多版**取最长**」—— 属**内容选择**，不得用于定框。
- 「**下一字段也是日文串** ⇒ 名札」——可作名札识别，但**不得**据此断行；名札判定错＝整行丢失（千銃士）。
- 「**相邻 id 差 == 1**」—— 已禁（框内 id 会跳号）。
- 「**地址连续** ＝ 同框」—— 必须同时给出**分隔记录**（Glass Heart：连续 + `[0][0x1f4][0][0x10]` 才成立）。
- 「**记录条数 = 行数**，看起来行数合理」—— 合理不是证据（见 §2）。

## 6. 拿不到 L0/L1 时（禁止硬上）

**先做「点击 op 定位三步法」**（比翻文本可靠得多）：

1. **重复台词差分**：全库找**同一句文本出现 ≥2 次**的记录，对比两次之间的指令 —— 共同出现的那条
   就是候选断框/等待 op（真断框会**每次点击都出现**，但同一句的两次上下文未必相同 ⇒ 还要第 2 步）。
2. **必现性筛除**：对上一步的候选，回溯**全库**统计「两段正文之间出现率」：
   框内出现率必须 **≈0**、框末出现率必须 **≈1**（O＊G＊A `0x3f/0x41` 即由此定案，5,153 + 16,244 次）。
3. **行为验证**：改一条文本（加长/插入标记）在模拟器里跑，观察**点击时**执行到哪条 op；
   或直接查引擎脚本/文档（`LineMode.tjs`、`macro.ks`、官方 SDK 说明）。

> 三步都走不通 ⇒ 记录「候选 op + 出现率 + 已排除项」再停手汇报（`00-discipline.md`）。

- 仍不通 ⇒ 回 `S0-triage.md` §E 四步攻坚；或找**参考实现**（GARbro / FreeMote / KrkrZ / 同引擎开源工具）。
- 还拿不到 ⇒ 报告写「**切行判据未证（L2）**」＋已排除项 ＋ 候选清单，**交付前须用户确认降级口径**。
- **禁止**把「读得通顺」当结论（SKILL.md §0 禁猜测的延伸）。

## ★ 反例：**禁止用「行内引号数量 / 字数」判多框**（2026-10-26）

现象：成品里出现「一行 200~243 字、含 4~12 组 `「…」`」，看起来像多个框被合并。

**我当时的错**：按「行内 `「` ≥4」直接拆成多行 ⇒ **154 行全部拆错，已回滚**。

**代码判据（HuneX Ogre 系，`allscr.mrg`）**：

```
_ZM<5hex>($NNNNNN)     一次点击 = 一个框
_MSAD($NNNNNN^)        同框续写（并入上一框）
_MTLK(1,id)            换说话人 ⇒ 必须新开框
```

实测（スチームプリズン `CH04_01_STORY`）：`_ZMbab09($042413^)` 后连续 **7 条 `_MSAD`**，**中间无 `_MTLK`**
⇒ 引擎语义上就是**一个文本框**（一括表示／框内滚动），**不拆才对**。

**通用结论**：
- `_ZM`（或等价「开框」指令）+ N×「续写指令」且**无换说话人指令** ⇒ **一行**
- 出现换说话人指令（`_MTLK` 等）才新开一行
- **引号数量、字数、行宽、像不像对话，全部是 L2，只可当探针**

同类注意：日式 AVG 常见「一括表示」——整段文字一次性铺满文本框，玩家滚动阅读；这类长行是**引擎设计**，不是提取缺陷。

## ★ 核心区分：「一次文本更新」≠「一次点击」（2026-10-26 两个案例收口）

同一件事在两种引擎上以不同外观出现，判据必须落到**记录粒度**，不能落到「点击指令」：

| 引擎 | 外观 | 错判成什么 | 正解判据 | 实例 |
|---|---|---|---|---|
| HuneX Ogre（`_ZM/_MSAD`） | `_ZM` + 7×`_MSAD` 无 `_MTLK` | 「一个文本框 ⇒ 一行」 | **上一条文本引号未闭才并入**（真续写 148/4,088） | スチームプリズン 42,370→43,181 |
| STCM2L（`0x1348C`+`0x1F4`） | 整段只有一个 `0x1F4`，句间是 `NAME`+`0x43B54` | 「一个段落 ⇒ 一行」 | **两条正文记录直接相邻才并入**（同句换行 39,164；换人 690、换段 546） | KLAP!! 50,102→50,722 |

**共同结论**：引擎可以「不等玩家点击就连续替换文本」（自动演出、群像齐声）。
此时玩家看到的仍是**一条一屏**，把它整段合成一行会让翻译无法处理。
**落地检查**：若某行 ≥4 组 `「…」` 或 200 字以上，回源看「这些句子之间有没有换说话人/换立绘的指令」——
有 ⇒ 必分行；只有「同一句被框内换行切碎」（记录直接相邻、或上一条引号未闭）才合并。
