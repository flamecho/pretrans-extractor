# 脚本结构逆向（细节）

> 见 `02-stcm2l.md`。

## 1. 主循环必须「字符宽度感知」（最容易静默丢文本）

混合编码下：汉字 2 字节（首字节 `0x81-0x9F` / `0xE0-0xFC`），假名/控制 1 字节。
主循环写 `i += 1` ⇒ **汉字尾字节撞上指令码** ⇒ 消息从汉字中间被切开。

```python
def is_lead(x):
    return (0x81 <= x <= 0x9F) or (0xE0 <= x <= 0xFC)
# 主循环里：if is_lead(x): i += 2; continue
```

> **真实事故**：某 PSV 作尾字节 `0x76`/`0x7C` 恰好等于「文本段起」「消息 id」指令 →
> **20,285 / 80,168 条消息为空，丢约 21% 文本**，而抽出来的句子**仍然通顺**，肉眼看不出来。

**自检**：统计文本字节总数 / 空消息数。空消息 > 10% 几乎一定是这个 bug。

## 2. 常见消息结构

`7c <u16 msgid>` + 可选 `76 <p1> <p2>` 头 + 正文 + `07 <x>` 分隔。

- `7c <u16>` 后约 88% 跟 `76 p1 p2`，12% 直接接正文 ⇒ 头部当**可选**处理。
- `07 00 / 07 01 / 07 02` = 段结束；其余 `07 XX`（含 `07 0a`、罕见 `07 5b`）= 软分隔，继续读。
- **转义序列（如 `7e XX`）必须整体跳 2 字节**：否则 `XX ∈ {0x76,0x77,0x7c,0x00,0x0b}` 会被当分隔符吃掉，
  表现为「消息以 `7e` 结尾」（实测 33 处）。
- 正文段用 SJIS 感知游标扫描，遇 `0x07` 才判分隔。

**不定长 op 的通用解法**：用「**文本记录驱动扫描**」——记录自带长度自定界 ⇒ 永不失步。

## 3. 字符层顺序与字符合成

**顺序**：① **先定假名块**（单字节码通常是自定的假名序，可能剔除小假名）——
用「**人工读图 + 同句变体**」交叉验证，**不要只靠语言模型**；② **再定汉字**（多数直接是 cp932）；
③ 再处理替换槽（见 `pitfalls/A1-decode-core.md`与 `03-basics.md` A2）。

- **1 字节汉字宏**：用「**同句拼写变体**」法确证 —— 同一场景里往往有一处把宏写全了。
  取前后缀（各 ≥4 字）在全文里搜「中间填成完整词」的行即可铁证。

  ```python
  pat = re.compile('^' + re.escape(pre) + '(.{1,6})' + re.escape(suf) + '$')
  ```
  例：`0x6F` 旁出现 `8e 76 0f 8f 6f`（思 い 出）→ 铁证 `0x6F` =「思い出」。
- **「后字选词」宏**：`XX`+下一字 → 输出「与下一字组成词的首字」（下一字保留）。
  例：`7B`+`ク`→ボ、`7B`+`当`→本、`6C`+`た`→私、`69`+`泉`→永。实现成 `LOOK_NEXT = {code:{next:out}}`。
- **变量**：`7e XX` = 名字/地名/术语表引用；`0x67 <form>` = 主角名（姓/名/全名分 form）；
  `0x7A`/`0x74 <form>` = 同行者名。术语表常在另一个 entry（如「用語辞典」文本）。
- **内联插入有两种形态，别默认是「文本内联」**：
  ① **文本内联** —— 插入块里直接就是字面（コルダ/下天の華 路线）；
  ② **定长表引用** —— 插入块只带 `id`，真值在别处的**定长记录表**里（遥か5 实证：脚本用语表 52B、
  用語辞典表 64B）。**遇到「插入块解出来是空 / 断句」先怀疑是②**，而不是「变量表没找到」。
- **定长表的基址定位靠「空槽字面」**：空槽（`仮`／`用語予約NNN`）会**把 slot 索引与逻辑 ID 的错位暴露出来**。
  用「某条空槽的字面编号 N（如 `用語予約３６８`）」反推 `base = 该槽地址 − N × 记录长`，
  才能整体对齐；直接假定 `base=0` 会**整体错位一格**、查表查到邻居值。
- **说话人标签**要单独识别并丢弃：如 `5b XX 00 47 YY 00`、`name "△△△△"`。

## 4. 分支变量的块回填

「フリートーク / 物忌み」这类循环会把**同一段台词按固定顺位复制 N 份**（如八葉 8 份）。
判据由强到弱：

1. **同一句占位台词在一个事件内恰好出现 N 次 → 第 k 次即第 k 位角色**（最强）
2. 锚点区间：找 `xN` / `x40`(=5×8) 的重复行当块边界；**最大间隔通常恰好落在 N 的倍数处**
3. 就近推定（兜底，距离 ≤60 行）

**不要**无条件「就近点名」—— 会把**上一块的名字填给下一块**（整体错位一格）。

## 6. 条目边界：先切「尾部签名」，再跳「前置表区」

**A. 尾部可能有哈希/校验/对齐/填充 ⇒ 解析前切掉。**
- 症状：某条目的**末个文本 op 的 run 被掺入二进制随机字节** ⇒ 凭空多出**含 `PUA`（U+E000-F8FF）的文本/选项**，
  且这些假行**含汉字**，`filter_lines` 的「无假名/汉字即丢」拦不住 ⇒ 必须按**结构**切。
- 本族（D3P「CRI CPK ＋ 自建字体」）：条目 ＝ `0x2000 B 头 ＋ u16 码流 ＋ 尾 16 B 哈希`
  ⇒ `d = raw[0x2000:-16]`（Vamwolf Cross† 実証：不切则多 **147** 个假选项，占选项总数一半）。
- 通用做法：**先用「尾部签名」判别**（定长哈希 / 全 0 填充 / 固定 magic），切掉再进 `toks()`。
  ★ **PUA = 「二进制被误读成文本」的强信号**，可当假文本探测器。

**B. 脚本前常有一段「样式 / 字符定义表」区，且内含真命令码。**
- 表区里会出现与正文**同形**的 `FFFF` / `FFE6` / `FFE7` / `FF33`（如循环 `FFE4 FF33 。 FFE5 FF33 ， FFE6 FF33 ． …`），
  若从条目头扫描 ⇒ **插错名 / 产假选项**。
- 做法：**从首个「正文类命令」起解析**（本族＝名牌 `FFF0`；其它引擎＝首个文本框/消息 op）。
  ⚠ 且该表区可能**夹在脚本中间**（不只开头），故「按前后文判定」比「按偏移一刀切」稳。

**C. 宏（变量插入）要按「链」续接。**
- 同一处常连发两个宏（`FFE6` 姓 ＋ `FFE7` 名）；「行内 vs 名牌」判定若只看**紧前一个 token 是不是正文命令**，
  第二个宏会被丢掉 ⇒ **丢名**（Vamwolf：`管理人の`＋`FFE6`＋`FFE7(と申します」)` 曾丢 `セリ`）。
  正解＝**允许宏链**：前一 token 也是宏时，继续按行内处理（并同样 `cur += 宏值 + 其后 run`）。

**D. 「命令列脚本」＝ `<u16 tag> <u16 size(自身の 4B を含む)> <payload>`（自研 `.lzs` 系，2026-10-15 明治活劇 ハイカラ流星組）**
- **判型**：`<u16,u16>` が連続し、`pos += size` で**末尾まで一度に着地**すればこの枠組み
  （size<4 か `pos+size>len` で即破綻 ⇒ 別物）。`size` は**ヘッダ自身を含む**点に注意（payload は `size−4`）。
- **本文ノード＝ tag が 1〜2 種だけ**：payload 頭に `<u32 話者ID>`、続いて `<u16 len><utf8>` の列
  （本族＝3 個固定 `[ボイスID][名札][本文]`、`"-1"`＝無音／名札フィールドは §0 により破棄）。
  同 tag の**先頭に `<u16 node_size>` と `<u32 N>`＋`<u16 N>`（同値＝連番）**が並び、判型の手掛かりになる。
- ★★ **選択肢は別資源に置かれ得る** —— 本文を取っただけで終わらせない。本族は脚本に**選択肢文字列が 0**、
  選択コマンド `tag 0x68` は**キャラ ID 参照のみ**。実体は `CORE`（アセット台帳＋データ）側の
  `<u32 len><u32 スロット(0-3)><utf8>` 表に 383 件あった。
  ⇒ **手順**：① 脚本内で「選択」に相当する tag を数える ② payload に日文字列が無ければ
  ③ 全資源から `[読み][見出し語][解説]`/`<u32 len><utf8>` 型の**表**を探す（`03-archive-family.md` A24）。
