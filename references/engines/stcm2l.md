# STCM2 / STCM2L

## 识别与区段

识别 `STCM2` 或 `STCM2L` 生成器串，并按头字段定位全局数据、代码、导入导出表和子文件范围。
`CODE_START_` 可定位代码区，具体起点仍由对应头结构确定；导出表地址不天然是指令链终点。
UNI2 等外层容器可能在脚本前缀另存文本或记录表，代码区之外的相关区段须独立分类。

## 记录布局

| 布局 | 读取方式 |
|---|---|
| `u32 size + payload` | size 含头，按记录长度推进 |
| `is_call / opcode / nparams / length` | 按参数数量读取参数三元组，再处理数据区 |
| `pre / tag / N / size` 与样式槽 | 槽通常为 12 字节；结合 size、槽数和对象起点核对 |
| 文本对象 `[0,L/4,1,L,text,pad]` | 四个 u32 共 16 字节；验证长度、终止与对齐 |

参数可能包含多个文本对象或资源、颜色、标签；不能固定取 p0、固定槽数或固定串偏移。
对象前可有额外字段，先核对布局，再解释对齐和长度冗余。
区段边界、数组、填充与指令链分别消费；未分类字段保留来源。

## 调用与文本分类

导入函数编号可能逐文件平移 Δ。用导入表、处理函数及调用结构确认映射，不能由生成器日期或日文串频次确定 opcode。
文本、名札、选择和资源可共享 kind 或槽形态；分类须依据真实参数用途与显示调用。
同包多套脚本通过有效入口、动态调用和独有文本确认使用关系，不因未注册或高度重复整组排除。

## 显示与分支

等待命令不天然清屏。按提交、追加、清屏及配置维护段与页；连续正文记录也可能属于不同点击。
`#n` 等标记是否排版换行、`#Name[n]` 等槽是否动态姓名，以匹配语法和读取实现确定。
互斥参数组可为姓名、样式或内容变体。条件和引用证明为同一显示版本后才折叠，不能固定取第一支、最短周期或前半段。
选择文本逐字段读取，分支目标、标志值和调试字段不作为显示文案。
