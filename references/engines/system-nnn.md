## 2. `.spt` 格式

* **整文件逐字节 XOR 0xFF**（取反）即解密；取反后 `0x30` = 魔术字 **`SPTHEADER0`**、`u32@0x00 = 0x20`。
* 头（`0x00`–`0x40`）：`[u32 0x20][u32 0x66660001][u32 0x55550001][u32 0]` ＋ **4×(u32 count ＋ u32 base)**
  （`base + count` = 该字符串组首串的逻辑地址；组齐备时 count 与池内串数吻合）。
* 布局：`[头][指令流][地址表1][消息池1][小桩 4 条指令][地址表2][池2 杂多テーブル]`
  * 指令 4 字节对齐，形如 `[u16 参数][u16 op]`；op ∈ {`6666` `5555` `5556` `3333` `2222` `4444` `8000` `9000` `a000` `a500`}。
  * **地址表 = 池内串数条递增 u32（逻辑地址）**，紧贴池前方（⇒ 字节扫描时常与池被误并为一段）。
* **消息 = `<说话人名>\r\n<正文>`**（无 `\r\n` = 旁白）；说话人可为字面名 / `#名`(主人公名) / `？？？`。
  正文内联：`#［Nよみ］`=注音(剔)、`#名`=主人公名(inline)、`#<字>`=图标(剔)、`\r\n`=框内换行(合并)。

## 3. ★★ 字符串记录 = 4 字节对齐槽（2026-10-16 PSP 定案；PC 亦同）

* 记录格式 = **`[data][NUL][垃圾填充至 4 字节边界]`**（填充 1~3 B，内容为**未初始化内存残渣**，
  恰可解作 cp932 时即产生 PC 版所述「串首 1~3 字乱码」：`安綱`→`ｭｈﾀ綱`、`語気も荒く…`→`′鼡Cも荒く…`）。
* ⇒ 每条串起点落在**固定的 4 字节网格**上：从池起点「读到 NUL → 跳到网格下一格」行走，
  **串首天然干净**（PSP 实测污染 0 残留；PC 版当年的「三级重同步」启发式因此可以省掉）。
* 池起点自身可能不在 0/4 相位，且常与前方地址表被误并 ⇒ **每池在 4 个相位中择优 ＋ 头部裁切**
  （表项短、无假名）。判据 = 结构锚点加权分：
  `%#` 質問 ×20 ／ 人名札 `NAME_RE` ×10 ／ `■`・日期 ×2 ／ 含 CRLF ×1 ／ 半角假名 −3。
  16 本全部收敛到相位 0（含 PC 版曾靠硬编码 `po` 的 takatora / syuichi）。
* PC 版旧法（作废备案）：硬编码池起点 `po`（takatora `0xcf5a4` / syuichi `0xa8424`）＋
  「首串候选 p=0..5 找 `^<人名标记>\r\n`」三级重同步。

## 4. 池2 = 選択肢・場面タイトル（PSP 本篇）

| 形态 | 例 | 处理 |
|---|---|---|
| `%#` ＋ 色汉字 + 正文 | `%#黄初日を観ますか？` | **選択肢の質問**（`%#`＋色汉字剥除后上屏） |
| 質問直后紧邻的短日文串 | `観る` / `観ない` | **選択肢**（1 行 1 条、按序；判据＝纯日文・≤24 字・无 ASCII/数字/★/■・最多 6 条） |
| `■` ＋ 日期 | `■７月２８日・昼` | **場面タイトル**（`■` 剥除） |
| 裸日期 | `７月２８日` | 場面タイトル |
| `★★★★メイン★★★★`・`★★…` | — | 编译标签 → 剔 |
| 含 `：` 或 `＿` | `Ｘ：選択肢＿…` / `■ＢＡＤＥＮＤ：…` | 内部标签 → 剔 |
| 纯 ASCII/数字 | `bg01033` / `acu_chapter1sub` / `_catch` | 资源名・跳转目标 → 剔 |
| `★トップ` / `八重垣邸` … | — | 章节・地点标签 → 剔（非上屏） |

* 質問数 = 全文件 `%#` 字节出现次数（PSP 本篇 89，逐文件核对一致）。
* **跨池执行序不可廉价复原**：两块地址表的逻辑地址区间不相交（池1 全在池2 前）
  ⇒ 成品采用「各文件正文之后、按池2 出现顺序追加」，文件级与池内顺序均忠实（详见各作报告「已知问题」）。

### 5.1 ★★名札表必须「自举」——`charaname.xtx` 只收具名角色

PSP 本篇 `charaname.xtx` 仅 26 种（具名角色），但脚本里还有 **28 种泛用身份札**：
`青年`(25) `少女`(45) `少年`(22) `女性`(22) `妖`(6) `男` `女` `鬼` `三鬼` `子供たち` `未来`
`―――`(186，无声) `主座`(63) `退魔師`(29) `雑霊`(8) `禍神`(5) `ふたり`(5)
`東雲さん？`(10，主人公尚不知其名时的名札) `祇王・虚空` `水鬼・金鬼` `祇王・高虎` `先輩・後輩`（多名札）。
只按 `charaname.xtx` 比对 ⇒ **整行残留名札**（`青年「母上……」`）。**check_text.py 抓不到**（它只查 `【名】`/`名前：`），
必须靠 SKILL §1 的 **`^([^\s「」（）]{1,14})「` 词频复扫**才能发现。

**自举判据**（全库统计后判定，`mine_plates()`）：`<core>\r\n<rest>` 且 `rest` 以 `「`/`『` 开头、`core` ≤14 字，且
① 含汉字/片假名 ⇒ 名札（排除纯平假名叙述如 `そして`）；② `・` 连接的纯人名串；③ `core == '―――'`；
④ 纯平假名仅当 `rest` 以 `「「` 开头（`ふたり`/`子供たち` 齐声）；⑤ 以 `？` 收尾者（`東雲さん？`）须**重复 ≥2 次**才认。
⇒ 复扫后仅剩 11 行 `X「`，均为**叙述句内引用**（`彼がわたしを「姫さん」と呼ぶ…`），正确保留。

### 5.2 ★纯符号台词不能丢（旧过滤的隐形漏收）

`「…………」` `「？」` `「～～♪　～～♪」` 等**不含假名/汉字**的台词，会被
「`if not JP.search(b): continue`」整行丢掉（沿用 PC 版旧法）⇒ PSP 本篇 **450 行 = 450 次点击**。
正解：**以 `「`／`『`／`（` 开头者一律保留**，其余仍要求含假名/汉字（滤资源名・符号噪声）。

### 5.3 原文缺陷：`LINE_FIX` 定值修

`chapter3.spt @0x69a7e` 该框正文 `「ん、いいねー。…甘さは欲しいけど。` 以 `…けど。` 收尾即 NUL
（**全库唯一、无平行副本**）⇒ 判为原作用漏收尾 `」`，按 アーメン・ノワール／Little Aid／月ノ光 先例 `LINE_FIX` 补。
不补则「行首 `「` 未闭合」＋引号配对差 1（两项 [E]）。
