## 3. ★★ 双主人公宏：`＠`＝姓、`＄`＝名（逐块切换）

本作一本软件装 **两部独立剧本**：
- **X 編**（冬・スキー補習合宿，Class X / B6）主角 **南 悠里**（vndb c20033，可改名）
- **Z 編**（夏・臨海学校／愛染町，Class Z / A4・P2）主角 **北森 真奈美**（vndb c29004，可改名）

两作**共用同一对宏**，值由当前剧本切换 ⇒ 必须**按块判侧**再替换：

| 宏 | X 編 | Z 編 | 依据 |
|---|---|---|---|
| `＠` | 南 | 北森 | 自介句 `私は＠＄です` / `＠＄先生杯`（全名序＝姓+名）；`＠先生` 66 次 |
| `＄` | 悠里 | 真奈美 | ELF `EBOOT.dec @0x1885c4` 串池 `＄`/`悠里`/`南`/`真奈美`/`北森`/`★`；`@0x167c90` 名字长度报错串 `<%c%c>`（恰两枚宏） |

- `★` **只出现在名札位**（1,253 次，正文 0 次）＝主人公叙述（地の文）的名牌，**丢**。
- **分侧判据（已实测 90 块无歧义）**：名札整字命中集合
  X＝{翼,瞬,瑞希,一,悟郎,清春,七瀬}／Z＝{天十郎,慧,千聖,八雲,那智,アラタ}；
  平票时退化为关键词（`スキー/スノボ/雪/冬/ゲレンデ` vs `海/夏/臨海/愛染/祭`）。
  结果：**块 1–42 与 85–86 ＝ X，块 43–84 与 87–89 ＝ Z，块 0 ＝ 系统表**（剔除）。

## 4. 控制码与引号

- `@n`＝框内软换行 → **合并**（15,884 处）；合并后原文常留 `　`（缩进/语气空格）⇒ **保留**（同 `アルカナ` 口径）。
- `@k … @w`＝着色开关（564 对）→ 去标记留字；无其他 `@` 命令。
- **原文 0 处 `「」`**（仅 210 组 `『』`，均衡）⇒ **不补 `「`**（与 Real Rode 的补偿相反，同族逐作变的又一例）。

## 6. 坑

- ⓐ **AFS 成员 0/1 是「场景包」而非纯贴图**：块内 `HFU2` 再嵌 `HFU2`（raw，无 UFFA）＋`UFFA` 贴图 ＋ 3 KB `IKA`；
  直接把块当 IKA 扫会看到 `通常`/`真壁　翼` 这类暂停画面标签 —— 那是 **UI**，不是正文。
- ⓑ **`decode_hfu2` 只认 UFFA 块**；本作块内还有**裸 HFU2**（条目直接指向 `HFU2`/`TTH`/`ANM`）⇒ 递归时必须两个分支都走。
- ⓒ 同名宏跨作语义会反转：`アルカナ`/`Lucian` 的 `＠/＄` 是「名/姓」，本作是「**姓/名**」⇒ **以本作自介句与 ELF 串池定序**。
- ⓓ 两部剧本混在同一 `HFU2` 里（90 块），**块序 ≠ 章节序**（X 的尾声 85–86 排在 Z 之后）⇒ 按数据序产出，不重排。
