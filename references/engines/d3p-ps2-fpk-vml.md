# D3P PS2 · FPK 归档 + VML 脚本（ラスト・エスコート 系）

> 首段固定四件套：**识别特征 → 容器链路 → 脚本记录 → 成行**。
> 实例：ラスト・エスコート 〜深夜の黒蝶物語〜（`SLPS_255.91`, 2006-01-26）/ 〜黒蝶スペシャルナイト〜（`SLPS_256.73`, 2006-07-27），D3PUBLISHER / 開発 Vingt-et-un。
> ⚠ 同系列 PSP `Club Katze` **不是**此引擎（NK/PAF＋PSCB）。
> 待验证同族：ひめひび / 乙女的恋革命★ラブレボ!! 等同期 D3P PS2 乙女作。

## 1. 识别特征

| 看什么 | 值 |
|---|---|
| ISO 根 | `SYSTEM.CNF` + `SLPS_xxx.xx` + `DATA2/`（`ADV.FPK` `CMN.FPK` `CG.FPK` `CPT.FPK` `FG.FPK`）+ `SOUND2/` |
| 归档头 | **无魔数**：`u32 count` / `u32 0` / `u64 数据区总长` / `u32 0x20` / `u32 dataStart` |
| 脚本后缀 | **`.VML`**（1069 个）。同目录的 `.FPK/.TEX/.ARC` 全是图像 |
| 文本特征 | 载荷字节全部落在 **0x21–0x7E**，且逐字节 `+0x80` 后是合法 EUC-JP |

> ⚠ `identify.py` 认不出（无魔数）。判型靠「`.VML` + `DATA2/` 目录名 + 载荷全 0x21–0x7E」。

## 2. 容器链路
```
ISO9660 → DATA2/ADV.FPK（FPK 归档）→ *.VML
```
FPK 条目 32 B：`name[16]` + `u32 size` + `u32 offset` + `u64 pad`；表起点 0x20。
`CMN.FPK` 只放 `FONT.FNT` / `RCV_MAIL.DAT` / `*.COL` / `*.DAT`（无剧本）；CG/FG/CPT 全 `.TEX`。

## 3. 编码
**JIS X 0208 的 7bit 形态**（不是 Shift-JIS、不是 cp932、无转义序列）：
`bytes([b + 0x80 for b in payload]).decode('euc_jp')`。
⇒ 半角假名/PUA 问题天然不存在；反解用 `b - 0x80`。

## 4. 脚本记录
VML 头：`u32 hdrSize(0x10)` / `u32 tableOff` / `u32 count` / `u32 fileSize`（tableOff 的偏移表**不用于文本**）。
字符一律 2 字节，`len` 是**字节数**。

| 记录 | 结构 | 语义 |
|---|---|---|
| 正文 | `68 00 00 FF` + `u8 len` + len 字节 | 画面 **1 行**（实测 ≤18 字符 = 一行宽，故 18 是天然行宽校验） |
| 名札 | `64 00 00 FF` + `u8 len` + len 字节 | 说话人（同时兼当该行语音的 key，故前作笔记记为「ボイス有」） |
| 选项 | `F6 01 00 FF` + `u16 idx` + `u8 len` + len 字节 | 选择肢；`F7 01 00 FF` 收尾；**idx 非显示序**（实测 `[1,0]`、`[3,2,6,5,…]`），成行按记录顺序 |
| 消息号 | `90 01 00 FF` + `u32 id` | 回溯用编号，非文本（每枠 +1，可当「一枠一击」自证） |
| 枠开始/フラグ | `66`（通常）/ `67`（flag 0 = 字幕・扉文） | 不产字符；扉文也要收 |

## 5. 成行（一次点击＝一行）
**紧随正文记录之后**的 4 字节决定边界：

| 码 | 语义 | 处理 |
|---|---|---|
| `69 00 00 FF` | 软换行（同框换行） | 合并 |
| `6A 00 00 FF` | 插入主角名 | 替换 |
| `6B 00 00 FF` | 插入主角名（**行首**也会出现） | 替换 |
| `6C 00 00 FF` | 直接接续（无换行） | 合并 |
| 其他（`6F`/`0C`/`09`/`6D`…） | 换框 | 断行 |

**校验判据**：按 69 合并后「行/框」分布应集中在 1–3 行（本作 1:5392 / 2:5518 / 3:9502 / 4:31 / >4:9），
一枠 1–6 个 `68`、总字数 ≤54（18 字 × 3 行窗口）。

**★ 窗口容量用「分布断崖」直接量出来**（不用截图）：把每框字数分 18 字一档统计 ——
`0–17:5974 / 18–35:7808 / 36–53:5866 / 54–71:11 / 72–89:4 / ≥90:1`。
断崖落在 54 ⇒ 行宽 18 × 3 行，**这个断崖本身就是窗口尺寸的证据**。
且 11 个超窗框里 **10 个收尾码是 `09`**（全作仅 20 处）、而不是常规 `6F` ⇒ `09`＝长叙述／自动翻页，
**超窗框不拆页**（拆了会在句中切断，如「…わけじゃない。拒絶さ｜れなかっただけ。」）。
反例警戒：`0F`/`0C` 收尾的框**不一定**长（30 字的也有），别把「长」当 `09` 的判据。
**别把 69 当「点击」**（否则一句被拆成 3 行、翻译全错位）。

## 6. 主角名（陷阱）
名字用 `6A/6B` 宏插入，**正文里字面出现的姓名可能是别人**。本作实测：
- ELF 有名字输入默认值：`作上` + `明里` + `あなたの名前は %s　%s でよろしいですか？` ⇒ 主角 = **作上 明里**
- ELF 另有名字表（含 `絢子`）⇒ `絢子` 是**另一位角色**（大小姐/解说役），正文 70 处字面「絢子」是她的
- `SOUND2/<NAME>/` 目录名（本作 = `AKARI`）= 主角语音，可当旁证
- **`6A` = 姓（作上）、`6B` = 名（明里）**：`6B` 后随 ちゃん663/さん212/くん82，`6A` 后随 さん14/？14/。9；
  铁证是 6 处 `6A+6B` 相邻句「私は[6A][6B]……え？」→「私は作上明里……え？」
⇒ **字面 絢子 一处都不要改**。判据优先级：`6A+6B` 相邻句（最硬）> 后随敬称分布 > ELF 输入默认值 > 名字表角色区分 > vndb > 语音目录名。

## 7. 易错
1. **别按 Shift-JIS 解**：0x21–0x7E 全是"ASCII"，看着像乱码/半角假名，其实是 JIS 7bit。
2. **`68 00 00 FF <len>` 的 len 是字节数**（18 字符 = 36）。
3. 记录之间夹着参数块（`e8 03` / `90 01 00 FF` + u32 / `a8 09 00 00` …）：**不要试图整体反汇编**，
   只按 `68/64/F6` 字面前缀线性扫描 + 「后随 4 字节」判边界即可；本作 45,109 条正文一条不漏、零误报。
4. 线路共用场景 ⇒ 大量**正文完全相同的文件**（本作 1069 里 389 个、98 组），按「共通块只留一次」折叠；
   字节不同（跳转/ID）但正文相同，用「正文 md5」判等才准。
5. 操作提示串（本作 `シャンパンコール中！□ボタンのスキップに注意して下さい。`×48）属 UI 提示，排除。
6. 闭合校验（推荐常做）：把 `68/64/F6` 载荷字节清零后重扫「≥8 字节连续 0x21–0x7E 且可解为日文」的残留串
   —— 本作残留 0 条；**非 0 ⇒ 还有别的文本记录类型没认出来**（本作正是靠它发现了 `F6` 选项）。
