# FPK ＋ VML（D3P / Vingt-et-un・GameStudio 系 PS2）

> 识别特征 → 容器链路 → 脚本记录 → 成行 → 易错。
> 代表作：**ラスト・エスコート 〜深夜の黒蝶物語〜（PS2, `SLPS_255.91`, 2006-01-26, D3PUBLISHER / Vingt-et-un. Systems, vndb v1978）**。
> 工具 `scripts/lastescort_ps2_extract.py`；报告 `提取结果/解析报告/[PS2-JP]ラスト・エスコート 〜深夜の黒蝶物語〜_解析报告.md`。
> ⚠ 与同系列的 PSP `Club Katze` **不是**同一引擎（那是 NK/PAF＋PSCB，见 `lastescort-paf.md`）。

## 1. 识别特征

- PS2 ISO 根目录 `DATA/*.FPK`（ADV/CG/CMN/CPT/FG 五件套），**无魔数**：头就是 `u32 count`。
- ADV.FPK 内条目后缀 = `VML`（剧本）/ `TEX`（纹理）/ `ARC`（立绘动画）/ `FPK`（事件语音）。
- VML 正文段字节全落在 `0x21–0x7E`（"像 ASCII"却是日文）——**7-bit 存放的 EUC-JP**。

## 2. 容器 FPK

```
+0x00 u32 count | +0x04 u32 0 | +0x08 u64 total(==文件长)
+0x10 u32 0x20 | +0x14 u32 dataStart | +0x18 u64 0
0x20 起 count × 32B：name[16] + u32 size + u32 offset（4 KB 对齐）
```
校验 `0x20+count*32 == dataStart`（ADV.FPK：`0xF800` 精确命中）。
⚠ 嵌套 `E*.FPK`/`S*.FPK`（每事件一个语音包）头不同、正文高熵，**不要试图解**（试过 |0x80 解出全随机汉字）。

## 3. 脚本 VML

```
+0x00 u32 0x10 | +0x04 u32 ? | +0x08 u32 offTable 数 | +0x0c u32 size
指令 = u16 id + 00 FF
```

| id | 语义 |
|---|---|
| `0x66` / `0x67` | メッセージ枠 開始 / フラグ（1=通常, 0=字幕・扉文） |
| `0x64` / `0x65` | **話者名札**（u8 len + 同编码文本，例 `弘史`/`カズマ`）/ 名札なし |
| `0x68` | 正文行：`u8 len` + len 字节（**len 恒偶数**） |
| `0x69` | 枠内改行 |
| `0x6A` / `0x6B` | 主人公 **姓 / 名**（宏，无操作数） |
| `0x6C` | 強調スパン（arg `02`=start / `00`=end，**不产字符**） |
| `0x6D` / `0x6F` | 枠終了（6D 少見，20 : 15102） |
| `0x190` | 消息/语音 id（逐枠 +1，可当一枠一击的自证） |

**★ 编码**：`bytes(b | 0x80).decode('euc_jp')`。
⚠ **不要用 cp932 偏移（如 +0x5E7E）验证**：平假名会"看着对"，片假名跑成希腊字母（`0x83A9`=Λ）——
判据必须含**片假名**段。

## 4. 成行

- **一枠（`0x66`…`0x6F`/`0x6D`）= 一次点击 = 一行**：`0x66` 15,114 ≈ `0x6F` 15,102 + `0x6D` 20；
  一枠 1–6 个 `0x68`，总字数 ≤ 54（18 字 × 3 行窗口；>54 的 10 条是自动翻页）。
- 一枠内多个 `0x68` **直接拼接**（`0x69`/`0x6C` 不产字符）；仅 1 例无终止符（文件末，按 EOF 收）。
- 宏 inline：`0x6A→姓`、`0x6B→名`（本作 作上 / 明里；`私は[6A][6B]……え？` 一句即可定对应关系）。
- 收：正文＋扉文（`0x67=0` 的「……　数日後　……」）。
- 不收：`シャンパンコール中！□ボタンのスキップに注意して下さい。`（玩法操作提示 ×21，黑名单）。
- **选项是独立记录 `0x1F6`**（`F6 01 00 FF` + `u16 idx` + `u8 len` + 文本），题干枠之后连排、`F7 01 00 FF` 收尾：
  本作 **574 条 / 287 组（每组 2 个）**；`idx` 非显示序，按记录序输出。
  ★**不要在 `0x68` 里找选项**：首轮只扫 `0x68` 且用「操作数整体能否解成日文」筛（`F6` 前有 2B idx 必然解不通）⇒ 漏 574 条。
  新引擎先枚举全部 op id 的频次与载荷形态。

## 4.5 「独白（…）与台词同框」不要拆（本作 71 处）

`0x65`（名札なし）→ `0x68`「（ま、間がもたない……っ。）」→ `0x69` → `0x68`「あ、あの、お酒、好き？」→ `0x6F`
＝ **一屏两行、一次点击**，不是漏断框。全作 71 例：**台词在前＋独白收尾 66 例**（`こ、こちらこそ。（……だ、誰か助けて……。）`）、
独白在前＋台词在后 5 例。判据仍是「一框 ≤54 字（18×3）＋`66`≒`6F`」，内容形态不参与断框。

## 5. 跨文件顺序

无顺序表（flag 驱动）。按族 + 编号：`E####`（本编事件，E0000=序章）→ `NN_S9xxx`（01–12 章 ×20）
→ `S####`（個別場面）→ `EVE##` → `ED##`（各角色 3 结局，7×3=21）。同文件内＝精确显示序。
