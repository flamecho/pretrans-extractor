## 1. 容器链

```
NSP(PFS0) ──> 主 NCA ──hactool --titlekey──> romfs
```

- **NSP 取 NCA**：自己读 PFS0 头（`magic|u32 count|u32 strtab_size`，条目 `(offset,size,nameoff,res)`）。
  ⚠ `hactool -t nsp -l` 在本版是「显示 license」，会把文件名当 license 名 ⇒ 别用它列表。
- **titlekey**：优先读模拟器自动生成的（`%APPDATA%\eden\keys\title.keys_autogenerated`，跑过一次游戏就有），
  形如 `010024200E00A000000000000000000A = 41B4408B3CEF1FE37F8F290585730EDD`。
  ⚠ `prod_fixed.keys` 里的 `titlekek` 可能是旧值 ⇒ 自己用 ticket 0x180 块算出来的 key 全错（段报 `corrupted`）。
- **Eden/Yuzu 的 `prod.keys` 有畸形项**（`mariko_master_kek_source_XX` 34 位 hex、`bis_key_*` 64 位），
  hactool 会 `Key (...) must be 32 hex digits!` 直接崩 ⇒ **用 `prod_fixed.keys` + 正确的 `--titlekey`** 即可。

## 2. `.cpk` = 标准 CRI CPK（`CPK ` + `@UTF` 表）

条目**常常没有文件名**（`EnableFileName=0`），只有 ID `0x0000..0xNN`。

**@UTF 实测格式**（`scripts/cpk_cri.py` 已实现，直接复用）：

```
+0x00 "@UTF" | +0x04 table_size
之后所有 offset 均相对 base+8：
    +0x08 rows_off | +0x0c str_off | +0x10 data_off | +0x14 name_off
    +0x18 ncols(u16) | +0x1a rowlen(u16) | +0x1c nrows(u32)
+0x20 起列定义，每列：flags(u8) [+ name(u32) if flags&0x10] [+ const(u32) if flags&0x20]
    type = flags & 0x0F   (0=u8 1=s8 2=u16 3=s16 4=u32 5=s32 6=u64 7=s64 8=f32 9=f64 10=str 11=vlData)
string 表基址 = base+8+str_off
```

- ITOC 的列一般是 `(ID u16, FileSize u32, ExtractSize u32)`；**两者相等＝未压缩**。
- 条目**起止偏移要自己推**：从文件末尾按 FileSize 反向累加（`sys.cpk` 得内容起点 `0x16C86`）。
- `.xtx`（`xtx\0` 魔数，有时前面多 0x10 字节头）＝ **CRIWARE 纹理**，不是 Switch 的 NVTX，也不是正文。

## 3. `sn.bin` = `[u32 解压尺寸][LZSS 流]`

```
ring = 0x1000 B，pos 起点 = 0xFEE
每 8 个 token 一个 flag 字节（LSB 优先，1 = literal，0 = match）
literal : 1 B 原样输出，同时写入 ring
match   : 2 B → idx = b0 | ((b1 & 0xF0) << 4)（12 bit 环下标）
                 len = (b1 & 0x0F) + 3
           从 ring[idx..] 逐字节复制，**边复制边写入** ring[pos]
```

**闭合校验**：解出长度必须**精确等于**头部 u32。
现成实现：`scripts/utapri_as_extract.py`（函数 `lzss(src, size, start=4, wstart=0xFEE)`）。

## 4. 平铺结构（Repeat LOVE 实测）

| 区域 | 内容 | 收 |
|---|---|---|
| `0x0000–0x1800` | 全零 | — |
| `0x1800–0x3780` | **场景选择菜单表**（`プロローグ`／`音也４月`…`〜大恋愛ＥＮＤ`／`バック 音也 １`、`ファイル別実行／デバックＯＮ/ＯＦＦ`） | ❌ 系统 UI |
| `0x3780–0x437F` | 场景条目指针表（含 `4F 0D 00` 但**无 `45 FF FF` 锚点**） | ❌ |
| `0x437F–EOF` | 剧本流 | ✅ |

**剧本区起点要自校准**：取「第一条**带收框且含假名/汉字**的记录」的文本偏移，其前整体丢弃。
（`4F 0D 00` 在表区也会出现，纯靠 op 分不开。）

## 5. 记录格式（L0）

| 记录 | 字节 | 说明 |
|---|---|---|
| 开框 | `4F 0D 00 <flag u16>` | `flag=1` → 有名札；`flag=0` → 直接正文 |
| 名札 | `46 0D 00 <name> NUL` | **不进正文**；常带 `%C999` 色码前缀（剥掉才是人名） |
| 正文 | `45 FF FF <idx u16> <cp932 文本> NUL` | `idx` 是递增序号（**不是行号**，有跳号） |
| **收框** | `4A FF FF 6A FF FF FF FF 49 FF FF FF FF` | **一次点击 ＝ 一条记录 ＝ 一行** |
| 空框 | `4F 0D 00 xx 00` 后直接跟别的 op（无 `45 FF FF`） | 不是正文，跳过 |

成行判据 **L0**；框内 `%N` 是**软换行**，必须合并 ⇒ **单版**（本族各作都没有「同框多次点击」）。

## 6. 控制码与占位符（码位必须 `ord()` 实测）

| 码 | 含义 | 处理 |
|---|---|---|
| `%N` | **框内软换行** | **删（合并进同一行）** |
| `%C999` | 色码前缀（常在台词/名札前） | 删 |
| `%Z` | 样式前缀（**2 字符**，后接 `『`，不是 3） | 删 |
| `%YE` / `%Y` | 样式前缀，位于 `45 FF FF` **之前**，本就不进正文 | 兜底删 |
| `●●●` = `0x819C` | 主角**姓** | → 真名 |
| `○○○` = `0x819B` | 主角**名** | → 真名 |
| `■` = `0x81A1` | 另一种占位（本族少用） | 按册内实证 |

⚠ **别按想象记码位**：`○=0x819B`、`●=0x819C`、`■=0x81A1`。第一次按猜的码位统计全成 0。

## 7. 四个必踩的坑

1. **`flag=1` 不保证紧跟 `46 0D 00`** —— 实测有 9 处中间夹 `44 00 00 ..` / `10 xx xx ..`。
   ⇒ 名札要在 **24 B 窗口内搜**，找不到就按「无名札」处理，否则这些正文全丢。
2. **正文可能是纯标点或全角英文** —— `「……………………」`、`「！！！」`、`『ｍｙ　ｓｏｕｎｄ　ｎｅｖｅｒ　ｅｎｄ』`。
   ⇒ **不能用「含假名/汉字」过滤正文**（Repeat LOVE 会丢 117 条）；该判据**只能**用来标定剧本区起点。
3. **收框有例外** —— Repeat LOVE 有 5 条用 `43 07 00 00`／`2F 1E 00 45`／`2D 06 00 00`／`2F 78 00 10`，
   内容是正常台词（淡出/转场分支）⇒ **不能只用收框做过滤**，用「起点之后全收 + 非空」更稳。
4. **序章等段落会存两份**（Repeat LOVE: `0x438F` / `0x5DACA`，都叫 `序章`），20 行滑窗约 2% 在别处逐字重现
   ⇒ 默认**全量忠实交付**，去重版另出、不覆盖。

## 8. 交付前自检

```bash
python scripts/check_text.py "提取结果/<包名>.txt" --name <主角名> \
  --allow "解析报告/allow/<包名>.txt" --report "解析报告/<包名>_解析报告.md"
```

常见 allow 项：
- `#@open-quote`：**跨框引用**（开引号在本次点击、闭引号在下一次点击，常伴随下一框是 `　　　砂月」` 这种续尾）
- 评分播报类 `名前：本文` 形态（会被误判成「说话人前缀残留」）
