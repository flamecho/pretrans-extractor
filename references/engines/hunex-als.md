## 2. `.ALS` 结构
```
0x00 u32 = 0x20        头长
0x1C u16×2             逐文件不同（未解析）
0x20..                 16 位 opcode 流；操作数内可含 u32 字符串绝对偏移
末尾                    文本池：起点＝代码区**最后一次 `0D 02`** 之后
                       每条 = NUL 结尾 cp932；池尾 24 B 收尾（1B 标记 + 00 + 小整数）
```
- **不必走查 opcode**：池内串按编译顺序连续排列，**池序＝流程序**（选项组精确插在对应台词之后，可实证）。
- 池尾 24 B 会被读成单字串（`先`/`ｸ`/`n`）⇒ **只从末尾剥 1 字以内的尾项**；
  ⚠ 不能用「距文件尾 <40 B」之类的阈值——**末条正文可能就起始于末尾 40 B 内**（会误删 3 条）。
- ⚠ 池内可能出现**非字符串数据表**（如 scene67 的 `空/海/土` 单字表）夹在串流中 ⇒ 不能「遇单字即止」。

## 3. 文本记录

| 码 | 语义 | 处理 |
|---|---|---|
| `%K` | **待键**，每条消息恰 1 次（11,663/11,663） | 断行 |
| `%P` / `%p` | 点击后清框（台词） | 删 |
| `%N` | 清框（地の文）；行首＝先清框（有 `%N%N%N`） | 删 |
| `%O032` | 清框变体（数值 032），语义未解析 | 删 |
| `%n` | **框内软换行** | 合并 |
| `%IF0` / `%IL0` | 名 / 姓 插入宏（本作＝アンナ／ヒイラギ） | 替换 |
| `%L1` / `%T2` | 扉文模板 `%L1`＋`～　%T2　～`＋`%L1`（每文件池首） | 剔 |
| `├┤`(84A5 84A7) | 罫線素片；同族 `├─────┤` 证明是作者手绘装饰线 | 保留 |

- 行粒度：一消息＝一框＝一次点击（每条尾部必带清框码，0 例外；显示行数上限 3）⇒ **不需要「一框一行」第二副本**。
- 名札 `【名】` 在串首剥一次；85 种。
