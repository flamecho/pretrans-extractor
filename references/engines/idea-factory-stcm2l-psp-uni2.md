# STCM2 · CRI「UNI2」容器 —— PSP 样本（③ `D.C. Girl's Symphony Pocket` ／ ④ `アルコバーノ! ポータブル`）

> > PS2 侧样本（PANDORA・L2 Love×Loop）仍在原册；路由见 `../engines.md`。

- **★ 第 3 样本：`D.C. Girl's Symphony Pocket`（PSP `ULJM05690`，**Idea Factory** 2010-06-24）—— UNI2 ＋ 头串逐作变**
  - 容器仍是 `UNION/SCRIPT.UNI` = CRI **UNI2**，头与 PANDORA 同形（`u32@4=0x10000`、`u32@8=文件数=161`、`u32@0x0c=1`、`u32@0x10=3`），
    **FAT@0x800**（16B/条 `[FileID][startCluster][sizeClusters][sizeBytes]`，绝对偏移＝`startCluster*0x800`，第 1 数据簇＝15）。
    ★**头串不是 `STCM2L …` 而是 32B 的 `STCM2 File Make By Minku 07.0`**（magic 实为 `STCM2 `＋空格）⇒
    **identify/`magic` 检测会漏**，判型须自己看 `+PREFIX` 处 32B 生成器串。
  - 子文件 = `[0x1800 前置区][STCM2 @ +0x1800]`（同 PANDORA 的 0x1800，与 L2LL 的 0x2000 不同）。
    ★★**但 0x0000–0x1800 里放的不是本文件的表，而是「上一个子文件 opcode 链的溢出」**——
    实测 fid=100 的链终点 `0xA58FC` ＞ 自身末尾 `0xA42E0`，多出的 0x161C 字节正好落在 fid=101 的前置区
    （链在撞上「`EXPORT_DATA` 导出表」时因 size 非法自停）。⇒ **遍历终点取 `下一子文件起点 + 0x1800`**（与 L2LL 同源口径）。
    漏此 ⇒ **每个子文件开头丢一段正文**（fid=101 丢 32 条：孝明×史桜 洗衣物整场）。
    前置区之后依序是 `EXPORT_DATA`／导出表（`memory_init`・`memory_exit`）／`GLOBAL_DATA`／`CODE_START_`（+24＝代码段）。
  - ★★**记录解析必须「端锚定」**：`payload = [u32 addr][u32 style]*n [u32 0][u32 L/4][u32 1][u32 L][cp932 text][u32 0][u32 cmd][u32 flag]`。
    先读**末 12B 标记**，再反推 `k+16+L == len(payload)-12`。**本作 `L` ≠ `align4(bytelen+1)`**
    （实测 L 常大于对齐值）⇒ 沿用 L2LL 的 `A4(len+1)==L` 判据会**静默漏掉一批记录**（选项尤甚）。
  - ★**`k`（`[0]` 字段偏移）逐记录可变**（样式字段个数不同：2 个→12、4 个→20、5 个→24…）⇒
    **不能用 k 当类型判据**；用 `k + cmd + 内容` 三者合并。本作 k=12 上：
    `0xd2`＝正文**续行**(31,163)・`0xd3`＝正文**框末**(24,691)・`0xe7`/`0xd6`/`0x35`/`0x3d`/`0x9a`/`0x6f`＝**框末变体**(共 147)・
    `{0x0,0x33,0x64,0x96}`＝符号/系统串(`sureN`・`処理開始`・`screen`，剔)。**判据＝`k==12 且 cmd∉{0,0x33,0x64,0x96}` 即正文**；
    收行条件＝`cmd != 0xd2`。**选项**＝`k!=12 且 cmd∈{0xe6,0xe7,0xec}`（`select` 关键字 op 紧随其后）。
  - ★★**样式/参数区的 `0xFFFFFFFF` 哨兵会被误匹配成文本**：cp932 单字节 `0xFD/0xFE/0xFF` 被 Python 映到 PUA
    `U+F8F1/F8F2/F8F3` ⇒ 解出 ``（本作 408 处，**每文件恰好 1 条**，位置固定）。
    ⇒ **解码后凡含字节 ≥0xFD 一律丢弃**（cp932 合法字节仅 0x00–0xFC）。修前成品 `[E] 私用区 PUA ×408`。
  - ★**名札自举的字符集必须含全角数字**（`０-９`）：本作有 `女子生徒１/２/３`・`男子生徒１-４`・`３年女子`・`３年男子`
    共 8 种带编号名札，字符集不含数字 ⇒ 它们会被当正文并**拼进台词**（`女子生徒１「…」`）。
    本作名札 64 种 / 12,447 条丢弃，全部可比 vndb（13 名全中）＋泛称角色。
  - ★**行内『名＋「台词」』剥离须加「行尾必须是闭合引号」**：否则会毁掉「名字作句子主语」的行
    （`稜平くん（本当はくんなんて…）だって、黙って立ってれば普通に格好いいのに。`）；该条件把这类全部排除
    （残留 44 处经复核全为「句中引用」，非说话人）。⚠ 也可用「名札独立成条」路线（本作两种并存）。
  - ★**注音宏是 `#Kana[n,よみ]基底语`**（＝ruby）：**只删宏、保留基底语**
    （`「あ、#Kana[1,ゆう]悠くん？」`→`「あ、悠くん？」`；`#Kana[2,こじょう]古城先生`→`古城先生`）。全库无其它 `#`/`%` 宏。
  - ★★**同容器内混有整份『薄桜鬼』他作遗留**（本作 PSP 版由 **Idea Factory** 开发，引擎/资源复用）：
    `end_土方/沖田/斎藤/藤堂/原田/風間/ノーマル`（结局 CG 名单）・`序章〜終章`（章表）・`土方/沖田/…`（角色名）
    ＋约 600 条**剧情梗概／用語辞典**（`羅刹`・`鳥羽伏見の戦い`・`藤堂平助(とうどうへいすけ)`・`会津中将`・`油小路の変`）。
    **且整个 `UNION/SUB.UNI` 都是薄桜鬼数据**（队士告别台词＋读音辞典表）。⇒ **整段排除**。
    判据（零成本）：把「未收的日文串」全列出，**含本作人名的 0 条**；成品全文 土方/会津/新選組/幕末/沖田/斎藤 各 0 次。
  - 收/不收：**收** 正文＋选项(308)＋400–411 追加剧本（与主线去重仅 6% 重叠＝独立内容）；
    **不收** `SYSDIR/UPDATE/`（＝**PSP 主机固件更新器**，非游戏补丁）／`SUB.UNI` 与符号表内薄桜鬼遗留／
    纯 ASCII 场景标签（`op` 等 13 处）／系统 UI（`SYSTEM.UNI` 内 gzip 的 `ART2` 图像）。
  - 主角 **古城 史桜**（こじょう しおん，vndb **v969** role=main）—— **固定名**：正文全为字面名（`史桜` 1,168 行，
    含点名台词「起きなさい、出席番号１５番、古城史桜！」），**库内无任何名称插入宏**。本作**无用語辞典**。
    成品 **25,032 行** / `check_text.py` PASS。
  - 工具：`scripts/dcgs_extract.py`（定稿；常量 `FAT=0x800`・`PREFIX=0x1800`・`NON_DLG={0,0x33,0x64,0x96}`・`OPT_CMDS={0xe6,0xe7,0xec}`）。
    报告：`提取结果/解析报告/[PSP-JP]D.C. Girl's Symphony Pocket_解析报告.md`。

- **★ 第 4 样本：`アルコバレーノ! ポータブル`（PSP `ULJM05609`，Design Factory & Otomate／Idea Factory 2010-01-28，vndb v1415）—— ★判型改「槽数」**
  - 容器同 DCGS：`UNION/SCRIPT.UNI` = **UNI2**，`u32@4=0x10000`、`u32@8=239`、**FAT@0x800**、绝对偏移＝`startCluster*0x800`、
    生成器串 `STCM2 File Make By Minku 07.0`、**`PREFIX=0x1800`**。224/239 带脚本，15 个纯数据文件（fid 10–24）。
  - ★★**判型用「槽数 slots」＝ payload 前导 `[u32 值][0xff000000][0xff000000]` 三元组个数**（比 cmd 稳）：
    **slots=4**＝正文框（同框多串⇒合并为一行）／**slots=2 且 cmd∈{0xe6,0xe7}**＝选项／**slots=1 且 cmd=0xdf**＝名札（丢）；
    `cmd∈{0xd3,0xd8}` 与 slots=2 的变量/旗标表（cmd 0x00/01/05/32/33/35/67/0xffffff*）＝符号表（丢）。
    ⚠ **cmd 单独不足以判型**：`0xe7` 既是选项又是正文框、`0xdf` 既是名札又是旁白框、`0xd4` 还被旗标表复用。
  - ★★**串过滤不可用「须含假名/汉字」**：`「……#Name[2]。` 这类**纯标点＋宏**的串会被误删 ⇒ 整行被切断
    （修前 引号不配对 49 处）。判据改「**非纯 ASCII 即保留**」（纯 ASCII＝资源名/`sureN`/`screen`/`chapN`）。
  - ★★**前缀区（0x1800 内）另有一层记录**：形如 `[12B 槽×k][ [0][L/4][1][L][text] ]×n`，**无收尾 `[0][cmd][flag]`**
    ⇒ 与代码段分开，只走代码段会漏。**与代码段比整行重复率 74%（1,166/1,560 逐字相同）＝显示稿副本层** ⇒ 剔重，
    仅留代码段没有的 384 行（如 `「え！？　オレも、ここで研修していいの！？やった～～！！」` 全库仅此一处）。
  - **数据文件（fid 10–24）= `[u32 count][u32 8]` 头 ＋ 条目 `[u16 seq][u16 idx]<cp932>\0`（0xFF 填充）**：
    fid14=读盘提示／fid16-18=料理食谱步骤／fid10-11=内部旗标 ⇒ 判系统/UI **不收**；
    **fid19–24=剧情性文本（邮件正文＋角色语音/评论台词）⇒ 收**（每封邮件以 `＞<件名>` 起头，其后 `宛先：X`／`送信者：X`／`―――…`／本文行
    ⇒ ★**件名・宛先・送信者各自成行；同一件的正文行(软换行)合并为一行**；**不可把整封并成一行**（200~3000 宽巨行，用户 2026-10-18 否掉），分隔线判装饰不收）。
  - 主角宏 `#Name[1]`→**茅野**(姓)／`#Name[2]`→**夕菜**(名)，默认名表在 `SCRIPT.UNI@0xb600/0xb640`（`茅野`・`夕菜`）；
    实证 `#Name[1]#Name[2]。`（全名）＋`#Name[1]さん` ⇒ 1=姓、2=名。vndb v1415 `Kayano Yuuna`＝**茅野 夕菜**（Nameable）逐字一致。
  - 成品 **15,069 行**（正文 13,186＋选项 389＋前缀区独有 384＋剧情性数据表 1,202）／`check_text.py --name 夕菜` PASS。
    工具：`scripts/arcobaleno_extract.py`（定稿）。报告：`提取结果/解析报告/アルコバレーノ! ポータブル_解析报告.md`。
