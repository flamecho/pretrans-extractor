# Plan Peace / InterOne 自研「PCT」——`data.dat` ＋ `pct_mess.dat` ＋ `script_*.dat`

> 2026-10-17 立（**Solomon's Ring ～地の章～**，PSP `ULJM06200` 系，CHD v5/zstd）。
> 同系列另有 水の章／緋の章／風の章（`.zip`），链路应一致，**但同族逐作必回查**（§5）。

## 1. 容器 `PSP_GAME/USRDIR/data.dat`（只有一个数据文件）

- 表头 = **扁平 `[u32 offset][u32 size]` × 14592**（0x1C800 B），**无魔数、无名字**；
  首条 `offset` 恰等于表尾、条目按 offset 升序、`max(offset+size) == 文件大小` ⇒ 三条同时成立即可定表长，不必猜。
- 条目 `0..163` 是内部表（0=小配置、1=**路径名表**、2=**说话人名表**、16 起是纹理…）。
- `size==0` 的槽 = `data/dummy.dat`（本作 10,519 个），扫库时先滤掉。

## 2. 路径名表 = 条目 **#1**

- `[u32 n=14428][u32 pad]` ＋ n×u32（偏移，指向池内）+ 池；
- 记录格式 `[u32 1][u32 0x0c][u32 L][u32 L][name…\0 pad]`（名从记录 +16 起，**靠 `01 00 00 00 0c 00 00 00` 模式扫**最省事）；
- ★**名字表按文件名排序，与条目存储顺序不一致**，存在固定偏移 Δ。
  **定 Δ 的零成本办法**：对每个候选 Δ，算「条目内容以 `RIFF` 开头」与「名字以 `.at3` 结尾」的一致率，
  取最大值（本作 **Δ=10**，一致率 3909/3909 = 100%）。⇒ 之后 `entry = name_idx + 10`。
- 本作资源分布：`.at3` 3,489（语音/BGM）、`.dat` 10,557（多为 dummy）、`.pak` 336、`.tx` 37（纹理，头 `xt.00.1`）、`.arc` 5（特效）。

## 3. 正文：`data/pct/e/pct_mess.dat`（唯一天然语言载体）

```
u32 n            ; 11857
u32 pad          ; 0
u32 off[n]       ; 首值 0x1c，单调不减，末值 == pool_size-3
pool             ; cp932，NUL 分隔不存在，末尾 3 字节补零
base = 8 + 4*n
段 k = pool[ (k==0 ? 0 : off[k-1]) : off[k] )      ← 注意 off[0] 不是第一段的起点
```

- **一段 = 一个文本框 = 一次点击**（不是「行」）；段内 `0x0A` = 框内软换行 ⇒ **合并**，续行行首 `U+3000` 是显示缩进，剥掉后直接拼接。
- **无控制码、无名札标记、无 `%s`/`Name[n]`**；台词用 `『』`（旁白里嵌台词）、`「」`（当前说话人）。⇒ §0 的「不加说话人前缀」天然成立。
- 主角名 **リリー** 直接写在池里（且常以 `『リリー』` 出现，是原文写法，不是宏）。
- 末段会带池尾 3 个 `\0` ⇒ 解码后 `.strip('\x00')`。
- 规模自证：11,858 段 / 259,686 字；主脚本引用到的 u32 索引覆盖池 **81%**（9,594/11,858）。

## 4. 剧本 `data/pct/e/script_*.dat`（38 个，纯字节码、零日文）

- 头 `[u32 script_id][u32 0x28][u32 ×8 指针]`，指令流自 `0x28` 起，按 **u32 对齐 token**；
  含 `0xffffffff`（=无目标）与 `0xffffXXXX`（低位像索引）⇒ **本作未做完整 VM 还原**（见 §5 取舍）。
- `script_000000.dat` = **开发用测试脚本**：其文本块（池索引 159–171）为
  `１を選んだ` / `波演出` / `波演出中` / `０１２３…` 数字列 / `選択肢文１〜４` ＋ `どうする？` ⇒ **整块剔除**。
- 其余：`000100` = 主线（507 KB，覆盖全篇）、`0010xx` = 分支小场景、`0020xx` = 尾声。

## 5. 取舍：**不做 VM 还原，直接按池序出文本**

- 池序 = **场景编译序**（主线顺序叙事、分支场景原位插入），实测 0→11845 通读连贯（序章→祭り→アモン线→ルシファー→レラージェ线收尾）；
- 因此**不解析脚本也能得到正确阅读序**；代价是：① 无法把选项打上标记（选项本就是独立段，按序输出已符合 §0）；
  ② 多分支并存时按「先 A 后 B」顺序排列，无法还原互斥关系。
- **换作（水/緋/風の章）时**：先按 §2 的 Δ 法复算偏移，再确认 `pct_mess.dat` 是否仍为唯一 JP 载体（扫全库 JP 比 >0.3 的条目）。

**★名表扫描法修正（本作得出，通用）**：`01 00 00 00 0c 00 00 00`（水の章用法）**会漏掉 `pct_mess` 等 `0xff` 开头记录**。
改用 **`0c 00 00 00` ＋ 紧随两个相等 `u32 L` ＋ 名字含 `/`** 扫，本作一次取全 **10,586 条 == `u32[0]`**（零漏零多），
且 `pct_mess`(名序 346) 与 `script_000000`(347) 两条锚**同给 Δ=9**（非单点巧合）。
⇒ 今后定 Δ：**先按新法整表导出名序，再多锚交叉验**；只有名表真读不出（緋の章）才退回内容判型。
