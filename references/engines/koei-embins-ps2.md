# Koei PS2「EMBINS.VVV」单模块镜像（アンジェリーク トロワ 系）

> 路由/一句话索引见 `../ENGINES-3.md`；主索引见 `../00-index.md`。
> 首见作品：**アンジェリーク トロワ（PS2, SLPM_620.22, 2000-11-22, Koei/Ruby Party）**。
> 与同厂 `koei-pack-ps2.md`（エトワール, 2004「HD/BIN + PACK」）、`koei-cdar.md`、`koei-pasc.md` **均不同族**。

## 1. 盘面

```
ISO9660（本作是 CD：MODE2/2352 裸 bin，剥 24 B → 2048）
├─ SYSTEM.CNF → BOOT2 = cdrom0:\SLPM_620.22
├─ SLPM_620.22        主程序（MIPS ELF，单 PT_LOAD：file 0x4000 → vaddr 0x100000）
├─ EMBINS.VVV  9.2 MB ← ★正文＋脚本代码
└─ DATA/  INIT.DAT / STATION.LZC / *.DAT / VOICE0..1,BGM,SE,BG,CATDATA,IKUSEI,STORY,MOVIE.VVV
```

- **不要被 `STORY.VVV` 误导**：那 4 MB 熵 7.78、假名命中 6 处 ⇒ 图像/压缩块，不是剧本。
- 定位法：对整盘 ISO 扫 cp932 连续平假名（`82 9F..F1`×2）密度，正文会形成 10 MB 级单峰。

## 2. 载体结构（EMBINS.VVV）

- 名称＝**EMB**edded **INS**tructions：整个文件是「MIPS 代码 + rodata」镜像。
  - 0x000–0x11FF 代码（`2d 18 a0 00`=daddu、`f0 ff bd 27`=addiu sp,-0x10）
  - 0x11C0–0x12EF 指针/常量区（含 `bad_alloc`）
  - **0x12F0–0x8C3504 = cp932 串池**（≈9,190 串，NUL 结尾，串间无对齐）
- 串池是**明文**，不压缩不加密，无 0x01–0x1F 控制码（串内只有 `\n`）。
- 一条串 = 一个 message box = 一次点击；框末 `\n\n`；未完句框以单 `\n` 结尾。

## 3. 名字槽（本族最关键的一条）

主角名不写宏，而是**把句子在名字处切成两段、中间留 1–16 B NUL 空位**：

```
そうか…  \0×8  邪魔したな。\n\n
```

- 空位可含**单个 `\n`**：`…お前のことを…\0×7 \n \0×7 、という名で…`（即 14 B 名＋分隔的形态）。
- 判据（两条同时成立才填名，否则按换框）：
  1. 1 ≤ 空位 ≤ 16，且只含 `0x00`（允许一个 `0x0A`）；
  2. 下段首字 ∈ `。！？、」』）`，或 ∈ 助词 `のとはがをにもでへやか` 且上段末字 ∈ `（　、…「`。
- 反例（**不要**一律填名）：`胸が…\0×2 痛い…。`、`そうか…\0×8 邪魔したな。` —— 下段以普通语汇起头 ⇒ 是两个框。
- 助词判据**只在上段以 `（`／`　` 收尾时**成立；上段以 `…`／`、` 收尾而下一段以助词开头，多半是另一句
  （`ジュリアス様…` ／ `はい。` ⇒ 误插成 `ジュリアス様…アンジェリークはい。`）。
- 本作实测 **1,514** 槽（收紧前 1,927，去掉 400+ 误插）；默认名 **アンジェリーク**（アンジェリーク・コレット）。字面名全篇仅 7 处。

## 4. 选项块

判据 A（单换行结尾）：**单个 `\n` 结尾 + ≥3 行（≤6）+ 第 2 行起全部以全角空格 0x8140 开头** ⇒ 第 1 行＝问题，其余＝选项。
判据 B（双换行结尾）：**首行是完整问句/心声（以 `？…。` 收尾）+ 选项 ≤3 条 + 首行不以 `「『` 开头** —— 全篇 407 块。
⚠ 不符合 B 的 180 块是「一句话被折成 3 行」的叙述（首行不以句末标点收尾 / 以 `「` 开头），**别拆**。
⚠ 问句本身可能折行：按「括号未闭合就并下一行」把 Q 拼回来，再切选项。

```
雪祈祭を知っているかって…\n　はい、知っています\n　いいえ、知りません\n
```

- 选项非独立串、也不是 `・` 列表（例外：姓名问答里写成 `　\0・コレットよ！`）。
- 另有 `％`（U+FF05）在选项尾/句中作心情记号，**不是控制码**，别删。

## 5. 成行

| 情形 | 处理 |
|---|---|
| 普通框 | 框内各行 strip 后合并为一行 |
| 半句残片 | 上段未以 `\n` 收尾 且（`（` 未闭合且下段含 `）`，或上段末字 `　`／`（`）⇒ 并入同一框 |
| 跨框 `「」` | 未闭合 `「` 行并入下一行（72,901→72,844 行） |

## 5b. ★ 禁链式合并（2026-10-18 用户指出的返工点）

本作有大量**并列变体表**（同一前缀配 N 条后缀，按分支各存一条）：

```
（そうだわ、これは\n　X様からいただいた物…\n　      ← A：以全角空格收尾的残片
…これは、Yから贈られたものではないのか？…\n\n     ← B：完整框（且 A(k) 与 B(k) 在文件里是 B 在前）
```

- 症状：若「残片合并」允许**链式**（合并后的记录再参与下一轮合并），14 条 A 会被串成一行 365 宽的粘连。
- 铁律：**① 残片合并必须「上段 `（` 多于 `）`」且「下段含 `）`」才合**
  （只凭「上段以 `　`／`（` 收尾」会并掉两条各自闭合成句的心声，实例
  `（これで最後…。アルカディアは消えてなくなってしまう）` ／ `（私の宇宙に突然現れて…）`）；
  **② 合并过的记录不得再合并**；**③ 名字槽的并列变体不合并，而是每条都补回「前缀＋名字」**。
- 判据的副作用要接受：变体表里配不上对的后缀会以 `、`／`。` 开头（本作 1 行），**不猜配对、各自成行**。
- 补一条窄规则：**双换行结尾 + ≥2 条缩进行以 `）` 收尾 ⇒ 带括注的选项块**（全篇仅 1 例：
  `好きな人…／いるわ（…内緒よ）／いないわ、そんな人いるわ（…あなたよ）`），选项按「以 `）` 收尾」切分。

## 6. 源数据固有的不配对（别去补）

- `EMBINS.VVV` 原始字节：`（`=628 / `）`=403、`「`=1446 / `」`=1448。
- 成因：**心声每框都重新以 `（` 开头**，只在整段思考末框补 `）`；另有分支重复写法（同一句存 7 份，都不补 `）`）。
- 结论：`check_text` 会报 2 项 `[E] 引号不配对`，属**原文如此**，按「不改写」保留并在报告留证。
