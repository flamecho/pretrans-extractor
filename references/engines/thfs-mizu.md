# KID 自研 `THFS` 归档 ＋ `%` 控制码脚本（水の旋律 PSP/PS2）

> 作品：**水の旋律**（PS2 2005-09-29 ／ PSP 2009，KID，vndb **v855**）
> 工具：`scripts/mizu_extract.py`；报告：`提取结果/解析报告/水の旋律_解析报告.md`

## 1. 容器（`GAMEDATA.DAT`）

```
0x00 "THFS"          magic
0x04 u32 total_size  ＝文件大小
0x08 u32 entry_count （本作 3372）
0x0c u32 0
0x10 8B  hash
0x18 条目 × N（64 B/条）

条目：name[32] NUL 填充
      pad[8]
      u32 offset   绝对偏移（数据按 0x800 对齐）
      u32 size
      u32 0        （压缩尺寸占位，本作全 0 ＝ 未压缩）
      u32 size2    （＝size）
      8B  hash
```

- `PACK.DAT` 同格式（只装 ICON0_1.PNG / PIC1.PNG）。
- 表末 `0x34B18`、首数据 `0x35000`（与条目自洽）⇒ 无需扫描。
- 全库 **1 个 .DAT**，无二级容器；无加密、无压缩。

## 2. 脚本

- 扩展名 `.BIN`；头 `20 00 00 00 …`（32 B），其后＝指令流（`u16 opcode ＋ 变长操作数`，**本作无需反汇编**）。
- **字符串＝裸 CP932，以 `00` 结尾**；串内无 NUL。
- `JIS2UCS.BIN`（131,072 B）＝ 64 KiB 完整 cp932→UTF-16 表 ⇒ **不存在自建码表/字形槽**。

### 文件命名（＝章节/路线/场景）

`S{章}{角色码}{类别}{编号}{后缀}.BIN`、`EV{nnn}.BIN`（事件）、`MR{nnn}.BIN`（短篇）、
`MAIN{nn}.BIN`（系统消息）、`DATA.BIN`（名札表＋系统表）。
角色码实例：`SHU`（愁一）`KEI`（圭）`KEN`（憲吾）`TAK`（貴人/拓哉）`ANI` `KYO` `HAN` `TET` `KUS` `SHI` `MIZ`。
排序＝自然序（章号→角色→场景号→后缀），与字节内顺序一致（脚本内另有 `18 0e` 索引表，addr 递增）。

## 3. 控制码

| 码 | 语义 | 处置 |
|---|---|---|
| `%K` | 换行 | 删（一框内软换行合并） |
| `%P` | 上屏等待（**页尾**） | 删，页边界 |
| `%p` | **选项前的最后一页** | 删；其后连续串＝选项 |
| `%N` / `%n` | 硬换行（歌谣/信纸） | 删 |
| `%W` | 停顿 | 删 |
| `%O<num>` | 特效/信纸段尾 | 删；该串＝**直接上屏特效** |
| `%S<num>` `%LC` `%FS` `%FE` | 字体/窗口开关 | 删 |
| `%R<num>` | 日期/数值引用 | 仅系统串，不收 |

⚠ **清洗正则必须支持双字母码**：`%[A-Za-z](?:[A-Za-z]|[0-9]{0,3})`。
只写 `%[A-Za-z][0-9]*` 会把 `%FS` 的 `S`、`%LC` 的 `C` 留在正文里。

## 4. 成行（★本作两个关键点）

1. **页有两种物理形态**：
   - 内嵌：`【陽菜】「…」%K%P\0`
   - 分离：`【拓哉】「それは……痛ッ……」\0` ＋ `%K%P\0`（控制码单独成串）
   ⇒ 只按「串尾匹配」扫会漏第 2 种。
2. **选项**：`%K%p` 之后、**不带任何尾码**的连续文本串，每串＝一个选项。
   可以是**无平假名短句**（`体育館`、`１年生の教室`、`ホラー映画`）⇒「含平假名才算正文」的判据会把选项全丢。
3. 名札 `^【名前】` 剥除；**名札独立成页**（剥完为空）整条丢弃。

## 5. 排除

| 载体 | 理由 |
|---|---|
| `DATA.BIN` | 名札表（57 种）＋系统消息表，**无 `%K%P` 页** |
| `MAIN00/01/02.BIN` | `エラー`、`%D月%D日(%s・%s)` 等系统消息 |
| `DMENU*/DBG*/INIT/SHORTCUT/JIS2UCS` | 菜单 / 调试 / 初始化 / 章节选择 / 码表 |
| `*.CFG`（ALBUM/MUSIC/MOVIE/CLRLST/PRINT/DOWNLOAD/SYSTEM） | 画廊、音乐鉴赏（曲名）、结局列表、他作下载推荐、设置 |
| 剧情文件**尾部署名字库** | `瑞紳/瑞心/瑞仁/瑞芯/瑞星…`、单字 `帥/芯/染/跡` ＝ 玩家命名候选，不在叙事画面 |

## 6. 化け判别（二进制巧合解出合法 cp932）

症状：`%/弸ﾂ`、`@H姆ｷ`、`瑞ｴ`、`繊ﾑ+A` 之类短串混入。
判据（三条同时）：① 含**半角假名**（U+FF66–FF9F）⇒ 化け（本作正文不用半角假名）；
② 以 **ASCII** 起始 ⇒ 命令残余；③ 无平假名却含 2 连以上 ASCII ⇒ 化け。
本作按此剔除 386 条，`check_text` 由 FAIL 转 PASS。

## 7. 结果

403 脚本 → **24,212 行**（正文 23,798 ＋ 选项 404 ＋ 上屏特效 10）；0 未解析。

## 9. 名字宏（★先替换再判文本）

- `%IL0%IF0` 连用＝全名 `柏木きら`；单用：`%IL0さん`＝柏木さん、`%IF0たち`＝きらたち。
- 默认名来源：`DMENU*.BIN` 的名字输入初值「きら」＋`S1HAN01A.BIN` 的 `%IL0　%IF0` 确认页。
- ⚠ 若在 `is_text_seg` 之后才替换，`ASCII2` 判据会因 `%IF0` 里的 `IF0` 把整页判成化け ⇒ **sanitize 内即替换**。

## 10. 载体内「非正文」的三类

1. **无 `%P` 尾的数据表**：`S1HAN01A.BIN` 段 3457〜 的名札表 + 場所名表（`尚和高校・正門前`…）；`S1FUG…` 的选项副本。
   ⇒ **只认 `%P`/`%p` 收尾的页**；连续无尾串（>3 段）判数据表丢弃。
2. **战斗结算开发块**（每战斗脚本尾，或中段）：
   `クリアリスト画面に戻ります` ／ `（＋１）` 选项副本 ／ `%CFF888康秀好感度 +%D （%D）` ／
   分岐コメント `選択で康秀を選択した場合…`・`好春と会ったフラグＯＮ` ／ `いいよ（横恋慕フラグＯＮ）`（注记剥、选项留）。
   ⚠ 该块的 `…%K%p` 是**后续选项的页标记** ⇒ 文本丢但 `opt_mode` 要置位。
3. **`BATTLE.BIN`**＝战斗 UI（`次へ`/`メンバー人数`/`合体（連携？）`）⇒ 整文件排除；
   `BTL_MES1-4`＝**战斗事件台词（要收）**，按非章节内容排到全文末尾。

## 11. 段首二进制残留

战斗/选项段常带 8~12 B 残留（`01 04 xx 07 05 02 05 02 0d 02`）⇒ `sanitize()` 取第一个可完整解码、且以日文/引号起头的起点。
**不要**加「前一字节不得是 2 字节前导」的限制：残留末字节可能是 `0x83`，会把 `昭和レトロ通り` 切成 `ロ通り`。

## 12. 外字槽（保留未改）

`③`(0x8252) 48 处均在句尾（`は～い③`）⇒ 字体侧疑为 ♪；`⑱`(0x8261) 5 处见 `羅⑱星`（＝羅睺星）⇒ 疑为外字。
字体未解析，**原文码位保留**，报告单列待人工确认。
