# 引擎专项（STCM2L）与定序法

> 通用逆向套路见 `S4-structure.md`。

## 1. STCM2L（Idea Factory）—— 平台 × 作品各不同形态，别照搬

同一作系**每平台、每作都要重新求证**：
**PSV 侧已实测 4 个互不相同的变体**（A Norn9＝UTF-8＋逐文件 Δ ｜ B RE:VICE[D]＝**CP932**＋**opcode 固定** ｜
C PsychicEmotion6＝UTF-8＋Δ≈0 ｜ D ROOT∞REXX＝**CP932**＋**opcode 固定**＋**文本记录内联在指令自身**＋**独立选项 op `56856`**）
—— **换作必回查 opcode / 编码 / 选项 / 换框机制**（详见 `S3-wsc-ops.md`）。

| | PS2（PANDORA） | Switch（猛獣） | **PSV（Norn9 Act Tune）** |
|---|---|---|---|
| 编码 | CP932 | UTF-8 | **UTF-8** |
| 指令 | `[u32 size][payload(size-4)]` | 同左 | **`[is_call][opcode][nparams][length]` + nparams×`[p0,p1,p2]` + data** |
| 文本 | payload 内 `[addr][c1][c2][0][L/4][1][L][text]` | 同左 | **p0 局部指针 → 数据区 `[0][L/4][1][L][text]`** |
| 换行 | 12B `[0][cmd][flag]` | msg desc `0x14058` / node id | **builtin `0x1f4`（等待点击）** |

> ★★ **Switch 侧亦「每作不同型」—— 已实测 ≥4 种互不相同的记录框架**（2026-10-16 补）：
> ① 猛獣＝`0x14058` 消息描述符；② BLACK WOLVES SAGA＝`0x61` 串对象（判型 `u32(i-0x18)==0x61 & u32(i-0x10)==0x10 & u32(i-0x0c)==0 & u32(i-0x04)==1`）；
> ③ **Glass Heart Princess＝「节点 3 型」**（k=1 头44B 正文/话者名 ／ k=2 头56B 选项・`switch` ／ k=3 头32B 变体台词列表＋裸记录续行；
> 框分隔记录 `[0][0x1F4][0][0x10]`；类型指针跨文件稳定⇒**全库聚合分类**）；
> ④ **ニル・アドミラリの天秤 色ドリ撫子＝「头长 28+12k」统一式**（**CP932**；`k=1` 头40B＝正文/话者名、`k=2` 头52B＝`switch`/`select`/シーン回想タイトル表、
> ★**`k=3` 头64B＝选项**；框分隔 `[0][0x4BB][0][0x10]`）—— **换作必回查，前作判据一律不照搬**。
> ⚠ ★★ **「尾部签名同、头长不同 ⇒ 必做 k 泛化扫描（k=1..6）」**：只扫 k=1/2 会把 **k=3 的选项整块丢掉**
> （ニルアド实证 525／569 条全失）。泛化签名＝`u32(iL-8)==L/4 & u32(iL-4)==1 & u32(iL-12)==0 & u32(i+16)==u32(i+20)==0x40000000`（`iL=i+24+12k`）。
> 细节全在 `S6-typing.md`（含 span 算错 4B ⇒ 整库不合并、续行遇节点起点即停、通用样式宏顺序）。

### ★★ PSV 版：每文件 opcode 有常量平移 Δ（最大的坑）

- **导入函数 ID 整块平移**（Δ = 0x10 的整数倍；实测 Δ ∈ {0,±0x10,0x30,0x40,0xe0,0x120,0x150}）。
- **builtin 不随 Δ 动**：`0x1f4`(wait) / `0x6`(goto) / `0x3`(Mif) / `0x0` / `0x11` / `0x12`。
- **Δ 检测**：把「含日文串的 opcode」按**平均字符串长度**排序取最大者为 `text_op`，
  `Δ = text_op − 0xcf9c`。**别用出现次数**——正文极少的文件（如 Norn9 的 5001–5010）flag 串反而更多，会选错。
- 归一化（Δ=0 基准）：`0xcf9c`=文本 push / `0xd698`=人名 push / `0xe090`=选项（p0=文本,p1=目标标签）/
  `0x236c`=章题标识 / `0x5414`·`0x4b24`·`0x4cfc`·`0x4ed4`…=flag。

### ★ 互斥分支 = 同一次点击的多版本（结构识别，不靠相似度）

编译器把 `if/else` 两版正文**相邻排放**，以 `goto`(0x6) 分隔；且 **「then 版」的 `0x1f4` 后面紧跟 `goto`**（跳过 else 版）：

```
[cond] Mif → ELSE
  [文本 A] … 0x1f4 ; goto → END      ← A 结束、跳过 B
ELSE:
  [文本 B] … 0x1f4                    ← B 结束
END:
```

⇒ 合并规则：**`goto` 断「段」不断「点击」；`0x1f4` 若下一条是 `goto` 也只断段**；否则断「点击」。
同一点击内多段取一：**优先不含 `#Name[` 占位符者，其次取最长**（＝直写名版）。
若只按 `0x1f4` 断行、不识别 `goto`，同一句会输出 2–3 份（`#Name[n]` 版 / 直写名版），即「差一两个字的重复行」。

### 每文件开头的「共通导入块」

Norn9 的 88 个 SCRIPT 文件**各自开头重复同一段 5 行导入**（`プロローグに新たな選択肢が追加されました`
＋4 行世界观），逐文件计会重复 88 次 ⇒ **只保留一次置全文最前**（判据：被 ≥8 个文件作为开头重复的块）。

## 2. 定序：先找「顺序表」，再考虑解释器（Orfleur/DCVM 案例）

**结论**：弦乐上「一次点击 = 一行」的顺序，**优先在容器里找一张顺序表**，而不是写 VM 解释器。

自研 VM（dramatic create「Orfre」/ `DCVM`，PSV オルフレール）的段序：
`DCVM > STOR > PTBL > PSTR > [VTBL] > FTBL > CODE > STR > STBL`

| 段 | 语义 | 能否定序 |
|---|---|---|
| `STR ` | NUL 分隔字符串池 | ❌ **按类型分组存放**（旁白→心声→对白→资源名→符号名→语音→章题→选项） |
| `CODE` | 栈式 VM 字节码（`<args>; PUSH <funcid>; CALL`；跳转 `PUSHIW <imm>; JMP*`，目标 `code[imm+0x14]`） | ❌ 引用序＝按池序遍历（注册） |
| **`STBL`** | `u32[size] + u32[count] + count×u32[offset]` | ✅ **＝编译发射序＝显示序** |

- **偏移基准**：`字符串 = data[STR_off + 16 + offset]`（即 `strd[offset+8]`，`strd = data[STR_off+8 : STR_off+size]`）。
  ⚠ 基准是「STR 段 tag 起点（含 8B 头）＋8」，**差 8 会从 236/236 掉到 5/236** ⇒ 用 δ 扫描定。
- **行首判定**（显示文本）：` ` / `　` / `「` / `（` / `―`（扉文·章题卡）/ `『`（信件）；选项＝含 `\n` 的连接串（逐条成行），
  紧随 `選択肢` 的同名副本丢弃。**丢弃**：名字札 / 资源路径 / `aa/nnnn` 语音 / `bgm*` / API 符号名 / 系统串 / `回想:XXX` / 裸章题（元数据）。
- **场景顺序**：另有「流程桩」块序列给出脚本流程序（各桩含 1 条副本名），正文块与之一一对应；
  正文块内还含**下一条**副本名（流程指针），可自校验对齐。
- **反面教材（别重走）**：代码引用首现序 / CFG 访问序 / 按 funcid 分组 / 8B 步长链 / `STOR` 分段 / 线性走链 / 语音 id 定序
  —— 全部实测无效，**根因就是池被排序**。识别信号：首现序单调递增（≈0.99）、分组 sorted-ratio 0.55–0.88。

### ★ 「长度自定界命令流」与「消息号定序」（MZ 命令流）
`[u16 op][u16 a]` ＋ (a-1)×u32 ⇒ **走查须精确到 EOF（`delta=0` 即格式确认）**；正文 op **首字段＝全局消息号 ⇒ 升序＝显示序**（同 §2）。

**池「排序存放」⇒ 别急着写 VM 解释器，先找同容器的「顺序表」**（＝编译发射序＝显示序）
- 止损信号：`<id>;STR` 首现序单调递增（比值≈0.99）／按调用目标分组的 sorted-ratio 0.55–0.88 ⇒ **立刻停手**，别再往解释器方向加码。
- 正解＝容器里另有一张 `u32[size]+u32[count]+count×u32[offset]` 顺序表（Orfleur 的 `STBL`：562 块 122,212 条偏移 **100% 命中**）。
- 验收：按顺序表排出的序列须成篇（截图/他平台译文锚定一两句）。案例见 `S4-stcm2l-cases.md`。

**表内偏移「基准」常是段 tag 起点 ⇒ 用 δ 扫描一秒定基准**
- 症状：映射命中率极低（5/236）但数值范围明显落在数据区 ⇒ 对 `δ∈[−8,+8]` 统计 `(offset+δ)∈字符串起点`，哪档 100% 命中就是它（Orfleur δ=+8）。**先做单位置扫描，再谈语义。**

**交叉验证：跨平台/跨版本同作是最好的标尺**
- 章题·语音 id·场景名常同名（PSV `ad01-02v` ↔ PC `ad01-02.snr`；`(AD1092)` ↔ `ad/ad1092`）⇒ 可作定序标尺＋**行数比验证**（本作 1.00：22,250 / 22,142）＋定位漏提。
- 汉化补丁可从作者仓库取；raw 被墙走 `api.github.com/repos/<owner>/<repo>/contents/<urlencoded path>`（base64 `content`）。

### PSP「CRI CPK」第三样本：ガーネット・クレイドル ポータブル（2011 SPICA／オトメイト）

- **同族同平台也已三变体**（SBL／アーメン／本作）⇒ **cmd 集必须重统计，别套前作**：
  `0xd4`＝**说话人框开始**（带脸参数）／`0xd2`＝正文片段 **或名札**／`0xd3`＝片段+框末／`0xe7`(1 槽)＝框末变体／
  **`0xe7`·`0xec`(2 槽)＝选项**／`0xe6`・`0x33`+'select'＝选项组终止。
- ★★ **「槽数」是本族最强判据**：正文/名札＝1 槽、选项＝2 槽（アーメン 靠 cmd、本作靠槽数）。
- ★★ **名札＝结构判定，零内容猜测**：`0xd4` 与「其后**紧跟**的那个 1 槽 `0xd2` 文本 op」全库 **19,461:19,461 严格 1:1**
  ⇒ 该 op 即名札（丢、不加前缀）。判据自证：名札位置**无一以 `「` 开头**、>8 字仅 15 例且全为 `X・#Name[1]`。
  反例：未命名框不带 `0xd4`（`[0xd2 空][0xd3 正文]`／`[0xd2 7 槽脸部][0xd3 正文]`）⇒ 不会误当名札。
- **扉文/章题卡**：非文本 cmd 的日文记录 **且其后 1〜3 op 内有「≥5 槽 + 记录以 `IMG`/`BG` 开头」** ⇒ 收一行。
  ⚠ 同一批标题若在「路线跳转表」里**成组**出现（各路线设一次再统一画一张菜单图）⇒ 非扉文，判据自然排除。
- ⚠ **`#Name` 必须「先替换宏、再剥 `#Color/#Kana/...` 标签」**：先跑标签正则会把 `#Name[1]` 整段吃掉 ⇒ 名字变空（`『』`）。
- ⚠ **`FF FF FF FF` 记录＝空串**：cp932 把 `0xFF`/`0xFE` 解成 PUA `U+F8F3`/`U+F8F2` ⇒ 看着像「未解码」，
  实为**空文本占位**，剔除即可（`〔未解析〕` 只留给真解不出的字节）。
- 实例：`scripts/garnet_extract.py`；成品 30,235 行 PASS（`engines/idea-factory-stcm2l-psp-cpk-amen-garnet.md` §③）。

### ★★★ `0x1F4`(wait) = **段落末等点击**，不是「每句点一次」（2026-10-26 KLAP!! 实证）

**症状**：成品出现「一行 186 字、6 组 `「…」`」的多角色台词合并行。

**代码形态**（KLAP!! NS，`story01/SCRIPT/191.DAT`）：

```
0x43B54 argc=6 [b-sos_a102,…]   ← 立绘/表情设置（换角色）
0x1EAE4 argc=2
0x13BF8 NAME  壮介               ← 说话人名札
0x1348C BODY  「やるじゃねーか。ちっと見直したぜ？」
0x6108 switch / 0x0 end
0x43B54 argc=6 [b-sho_a105,…]   ← 换成另一角色立绘
0x13BF8 NAME  明人
0x1348C BODY  「センセーにしては頑張ったんじゃない？
0x1348C BODY  　ナイスファイトだね」    ← 同句换行（两条记录**直接相邻**）
   …（カミル/奏/紫苑 各一组）…
0x1F4 CLICK                            ← 整段只这一个
```

**判据**：
- `0x1F4` 出现 ⇒ 段落末，等一次点击后**清/续**；
- 段落内**没有 `0x1F4`** 但每句前有 `NAME`（换说话人）+ `0x43B54`（换立绘）⇒ 实机是「一次点击后文本**逐条替换**、立绘逐个登场」，玩家看到的仍是**一句一屏**；
- ⇒ **一条正文记录（`0x1348C`）＝一次文本更新＝一行**；只有**两条正文记录直接相邻**（中间零 op）才是「同句被框内换行切碎」而合并。

**全库统计（165 文件）**：直接相邻 39,164（合并）｜夹 `NAME` **690**（分行）｜夹 `love+end`/资源/`switch` **546**（分行）｜段末 `CLICK` 49,550。

**落地**：KLAP 行数 50,102 → **50,722**；≥4 引号行 1 → **0**；最长行 186 → 118（辞典条目）。`scripts/klap_extract.py` 已内建该判据。

⚠ **不要反向套用**：同一句被换行切碎时两条记录**确实直接相邻**（39,164 次占多数），所以「按 `0x1F4` 分块再整块合并」会漏掉 1,236 处换人/换段；「每条记录一行」又会把同句切碎。**两个条件都要看**。

⚠ 与 HuneX Ogre 的 `_MSAD` 是**同构不同症**：那边判「上一条引号是否未闭」，这边判「两条记录是否直接相邻」；本质都是「一次文本更新 ≠ 一次点击」。

> 实战与个案见 **`S4-stcm2l-cases.md`**：个案（两套指令体系 / 变体并入 / 名札 8 种 kind / 第二断框点）。
