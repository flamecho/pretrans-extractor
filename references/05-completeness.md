# 「有没有漏」完整性审计（两路查 ＋ 字节闭合）

> 触发：用户质疑「太少了／是不是漏了」，或交付前终检。
> ⚠ **别用「读起来通顺」判断** —— 静默漏 40% 也完全通顺（实例：ネオ アンジェ 21,273/37,102；
> 裏語未解 LZO 时明文片段读得通，实则只有约 1/4）。

## 1. A 路：opcode 日文承载量（`event.enc` **内**）

遍历全部 entry 的全部 `[u32 cmd][u32 len][data]`，对每个 cmd 统计 **[块数, 日文块数, 日文字节]**。

- 除 **{台词, 选项, 无说话人文框}** 外，**若还有 cmd 承载 >2000 B 日文 ⇒ 漏收**（去看它是什么）。
- ⚠ **名札 / 字库 opcode 也「承载日文」**（裏語 `0x2d` 137 KB / `0x31` 7 KB），但按 §0 丢弃
  ⇒ **必须在工具里显式排除**，否则每次都误报。
- ⚠ 统计时要**排除调试 entry**（否则数字与成品对不上）。
- 工具：**`python scripts/opcode_audit.py <解包目录> <作品键> [--cpk <umd.cpk>]`**
  （作品键取自 `urakata_extract.OPCODES`；新作在该表加一行 `txt/opt/name/sys/font` 即可）。

## 2. 字节算术闭合（终检，**最硬证据**）

```
已收(台词+选项+无说话人) + 名札 + 字库 + 其它 = 全库日文字节     差额必须为 0
```
实例（裏語）：`1,863,565 = 1,708,659 + 149,522 + 5,384 + 0`。
差额非 0 ⇒ 逐项查那部分是什么；**说不清 = 有漏**。

另可查**边界域**：把「名义上丢弃」的域（如 `0x2d` 名札）**全部 dump 出来看**——
裏語 15,347 块以 5 字人名为主、≥8 字仅 61 块且全是名札 ⇒ 确认没藏台词。

## 3. B 路：CPK 内 `event.enc` **之外**的文件（条目型文本常另存）

- 扫描器：取**非媒体扩展名** → 解 cp932 → 找 **≥12 连续日文串**（不是单字计数！）。
- ⚠★ **绝不用单字计数**：图像（`town_pic_*.enc`／`texture/*.enc`）的字节巧合会解出大量**假日文**
  （`涛涛血血東血桁`／`跏跏鮻鮻…`），必然假阳性 —— 实测单字法报 **569** 个「含日文文件」，
  换「≥12 连续串」只剩 **51** 个。
- 命中后**判定归属**（不按文件名猜）：对该文件统计「**本作固有词** vs **他作词**」词频。
  - 本作固有 ⇒ 按规范收。**条目型**（用語辞典/図鑑/事典）→ `【見出し語】解説文` 一行一条、
    **不带读音**、条内换行合并、**并入成品末尾**（铁律 5）。
  - 他作遗留 ⇒ **整文件排除**（同铁律 12 的 eboot 遗留串）。
- 实例（裏語）：`termItem.dat`（用語辞典 **108 条**，幕末詞 63／他作詞 0）**必须收**；
  `npc_album.dat`／`book.dat`／`text/TextDataEx.bin`＝**他作遗留**（ドラッケン学園/ダンジョン/呪文；
  本作词 0／他作词 52・32・154）不收；`table.enc`(道具説明)/`TextData.bin`(系统 UI)/`tutorial.dat` 不收。

## 4. 三条**不成立**的判据（别再用）

| 错误判据 | 为何不成立 |
|---|---|
| 「敬体（ます/です）太少 ⇒ 文本不落盘」 | 幕末/武人题材本就用常体；同作纯文本基准也低 → 应用**同作纯文本**做频率基准，别套「一般日语」 |
| 「比续作/FD 少 ⇒ 漏」 | 先**交叉检验**：抽 150 行看是否存在于本作**原始字节**（裏語 vs FD 仅 0.7% 命中 ⇒ 两作内容基本无关，FD 非超集） |
| 「能读到明文 ⇒ 未压缩」 | LZ 的**字面量就是明文**。判据＝条目表 bit31 / 压缩后·解压后大小比（`size2/size≈2.5`）稳定 ⇒ 有解压层（详见 `00-pitfall-index` ㉒） |

## 5. 「重复多」也可能是原文结构，不是提取缺陷

去重后骤减时，先判**粒度**：`裏語` 33,254 行 → 唯一 **12,017**（重复 63.9%），
93.1% 的行落在**≥8 行重复段**内、最长段 **3,016 行**；行数 ≥50 的 81 条 entry 中
**60 对呈 100% 包含**、9 组 entry 文本全同 ⇒ 归档内 `.evt` 之间大量互相复用，**非提取重复**。
判据＝「整段级重复 + entry 间 100% 包含」；**去重会同时抹掉「同一句的多种写法」**，按用途决定是否去。

## 6. ★ 用「引擎自己的目录表」反查漏项（零成本，优先于人工抽样）

**eboot/ELF 里常有一张「章节/回想/场景 选择表」**，把**表示名**与**脚本文件名**成对硬编码——
它就是引擎认定的「全部可玩内容清单」，拿它去 diff 我们收录的脚本集合，**一条 grep 即可证完整性**。

- 实例（2026-10-17 星色のおくりもの，Takuyo gss）：`SYSDIR/BOOT.BIN`（明文 ELF）`0x79a00〜0x7f000` 内
  `<タイトル>` ↔ `<脚本名>.SCR` 成对出现（370 条／185 唯一）。与每脚本 `0xf0` 标题卡**逐条一致**，
  **只缺** `09_PROLOGUE` / `11_BAD_EP`（回想不登记这两项）⇒ 脚本集合完整，同时**顺带校验了标题归属**。
  `Cafe Cuillere` 的 `EXTRA` 菜单表（含标题＋解锁条件）同理。
- 做法：① 在 eboot 内 `grep` 脚本名（`.SCR`/`.PRG`）连成片的那段；② 提取成对的表示名；
  ③ `set(表) - set(已收)` 与 `set(已收) - set(表)` **双向打印**（前者查漏，后者查多收）。
- ⚠ 表可能**重复两遍**（本作 370/185）⇒ 先去重再比；也可能**不含**序章/坏结局这类不登记项 ⇒ 差额要能解释。
- 附带产出：同一张表还能证明**顺序**与**路线归属**，比纯 `0x1e` 调用图更权威。

## 7. ★★ 记录级覆盖闭合：扫**全部日文串**，验证 100% 落在已捕获记录内

> 适用：**自定界字符串记录**（`5C <L> …` 类）的字节码。这是目前最省事、最不容易自欺的一路闭合判据，
> **强于「数 `5C` 有没有对上」**——因为 `0x5C` 兼具 SJIS 尾字节/操作数/媒体数据，计数永远对不齐，
> 且对不齐也判不出是漏还是噪声。

**做法**（约 20 行，零成本）：
1. 按已定记录模型扫一遍，把每条**记录整体**（命令头 + 长度字节 + 正文 + 终止符）的字节区间涂进 `bytearray` 覆盖位图。
2. 逐字节走全流：`lead = 0x81–0x9F | 0xE0–0xFC`、`trail = 0x40–0x7E | 0x80–0xFC`，累计**连续双字节日文**长度。
3. 取 **≥6 字**的串（<6 会被二进制/图像噪声淹没，假阳性暴涨），检查其区间是否**有一段未被覆盖**。
4. 打印「记录体外 ≥6 日文串」的条数与样例。**判据：必须 = 0**；非 0 即逐条看它归属哪个命令。

**实证（2026-10-16 アルカナ・ファミリア2 PSP／HuneX IKA SEQ）**：
- 只用「`26 ?? 24 ?? 5C` + L 校验」扫 ⇒ 体外 **663 条**，全部来自未识别的两类载体
  （`0xA7 n=8` 心の声／`0x50 n=6` バトルコマンド —— **字符串在参数列表末尾 `+18`，不在 `+4`**）。
- 补上这两类 + 改用**命令白名单**（见 `pitfalls/B5-late-2.md` ㊽）后 ⇒ 体外 **0**。
- ⇒ **这条一跑就知道有没有漏，不必先猜「还有哪些命令带串」**；建议**定完记录模型后立刻跑**，作为进入「成行」阶段的门槛。

**两个必须踩准的细节**：
- 覆盖区间要含**整条记录**（含命令头与末尾 `00 00`），否则串首/串尾各差 1–2 字节会误报「体外」。
- 该扫描只证明「**没有孤立的日文文本**」，**不能**证明「被扫到的串都该收」——
  收/不收仍按 §0 判据逐命令定（例：名札命令的串也在记录内，但要丢）。两者互补，不可互相替代。
