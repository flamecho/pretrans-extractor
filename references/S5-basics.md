# 解码层常识：宽度 / 替换槽 / 化け / 名字判别

> 坑总览见 `pitfalls/A-decode.md`。
> 解码层的其余三块分册：`S5-codetable-elf.md`（ELF code→Unicode 码表）· `S5-selffont.md`（自建字体）· `S5-names-macro.md`（名字宏）。

**字符宽度**
见 `S4-structure.md` §1。丢 20% 文本且抽出来仍然通顺，肉眼看不出来。

**替换槽 / gaiji 不能信 cp932**
- 开发者会把未使用的 JIS 槽改画成别的字形：`＄ ￠ ￡ с` 实际是 `？ ！ 。`。
- `0x82 0x40..0x91` 可能不是全角符号，而是**假名**（与假名频次高度一致）。
- **全角符号槽（U+FFE0-U+FFE5）必须列入允许集**，否则 `！` `？` 会凭空消失。
- **PUA（cp932 用户定义区 `F0 40..`）＝大号标点/记号的字形槽**：判别法见 `S2-decrypt.md` 的「化け的两大类」与「孤立化け逐位置定值」两节。
- 判据：**凡出现非日文字符，必须按上下文复核**（疑问句尾→`？`，感叹句尾→`！`）；
  并用 §外部核对确证。
- ★**替换槽成组出现，且几乎都在 JIS 第 1 区（`0x81xx` 符号）与第 7 区（`0x84xx` 希少字/西里尔）**：
  一次见到 `ゝ` 一千多次、`ゞ` 三百多次的时候，那不是文风，是 `？`/`！` 被改画
  （恋愛番長 命短し：`0x8154`=？／`0x8155`=！／`0x8490`=10／`0x8446`=11）。
- ★**定语义看「位置分布 + 前后字符」，不要逐字猜**：① 行末占比（本作 1,033/1,342 在行末 ⇒ 句尾标点）；
  ② 后接字符（154 处 `ゝ`+全角空格 ⇒ `？　`）；③ 叠用（`ゞゞ` ⇒ `！！`）；
  ④ 数字语境（`10月/10分/10ヶ月/10の68乗` ⇒ `10`；同档次下文出现 `来月はクリスマス` ⇒ `11月`）。
  ⑤ **旁证白送**：`sub.uni` 之类的**月名/章节名定长表**里出现同一槽（`5月…9月,ю月`）⇒ 数值直接锁定。
- ⚠ 拿不准时**保留原码位并在报告单列**，别把整套文本按猜的映射改掉。

**变量表要提前锁定**
数据流解析必须先固定「已知人物名映射」，否则条件分支里的 `mov $x,$y` 会把它冲掉
（ときたま 实证：先锁定人名映射才解析字符串变量默认值）。

**eboot（SELF→ELF）串表含「同发行商他作遗留串」**
已见 2 例 → 按角色/场景名核对后**整体排除**，勿混入。
另需剔：名字输入用标点/单字汉字字库、`error :` 内部日志。

**PSV PFS 解密（★两层：`pkg2zip` 只解容器层）**
zRIF/`-k`/pkg2zip 授权细节见 `S2-psv-pfs.md` §1；**判据 `header signature is valid`**。
- **★ `pkg2zip -x <pkg> <zRIF>` 只解 PKG 容器层**：`app/` 里 `icon0.png` 不是 PNG（`89 50 4E 47`）、`*.mp4` 无 `ftyp`
  ⇒ **文件内容仍加密**，**必须再跑 PFS 层**：`psvpfsparser -i app/<ID> -o dec -z <zRIF> -f cma.henkaku.xyz`，
  `dec/` 才是明文（先把 `work.bin` →`util/zzrif.py`→ zRIF；路径含日文时先复制成 ASCII 名）。
- **★ `-i` 要的是「完整 PFS 树」，不是散文件**：输入目录须与 `sce_pfs/files.db` 一致 —— 游戏文件要各自落在
  子目录里（PsychicEmotion6：`*.cpk` 必须在 `PCSG00815/data/` 下），且**目录一个都不能缺**
  （缺 `thumbnail/` 之类会直接 `Directory … does not exist` 中止）。手工拼输入树时先凑齐目录。
- **★ 必须前台运行**：后台任务拿不到沙箱网络豁免，`-f cma.henkaku.xyz` 的许可校验会**假报** `expected value`；
  前台放行网络后同一命令即通过（判据链：`header signature is valid` → `root icv is valid` → `keystone: matched retail hmac`）。
- 引擎分析需要 eboot 时：`util/self2elf.py -i dec/<ID>/eboot.bin -o eboot.elf -k work.bin`（需 pycryptodome）。
  eboot 串表常含**他作遗留串**（本作残留 CLANNAD 的「岡崎朋也」）。

**扩展名/文件名不可信**
`.dat` 可能是图片集；一律看**魔数**判内容。

**「孤立化け」别去总当り——用逐位置定值复元表**
区间 XOR 系的孤立化けは、ほぼ常に **「2 バイト字の首バイト 1 個が別値に置換」**。
ASCII に化ければ文字種走査で見つかるが、**別の合法前導バイトに化けると誤った漢字**になり検出困難。
- 確定は「**尾バイトは既に正**（が多い）＋前後文＋**同作内の平行語**」から一意に。
- 記録は `{バイト位置: 正値}` の表に固定（再現可能・秒級）。
- **★ 禁止総当り**：全 cp932 码表 7000 字 × 2 段 × 多輪 を数分回すのは無効な作業量
  （実測 >5 分で無成果）。**枚举前必須先 ask 用户**。
- **★ 制御行（`@endif` 等）の化けは必ず直す**：直さないと branch 整合が崩れ出力行数が大きく狂う
  （実測 408→560 行）。表示文だけ見ていると気づけない。

**XP3 の無圧縮変体**
zlib 無しの XP3 がある（蝶の毒 ～幻想夜話～）。この場合、索引 `segm` の `original` 字段は**当てにならない**。
**`stored`（第 3 字段）が磁盘長**。判定＝「off+stored == 次の off」の連続性。

**自建码表（u16 码流）的反推纪律 —— 禁穷举、禁 OCR（最高优先级）**
场景：非 ASCII 码 `≥0x8000`，字符落在脚本自带的**字符表**（如 `charset.csb`）里。BELIEVER! 实证。
- **只差一个「基址常量」时，用一条已知明文锚定，不要搜索**：码值单调随表 index ⇒ `base = code − index`，
  一条即可定值。BELIEVER!：系统消息 `…が見つかりませんでした` 的 `見` → `charset.csb[1064]` ⇒ 常量 **−6**。
- **禁止**：扫 `k ∈ [−1200,1200]` 打分、遍历 `+0x100/+0x200/lead±2/trail+0x40`、EUC/SJIS 各变体。
  **禁止**：渲染字形图集 + OCR/模板匹配来「认字」（变宽/打包字体必崩，还会撞成「图像问题」）。
- **先查参考实现，但务必先确认「同一作/同一变体」**：现成工具的可靠价值在**指令语义/框架**
  （opcode 名、名札/选项分派、TEXT 是内联还是索引），**未必含码表**。BELIEVER! 的参考 disassembler
  （`w_hese_dasm.py`）把文本**索引到外部 `script_dialog_ja.hdlg.txt`**，且用 `0xA0<op>` 框架 ——
  而本作 `A0 1b` 出现 **0** 次、`1b 00 00 80` 出现 **14,840** 次、无该外部文本 ⇒ **不是同一变体**，
  对解码零帮助。所以：**能抄则抄，抄不到就回到「明文锚定」，别在参考实现上反复找。**
- **警惕「看似通顺的错文」**：`+0x200→CP932` 能读出 `しています`，但同串的**汉字会全失败** ——
  先用**含汉字**的串做判据，不要被平假名段的假象带走（这就是当时绕弯的直接原因）。

**同引擎跨作 opcode 语义会变 —— 换作必须回查，勿硬套**
Takuyo gss 实证：`0x10c` 在 ひめひび 记为「动态调用」，在 Cafe Cuillere 实为 **`sprintf` 进槽位＝语音＋字幕**：
字符串形如 `"%.1d %.1d FILE.WAV 正文"`，**`.WAV ` 之后即上屏正文**；替换源是**字符串之后**的操作数。
- ⚠ 别把**字符串自身**也当替换源：曾因 `subst(s, ops[1:])`（含字符串）产出 `正文  FILE.WAV 正文` 的自复制行。
- 教训：同引擎不同作品，**同一 opcode 编号可能被复用给新语义**。语义表不可跨作硬套；先验证「操作数形态 ＋ 明文样本」。

**eboot→ELF（SELF→ELF）是「元数据金矿」—— 先读它，再推范围/顺序**
eboot.bin 解密成 ELF 后，直接搜 **UTF-8** 串即得三类金信息：
① 主人公**默认名表**（Cafe Cuillere：`藤白\0\0真緒\0\0まお\0\0`）② **脚本总表**（全部脚本名，**顺序＝开发者定义序**）
③ おまけ/EXTRA **菜单表 ＝ {脚本名, 显示标题, 解锁条件}**（同表常附带角色名/章节标题）。
- 价值：**比在脚本里推调用图更快确定「哪些脚本属发行内容」和「播放顺序」**。Cafe Cuillere 的
  `_008`(スイートエンド) / `009_*`(おまけ) / `010_*`(スイートハーレム) 仅被 `DEBUG` 引用，
  靠 EXTRA 菜单表（含解锁条件）才判定为发行内容 ⇒ 收录；若无此表极易误判为「未采用分支」而剔掉。
- 手法：对 ELF 搜 `"真緒".encode("utf-8")`，或 `re.finditer(rb'[\x20-\x7e\xe0-\xef\x80-\xbf]{3,}', seg)` 导出片段。
  ⚠ **ELF 内日文是 UTF-8（不是 cp932）**，用 cp932 扫会得到一堆乱码尾串（对比 `probe.py jp` 的假命中）。
