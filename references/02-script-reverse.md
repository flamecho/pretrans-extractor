# 脚本结构逆向（细节）

对应 SKILL.md §2 的 S4〜S6。

## 1. 主循环必须「字符宽度感知」（最容易静默丢文本）

混合编码下：汉字 2 字节（首字节 `0x81-0x9F` / `0xE0-0xFC`），假名/控制 1 字节。
主循环写 `i += 1` ⇒ **汉字尾字节撞上指令码** ⇒ 消息从汉字中间被切开。

```python
def is_lead(x):
    return (0x81 <= x <= 0x9F) or (0xE0 <= x <= 0xFC)
# 主循环里：if is_lead(x): i += 2; continue
```

> **真实事故**：某 PSV 作尾字节 `0x76`/`0x7C` 恰好等于「文本段起」「消息 id」指令 →
> **20,285 / 80,168 条消息为空，丢约 21% 文本**，而抽出来的句子**仍然通顺**，肉眼看不出来。

**自检**：统计文本字节总数 / 空消息数。空消息 > 10% 几乎一定是这个 bug。

## 2. 常见消息结构

`7c <u16 msgid>` + 可选 `76 <p1> <p2>` 头 + 正文 + `07 <x>` 分隔。

- `7c <u16>` 后约 88% 跟 `76 p1 p2`，12% 直接接正文 ⇒ 头部当**可选**处理。
- `07 00 / 07 01 / 07 02` = 段结束；其余 `07 XX`（含 `07 0a`、罕见 `07 5b`）= 软分隔，继续读。
- **转义序列（如 `7e XX`）必须整体跳 2 字节**：否则 `XX ∈ {0x76,0x77,0x7c,0x00,0x0b}` 会被当分隔符吃掉，
  表现为「消息以 `7e` 结尾」（实测 33 处）。
- 正文段用 SJIS 感知游标扫描，遇 `0x07` 才判分隔。

**不定长 op 的通用解法**：用「**文本记录驱动扫描**」——记录自带长度自定界 ⇒ 永不失步。

## 3. 字符层顺序与字符合成

**顺序**：① **先定假名块**（单字节码通常是自定的假名序，可能剔除小假名）——
用「**人工读图 + 同句变体**」交叉验证，**不要只靠语言模型**；② **再定汉字**（多数直接是 cp932）；
③ 再处理替换槽（见 `SKILL.md` §3 索引与 `03a-decode-basics.md` A2）。

- **1 字节汉字宏**：用「**同句拼写变体**」法确证 —— 同一场景里往往有一处把宏写全了。
  取前后缀（各 ≥4 字）在全文里搜「中间填成完整词」的行即可铁证。
  ```python
  pat = re.compile('^' + re.escape(pre) + '(.{1,6})' + re.escape(suf) + '$')
  ```
  例：`0x6F` 旁出现 `8e 76 0f 8f 6f`（思 い 出）→ 铁证 `0x6F` =「思い出」。
- **「后字选词」宏**：`XX`+下一字 → 输出「与下一字组成词的首字」（下一字保留）。
  例：`7B`+`ク`→ボ、`7B`+`当`→本、`6C`+`た`→私、`69`+`泉`→永。实现成 `LOOK_NEXT = {code:{next:out}}`。
- **变量**：`7e XX` = 名字/地名/术语表引用；`0x67 <form>` = 主角名（姓/名/全名分 form）；
  `0x7A`/`0x74 <form>` = 同行者名。术语表常在另一个 entry（如「用語辞典」文本）。
- **内联插入有两种形态，别默认是「文本内联」**：
  ① **文本内联** —— 插入块里直接就是字面（コルダ/下天の華 路线）；
  ② **定长表引用** —— 插入块只带 `id`，真值在别处的**定长记录表**里（遥か5 实证：脚本用语表 52B、
  用語辞典表 64B）。**遇到「插入块解出来是空 / 断句」先怀疑是②**，而不是「变量表没找到」。
- **定长表的基址定位靠「空槽字面」**：空槽（`仮`／`用語予約NNN`）会**把 slot 索引与逻辑 ID 的错位暴露出来**。
  用「某条空槽的字面编号 N（如 `用語予約３６８`）」反推 `base = 该槽地址 − N × 记录长`，
  才能整体对齐；直接假定 `base=0` 会**整体错位一格**、查表查到邻居值。
- **说话人标签**要单独识别并丢弃：如 `5b XX 00 47 YY 00`、`name "△△△△"`。

## 4. 分支变量的块回填

「フリートーク / 物忌み」这类循环会把**同一段台词按固定顺位复制 N 份**（如八葉 8 份）。
判据由强到弱：

1. **同一句占位台词在一个事件内恰好出现 N 次 → 第 k 次即第 k 位角色**（最强）
2. 锚点区间：找 `xN` / `x40`(=5×8) 的重复行当块边界；**最大间隔通常恰好落在 N 的倍数处**
3. 就近推定（兜底，距离 ≤60 行）

**不要**无条件「就近点名」—— 会把**上一块的名字填给下一块**（整体错位一格）。

## 6. STCM2L（Idea Factory）—— 三个平台三种形态，别照搬

同一作系（猛獣/PANDORA/Norn9）**每个平台都要重新求证**：

| | PS2（PANDORA） | Switch（猛獣） | **PSV（Norn9 Act Tune）** |
|---|---|---|---|
| 编码 | CP932 | UTF-8 | **UTF-8** |
| 指令 | `[u32 size][payload(size-4)]` | 同左 | **`[is_call][opcode][nparams][length]` + nparams×`[p0,p1,p2]` + data** |
| 文本 | payload 内 `[addr][c1][c2][0][L/4][1][L][text]` | 同左 | **p0 局部指针 → 数据区 `[0][L/4][1][L][text]`** |
| 换行 | 12B `[0][cmd][flag]` | msg desc `0x14058` / node id | **builtin `0x1f4`（等待点击）** |

### ★★ PSV 版：每文件 opcode 有常量平移 Δ（最大的坑）

- **导入函数 ID 整块平移**（Δ = 0x10 的整数倍；实测 Δ ∈ {0,±0x10,0x30,0x40,0xe0,0x120,0x150}）。
- **builtin 不随 Δ 动**：`0x1f4`(wait) / `0x6`(goto) / `0x3`(Mif) / `0x0` / `0x11` / `0x12`。
- **Δ 检测**：把「含日文串的 opcode」按**平均字符串长度**排序取最大者为 `text_op`，
  `Δ = text_op − 0xcf9c`。**别用出现次数**——正文极少的文件（如 Norn9 的 5001–5010）flag 串反而更多，会选错。
- 归一化（Δ=0 基准）：`0xcf9c`=文本 push / `0xd698`=人名 push / `0xe090`=选项（p0=文本,p1=目标标签）/
  `0x236c`=章题标识 / `0x5414`·`0x4b24`·`0x4cfc`·`0x4ed4`…=flag。

### ★ 互斥分支 = 同一次点击的多版本（结构识别，不靠相似度）

编译器把 `if/else` 两版正文**相邻排放**，以 `goto`(0x6) 分隔；且 **「then 版」的 `0x1f4` 后面紧跟 `goto`**（跳过 else 版）：

```
[cond] Mif → ELSE
  [文本 A] … 0x1f4 ; goto → END      ← A 结束、跳过 B
ELSE:
  [文本 B] … 0x1f4                    ← B 结束
END:
```

⇒ 合并规则：**`goto` 断「段」不断「点击」；`0x1f4` 若下一条是 `goto` 也只断段**；否则断「点击」。
同一点击内多段取一：**优先不含 `#Name[` 占位符者，其次取最长**（＝直写名版）。
若只按 `0x1f4` 断行、不识别 `goto`，同一句会输出 2–3 份（`#Name[n]` 版 / 直写名版），即「差一两个字的重复行」。

### 每文件开头的「共通导入块」

Norn9 的 88 个 SCRIPT 文件**各自开头重复同一段 5 行导入**（`プロローグに新たな選択肢が追加されました`
＋4 行世界观），逐文件计会重复 88 次 ⇒ **只保留一次置全文最前**（判据：被 ≥8 个文件作为开头重复的块）。
