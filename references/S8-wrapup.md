# 收尾（S8）—— 一条命令 + 拆分纪律

> 每作交付后照此执行，不等用户提醒。

```bash
python scripts/wrapup.py --report "解析报告/XX_解析报告.md" \
                         --text "提取结果/<压缩包名>.txt" --name <主角名>
```

它串起四步，**只输出一张待办清单**（机器能判的都判完，人只做判断）：

| 步 | 工具 | 机器判据 |
|---|---|---|
| ① 成品品检 | `check_text.py` | 退出码 0（`[E]` 必修，`[W]` 人工确认） |
| ①b 行数一致性 | （`wrapup` 内置） | 报告声明的 `行数` vs 成品实际行数；差 >1% ⇒ `[W]`（用错文件/成品过期） |
| ①c 切行判据 | （`wrapup` 内置） | 报告须有「断框判据/框界/换框」＋一条证据（L0/L1/覆盖率/串起点/反例）；缺 ⇒ 待办「补三行」（`S6-lines-proof.md` §7）；标了 L2/未证 ⇒ 提示补代码级证据 |
| ①d **可复现性** | （人工，两分钟） | **重跑提取器 → 与成品逐行 `difflib` 对比**，须 0 差异（差异只允许是已写进报告的「手工修订」，逐条可数）。⚠ 2026-10-27 两个隐蔽 bug（`<wait key>` 漏判 642 次点击、括号被「配平」后处理改 38 行）**只有这一步能发现**——品检、行数、引号配对全 PASS |
| ② 手册对账 | `lint_docs.py` | 断链 / 孤儿 / 空册 / 排版全 0。**体积不判**（2026-10-26 取消硬线） |
| ③ 沉淀草案 | `distill.py` | 候选按 **已覆盖 / 待沉淀 / 单作特例** 三分，并给建议落位册 |
| ④ 落位片段 | `archive_work.py` | 生成 WORKS 块 / TOOLS 节 / 日报小节 / 引擎提示；`--apply` 幂等追加。**报告带 front-matter ⇒ 字段零歧义**；否则标「正则抽取，请核对」 |

人工只做三件：**看草案勾选 → `--apply` 落位 → 报告写「重跑步骤」**。
★ 另外固定加一件：**①d 重跑 diff**（见上表）。成品若被任何「后处理」动过（配平、去重、补前缀、删注记），
**必须把该后处理写成脚本并写进报告**，否则下次重跑就复原不了，也查不出当时改了什么
（2026-10-27 もし神様：两条未登记的临时后处理同时改了标点与行边界，靠回源 diff 才浮出）。
★ **双版对照作**（`S6-lines-dual.md`）：**只交一版 `<压缩包名>.txt`（不加后缀）**，`--text` 就传它；
报告里写闭合式（对照版 = 段行总数 + 多段页数），另两版（段行版/页版）不落交付目录。
落位分工：**通用判据**进 `references/`（按阶段册）或 `pitfalls/`；**单作特例**只进 `WORKS` 作品块 / `engines/<slug>.md`。
`references/00-index.md` 不动（它只放铁律与导航，见 `00-workspace.md`）。

## 拆分/重组的三条硬规矩（**不可绕**）

1. **禁按字节切**：`>10 KB` 只在**语义边界**（标题 / 编号条目）下刀 —— 见 `split_md.py`。
   先 `python scripts/split_md.py <md> --dry-run` 看切点，再 `--names a.md,b.md` **语义命名**落盘。
   **体积不是拆的理由**（2026-10-26 取消 10/12 KB 硬线）：判据是「读者是否需要同时看这两段」。
2. **禁「先写新文件，再按 glob 删旧」**：新名会被 glob 算进"旧册" ⇒ 新旧一起删光（真实事故）。
   `split_md.py` 已内置：临时目录写入 → 校验（正文行守恒 / 边界守恒）→ **打印待删清单** →
   断言与输出名**不相交** → 才删旧、搬入。手工重组也照此顺序。
3. **拆完立刻改引用**：`grep -rn "<旧名>" .`（`references/` 与 `SKILL.md` 同步改），再跑 `00-index.md` 链接自检。
   ⚠ `--names` **必须带 `.md`**：漏写会写出无扩展名的文件、旧册仍照删（2026-10-19 `WORKS-misc-psp-2` 実例，
   事后只能手工 `mv` 补名）。`split_md.py` 现已自动补原扩展名，但落盘后仍要 `ls` 一眼确认。

## 落位与拆分约定

- **不设体积硬线**（2026-10-26 用户明令取消）。唯一保留 `references/00-index.md` **8 KB**——
  那是自动注入的截断阈值，属技术限制，超了信息真的会丢。
- **该拆的信号**（任一即拆）：一册里混了两个阶段；一册里混「判据」与「个案」；同一主题要连开三册才看得全。
  **不该拆**的理由只有一条：文件大。
- **拆要拆得能读**：文件名必须说清内容（`B-script-structure` 而非 `script-4-1`），否则读者还得挨个打开。
- 新结论按 §4 落位，**别往 `SKILL.md` 堆**。

## 未命中后的回填（判型表靠它长出来）

`§E` 四步走通、拿到可读文本后，**当场**补三处，缺一不可：

1. **本册**：在 `§B` 表加一行「魔数/头特征 → 引擎 → 该读哪册」；`§D` 有厂商线索就一并加。
2. **引擎册**：新建 `engines/<slug>.md`，首段＝`识别特征 → 容器链路 → 脚本记录 → 成行 → 易错`。
3. **路由**：`engines.md` 加一行（一句话索引 ＋ 详见），并在 `WORKS` 同族块里补本作条目。

> 判据：**回填后，同一引擎的第二作应该能在 10 分钟内定位到该读的册**。
> 做不到 ⇒ 说明这行写得不够「可判」——补上**特征串/偏移/结构**，别只写引擎名。

## 维护命令（改动手册后 / 收工前）

```bash
python scripts/lint_docs.py     # 断链 / 引擎册未进路由表 / 孤儿册 / 空册 / 超限
python scripts/pending.py       # 有成品无报告 / 有报告未进索引 / 未落位且无报告头
python scripts/memcheck.py        # 只报 00-index.md 超 8 KB；其余册仅列大小（不作达标线）
```

- `lint_docs.py` 的 **B 项（引擎册未进路由表）** 是「写了却没人知道去哪找」——新增引擎册后必跑一次。
- **F 项（册内编号不连续）**：合并两册之后必跑——两册各自从 1 编号，接起来就会出现 `## 1.` 重复或跳号。
- **J 项（命令示例不可跑）**：改完脚本参数、或改 README 的命令段之后必跑。读者第一件事就是复制命令，
  脚本不存在 / 参数已取消都会在这里露出来。
- **H 项（§N 引用失效）**：拆册 / 重排小节号 / 合并册之后必跑。裸 `§N` 一律写成 `文件名 §N`
  （跨册尤其如此）——`SKILL.md §0` 这种写法读者才知道去哪找；本册内引用则确认节号还在。
- `pending.py` 的判据是「报告名是否出现在任何 `WORKS-*.md` 里」；备忘录类（`*_メモ.md`）默认跳过。

### 改了品检判据：先跑回归

`check_text.py` 的每条判据都来自**被退回来过的真实问题**，但改它本身没有任何东西拦得住回退。
`scripts/selftest.py` 把这些返工点固化成 28 个微型样本，断言「该报的报了、不该报的没报」：

```bash
python scripts/selftest.py            # 退出码 0 = 28/28
python scripts/selftest.py -v         # 附带每个样本实际命中的 [E]/[W]
python scripts/selftest.py 半角假名    # 只跑名字含该子串的用例
```

**正确顺序：先在 `CASES` 加一条样本，再改判据。** 反了就只验证了「新样本能过」，
不知道有没有把老判据弄坏。想确认回归本身没失效：把某条判据临时改成恒 `0`，回归必须变红。

★**用例必须造完整目录布局**（2026-10-27 踩到）：字符台账的路径是
`<成品>/../解析报告/allow/<名>.charset`。旧用例只在临时目录写一个散装 txt ⇒ **每条用例都暗含一条
`[E] 台账缺失`**，而断言只做子串匹配 ⇒ 台账判据彻底坏掉也照样全绿。
`case()` 现在默认在临时目录造布局、并按样本自动生成台账（`no_charset=True` 才不造）。

★**加完用例要做变异验证**：把对应判据改坏（`pass  # MUTATION`），确认**只挂那一条**。
28/28 全绿本身说明不了任何事——不做变异验证，等于不知道网有没有洞。
