## B. 提取层（行粒度）

**B1. 续写形态必须做全集**（否则碎片行 / 长行粘连，两个方向都被退过）
コルダ 实证的 **5 种**：
1. `INS` 追加码（同框续写）
2. **名字插入块横跨一条文本记录**（记录本身就是插入块的字面量，其后间隔只剩收尾操作数；
   需跟踪「插入块是否仍开启」）
3. **间隔恰好只有 `CLOSE`**（无 msgid / 无边界码）→ 纯续写
4. **只有标点/空的记录 = 框内文本更新帧**（不另起一框）
5. **纯停顿帧**（整框都是标点/空）→ **丢弃**

★ 安全写法：**「默认新框，只在看到追加码 / INS 才合并」**。
反过来「要求必须有 INS 才算续写」会**漏合折行**（我犯过的错）；「默认合并」则会粘连标题/菜单。

**B2. 纯标点记录不要无脑断链**
否则会把 `「香穂子…` 拆成 `「`。但**整框都是标点/空** ⇒ 停顿帧，丢弃。
与 `4` 的区分：**仅当当前框尚未收句**（不以 `。！？」』）` 结尾）时才并入；已收句者单独成框并作停顿帧丢弃。

**B3. 标签/调试串要断链**（`is_label()`），否则菜单/标题会粘到正文上。

**B4. 互斥随机台词会并成一行**
无收尾标记就 `goto … textclear` 的随机台词串会被线性扫描并成一行（最长 589 字）。
→ **进入新 `*label` 且当前页未结页时 → 结页**（分支/随机台词互斥，标签即显示上下文边界）。
主剧情几乎不受影响（+54 行）。

**B5. 大字号演出把话者名写进正文流**
`setwindow3 …,0,0,…`（字号 0 = 不可见/全屏）后把 `【　椿　】` 之类的说话人名当普通文本行写进正文，
紧跟台词行且中间无点击标记 → 被并成一行 → 看起来像「说话人前缀残留」。
→ 裸名札文本行（`^【[^】]*】$`）视为说话人标签**剔除**。常规对白（99.9%）走 `name` 命令，人名不进正文流。

**B6. 页 / 点击粒度不要跟随引擎的宽窗模式**
脚本的 `*text_all*`=28×16 / `*text_all_angeltxt`=38×20 只是**显示模式**，
物理宽窗会把整段对话并成一行。**除非用户对本作另有明示**，一律「一次点击 = 一行」。

**B7. 互斥分支 = 同一次点击的「多版本正文」—— 按结构识别，别靠相似度**
同一句对白会按条件（女主是否改名 / 是否在场 / 礼貌级）编译成**相邻的 2–3 份**，仅一份会显示：
```
[cond] Mif → ELSE
  [版本 A（then）] … 0x1f4 ; goto → END     ← A 结束后 goto 跳过 B
ELSE:
  [版本 B（else）] … 0x1f4
END:
```
- **结构判据**：`goto` 断「段」不断「点击」；`0x1f4`（换框）**若下一条是 `goto`** 也只断段，否则断「点击」。
- 同一点击内的多段**取一**：**优先不含 `#Name[n]` 占位符者，其次取最长**（＝直写名版）。
  Norn9 实证：`「#Name[1]ー、七海ー、」/「こはるー、#Name[3]ー、」/「こはるー、七海ー、」` → 取第三版。
- ⚠ **只按换框断行、不识别 `goto`** ⇒ 同一句输出 2–3 份，即「**差一两个字的重复行**」（用户明确反感）。
- ⚠ **按文本相似度自动合并不可靠**：会把 `「（楽）」/「（質問）」`、`「…………」/「あ……」` 这类**真的相邻不同行**
  误判成变体。**以结构（`goto` / `0x1f4`+`goto`）为准**，相似度只作复核。

**B8. 每个文件开头的「共通导入块」会逐文件重复 —— 去重后只留一次**
连锁章节脚本（Norn9 的 88 个 `SCRIPT/*.DAT`）**各自开头重复同一段导入**（`プロローグに新たな…`＋4 行世界观），
逐文件计会重复 88 次；个别文件（5001–5010）**全文就只剩这段共通块**。
- 判据：取「被 ≥8 个文件作为开头重复的最长行块」，**只保留一次置于全文最前**，其余文件头部删去该块。
- 别把它当正文重复上报，也别整块丢弃（它是玩家可见的导入旁白）。
