## v1.3.0 —— 知识库按流程阶段重构 ＋ 收尾工具链

本次改动集中在两件事：**手册（references）的分册逻辑**，以及**提取完成之后的整理流程**。

### 一、手册按流程阶段重排

原来的分册是按 10 KB 体积硬切的，同一主题被拆散在多个文件里，定位一册要先读一串联导航。现在按**你实际在做哪一步**来分：

```
00-triage（判型）→ 01 取得/容器 → 02 脚本层 → 03 解码 → 04 成行 → 05 交付 → 06 流程
```

- **`00-triage.md`（新增）**：拿到没做过的游戏，从平台、容器魔数、脚本后缀、厂商四条线判型；
  全不匹配时给四步攻坚顺序。命中已知引擎就直接读对应的 `references/engines/<slug>.md`。
- **`02-record-patterns.md`（新增）**：文本记录的 8 种形态（P1–P8），认得出形状就不会在 opcode 上失步。
- **`02-false-signals.md`（新增）**：24 条「看着像判据、其实会骗你」的反例
  （汉字尾字节撞指令码、「读得通」≠字对、图集顺序≠码序 …）。
- **坑索引**归入 `pitfalls/` 15 册，按层（解码 / 提取 / 交付 / 专册），条目编号原样保留，旧引用不失效。

### 二、收尾不再是手工活

新增 4 个工具，把「提取完之后的一堆整理」变成一条命令和一张待办清单：

| 工具 | 作用 |
|---|---|
| `wrapup.py` | **一条命令跑完收尾**：品检 → 行数一致性 → 体积 → 沉淀草案 → 落位片段 |
| `distill.py` | 把报告里的判据按「已覆盖 / 待沉淀 / 单作特例」分类，并给建议落位册 |
| `archive_work.py` | 从报告生成作品索引 / 工具索引 / 日志小节 / 引擎提示，`--apply` 幂等追加 |
| `split_md.py` | 按语义边界拆 md，带正文行守恒校验与原子替换 |
| `lint_docs.py` | **手册对账**：断链 / 引擎册未进路由表 / 孤儿册 / 空册 |
| `pending.py` | **未落位检测**：有成品没报告、有报告没进索引 |

```bash
python scripts/wrapup.py --report "提取结果/解析报告/XX_解析报告.md" \
                         --text  "提取结果/XX_全文本.txt" --name 主角名
```

### 三、报告头可以写了

报告开头加一个机器可读块，索引字段就不用再靠正则猜：

```yaml
---
作品: 某某作品
平台: PSP
引擎: STCM2L
主角: 姓 名
行数: 31838
日期: 2026-10-18
---
```

`行数` 会与成品实际行数比对，差 >1% 会报警（防用错文件 / 成品过期）。

### 四、手册不会越用越钝

改过手册或收工前跑两条：

```bash
python scripts/lint_docs.py      # 断链 / 引擎册没进路由表 / 孤儿册 / 空册 / 超限
python scripts/pending.py        # 有成品没报告 / 有报告没进索引
```

`lint_docs.py` 第一次跑就抓到两处真问题：一处指向已改名的分册（`05b-discipline` → `06-discipline`），
以及 6 册引擎册写完却没人知道去哪找。这类「指针腐化」靠人工看是查不出来的。

### 五、拆分与重组的硬规则

- 只在**语义边界**下刀（标题 / 编号条目），不按字节切；
- 不「先写新文件、再按通配符删旧」（新旧会被一起删掉）；
- 拆完立刻改引用，再跑一次链接自检。
