## v1.3.1 —— 「命中已知引擎」这条路，最后一米接通

上一版把 240 多个**按具体作品写的提取器**随包附带了，但没解决一个问题：
判型命中某个引擎之后，**该改哪一个脚本**？

`scripts/INDEX.md` 只列了 11 个通用工具（判型 / 探查 / 品检 / 收尾），按作品提取器不在里面；
而 `00-triage.md` 的快速路径写的却是「按引擎查 `scripts/INDEX.md`」——查不到。
结果就是：引擎册给了容器链路和记录形状，脚本得靠 `ls | grep` 猜文件名。

本版把这个缺口补上。

### 新增 `scripts/INDEX-BY-ENGINE.md`

构建时自动生成，不手改。三张表：

| 小节 | 内容 | 用来回答 |
|---|---|---|
| 一、按引擎 | 75 个引擎册 → 各自可直接改的 174 个脚本 | 「命中这个引擎，改哪个 py？」 |
| 二、按脚本 | 脚本 → 一句话用途 → 出自哪本引擎册 | 「这个 `xxx_extract.py` 是干什么的？」 |
| 三、未被引用 | 65 个（薄壳 / 一次性脚本 / 漏记），附用途 | 「这个没归类的脚本能不能用？」 |

用法：`references/00-triage.md` 命中引擎 → 打开 `references/engines/<slug>.md` 看容器链路与记录形状
→ 回到本表挑**最近似**的脚本 → **只改路径 / 键 / 参数**。

### 新增 `scripts/selftest.py`

`check_text.py` 的每条判据都来自一次真实的返工（半角假名、引号不配对、句号被当空格清洗、
名札残留、插入宏漏出…），但改动它本身没有任何东西拦得住回退。

现在把这些返工点固化成 **21 个微型样本**，断言「该报的报了、不该报的没报」：

```bash
python scripts/selftest.py            # 退出码 0 = 21/21
python scripts/selftest.py -v         # 附带每个样本实际命中的 [E]/[W]
python scripts/selftest.py 半角假名    # 只跑名字含该子串的用例
```

覆盖：BOM / CR / 半角假名 / 半角标点（只 W 不 E）/ PUA / `U+FFFD` / `〓` / 控制符 /
引号配对 / 行首孤立标点 / 颜文字单侧括号不误报 / 名札三形态 / 邮件字段标签放行 /
含句读的 `【】` 特效放行 / 句号缺失 / 插入宏 / 主角名出现性。

**改了判断逻辑就前后各跑一次。**

### 修正

- **`00-triage.md` / `00-index.md`**：「按引擎查脚本」改指 `INDEX-BY-ENGINE.md`。
- **`scripts/INDEX.md`**：抬头原写「专用提取器不随 skill 发布」——与包内实际内容相反，已更正。
- **`lint_docs.py`**：`engines/` 与 `engines-N.md` 是构建期注入的（只有发行版才有这个目录），
  在工作副本里检查它们会稳定报 30+ 条假断链，把真正的断链淹掉。现在按「预期缺失」跳过，
  输出里单列「注入跳过」计数；发行版仍严格校验。
- **`05-wrapup.md`**：维护一节补上「先加样本、再改判据」的顺序（反了就只验证了新样本能过，
  不知道有没有把老判据弄坏）。

### 升级方式

替换整个目录即可，无配置文件、无外部依赖（纯 Python 标准库）。
`INDEX-BY-ENGINE.md` 会随包附带；若你增删了脚本，按文档重跑一次生成即可。
