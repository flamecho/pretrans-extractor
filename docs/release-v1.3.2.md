## v1.3.2 —— 文档质量清理（无功能变化）

上一版的路径脱敏是对的，但还有两类残留：一类让读者**找不到东西**，一类让页面**渲染错位**。

如果你的引擎册里写着「主索引见 `../MEMORY.md`」却点不开，或者某段文字突然变成等宽字体并吞掉后面几行，就是这个原因。

### 修掉的三类问题

| 问题 | 量 | 原因 |
|---|---|---|
| 引擎册抬头指向 `../MEMORY.md` | 26 本 | 该文件是维护者本地记忆层，不随包发布 ⇒ 改指 `../00-index.md` |
| `06-workspace.md` §5 整节讲记忆层 | 1 节 | 同上；该段不进发行版，收尾命令与环境坑保留 |
| 正文反引号不成对 | 8 处（脱敏造成）+ 20 处（源文件本来就有） | 见下 |

反引号那两类分别来自：

- **脱敏造成**：处理 `C:/Users/…` 与 `.workbuddy/memory/` 的正则，字符集没排除反引号，
  把紧跟在路径后的反引号一并吃掉 ⇒ 行内代码只剩开头、没有收尾。
  未闭合的 code span 会把**后文整段**吞进代码块——这是渲染错位的主因。
- **源文件本来就有**：跨行的 inline code（Markdown 不支持）、表格里多余的孤立反引号、
  `0x5C`（反斜杠）转义后残留的反引号。

### 构建期新增两道校验

防止同类问题再回来：

1. **正文行反引号奇偶** —— 任意 `.md` 的正文行若反引号数为奇数，构建直接失败；
2. **`MEMORY.md` 残留扫描** —— 发行版里出现该文件名即失败。

另加 `--no-clean`：目标目录被文件预览/资源管理器占用时，`rmtree` 和 `rename` 都会被系统拒绝，可用它跳过清空、就地覆盖。

### 升级方式

替换整个目录即可。本次**不改任何脚本行为**，已在使用中的提取流程不受影响。
